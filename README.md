## 목표

공유로 유입을 만들고 취향 이해와 추천 품질로 다시 사용할 이유를 만든다. 앱스토어 출시와 공유 발생, **출시 후 6개월 안에 제휴사 대시보드의 확정 예약 1건**을 성공 기준으로 둔다. 정산 입금과 클릭을 확정 예약으로 대신하지 않는다.
수익모델은 제휴와 LLM 기능 구독이다. 생계형 매출 규모의 입증보다 출시·유입·제휴 경로를 한 번 완주하는 것이 목표다.
구독은 2026-10-07에 도입을 결정했다. 검색을 쓰는 LLM 호출의 비용을 측정한 결과([실행 5 부분 결과](data/exploration/runs5/result-partial.md))가 계기다. 그 전까지는 제휴 단독이었고 구독을 제외 범위에 두었다. 가격과 사용량 한도는 2026-10-17에 정했으며 [추천 구조](docs/recommendation/README.md#2026-10-07-추가-결정-구독-자료-배포-저장)에 있다. 이전에는 미정이었다.
2026-10-08 변경: LLM을 구독자에게만 제공하고 무료 사용자에게는 쓰지 않는다는 2026-10-07 결정을 철회했다. 무료 사용자도 한도 안에서 쓴다.

기능을 판단할 때는 적은 입력으로 취향을 더 정확히 이해하는지, 추천 품질을 검증하는지, 출시·공유·다음 여행 재사용에 필요한지 본다. 기능 수·복잡한 산식·도시 수 자체를 경쟁 우위로 간주하지 않는다.

## 취향과 추천의 핵심 원칙

사용자는 **원하는 경험**, 여행지는 **제공할 수 있는 경험**으로 따로 정의한다. 사람과 여행지를 같은 성향 축에 놓고 거리를 비교하지 않는다. 사용자 정보의 의미는 [사용자 기억](docs/recommendation/memory.md), 여행권과 매칭 원칙은 [추천 구조](docs/recommendation/README.md#추천-단위와-입력)를 따른다.

취향 지문은 다녀온 여행의 컨셉을 쌓은 기록이다. 방문 횟수를 추천 점수로 쓸지는 [사용자 기억](docs/recommendation/memory.md#컨셉과-티어)의 사용자 확인 전 제안이며, 표현은 [지문](docs/screens/home-and-fingerprint.md#취향-지문)에 정한다. 2026-10-08에 5축 요약에서 바꿨다. 이는 새 설계의 원칙이며 현행 국가 추천이 전환 완료됐다는 뜻은 아니다.

## 범위

### 유지

- 사진첩·직접 입력·직접 선호 질문을 통한 온보딩.
- 여행 등록·상세·구간 기록·수정 가능한 평가·여행 랭킹.
- 취향 지문과 공유, 추천·여행 조건·북마크·제외·기억 관리.
- 하루 한 장과 연간 Wrapped·공유 카드.
- 로그인 없이 이용 가능한 흐름. Apple 로그인은 선택이다.

### 동결

- 사진 스캔 합치기·나누기 예외 처리의 추가 고도화.
- 장식 목적 A/B 사진 세트와 지문 그래프 개선. 질문의 의미나 정보 표현 정확성 개선은 허용한다.
- 랭킹 드래그 중 실시간 미리보기의 추가 투자.

### 제외

- 크레딧·종량 과금. 구독은 LLM 기능에 한해 도입한다(위 목표 참조).
- 전 세계 모든 도시의 완전한 커버리지.
- 출시 전 협업 필터링·집계 학습 서버. 출시 후 사용자 평가로 여행지 적합성을 갱신하는 것은 검증을 거쳐 허용한다([갱신 원칙](docs/recommendation/README.md#여행지-값의-갱신-출시-후)).
- 사용자 기록·도시 자료·검색 결과를 담는 외부 DB. 사용자 기록은 기기에 두고, 도시 자료는 앱 번들에 넣어 앱 업데이트로 갱신한다(2026-10-07 결정). LLM 호출 서버는 이 제외와 별개다. 서버 저장이 필요해지면 Firebase(Cloud Functions와 Firestore)를 쓴다. Firebase 제외는 2026-10-07에 해제했고, 사용량·도시 추가 수요를 위한 서버 기록의 예외와 무엇을 언제 저장할지는 [추천 구조](docs/recommendation/README.md#2026-10-07-추가-결정-구독-자료-배포-저장)를 따른다.
- 도착 감지·위치 권한.
- 실시간 항공 가격·총예산 적합 보장. 자동 일정 생성기는 2026-10-08에 제외 범위에서 뺐다. 계획은 없으며, 함께 갈 도시 추천 뒤의 가능성으로만 둔다([목록에 없는 도시](docs/recommendation/README.md#목록에-없는-도시)).
- 후보 비교 화면·유료 상세 비교 상품.

범위 변경은 별도 제품 결정이다. 기존 기능이 있다는 사실과 새 설계의 요구사항·출시 가능 여부는 구분한다.
