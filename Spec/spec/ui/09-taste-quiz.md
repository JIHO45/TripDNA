# 취향 퀴즈 — 여행 이력 없는 유저의 초기 UTV (P2-C 구체화)

전제: [07-onboarding-ui-flow.md](07-onboarding-ui-flow.md)의 P2-C(사진 A/B 선택)를
문항 수준으로 구체화한 문서. 퀴즈만으로 첫 추천 3슬롯까지 도달하는 것이 목표입니다.

**분기 기준 — 축별 신뢰도 게이트 (여행 수 고정 분기 아님)**:

온보딩 등록 완료 시점의 축별 신뢰도 `c_a`([spec/02](../signal/02-signal-quality-and-aggregation.md)
4.4절, 온보딩 확장 포함)를 계산해, **`c_a < c_min`(제안 0.4)인 축의 문항만 동적 출제**합니다.

```
c_a = n_a / (n_a + k_axis)          # k_axis = 4, 온보딩 시점 decay_a ≈ 1
n_a = Σ(등록 여행별 v_a) + 태그·비교 수
v_a = 축의 국가측 변별력 가중 (파일럿 축 분산에서 도출; 온보딩 확장 — spec/02 4.4)
```

- 전 축 미달(여행 0~2개 수준) → 사실상 풀 퀴즈 13문항.
- 여행 ~5개 등록 → natureUrban 등 변별력 높은 축은 통과, **국가분산 FAIL 축
  (energyLevel·socialMode)만 자동으로 남아** 미니 퀴즈 3문항(Q3·Q5·Q7, ~15초)이 됨 —
  하드코딩이 아니라 수식에서 도출.
- 전 축 통과 → 퀴즈 생략, 바로 P3.
- **관심사 문항은 별도 게이트**: 관심사 태그 관측 0이면 노출 (백필은 태그를 안 받으므로
  사실상 항상 노출).
- c_min(0.4)은 "축당 유효 신호 3개"와 동치 (n=3 → c=0.43). 원격 설정으로 분리해 튜닝.
- 등록된 여행은 개수와 무관하게 전부 원장에 기록 — 퀴즈 prior와 병행, 실평가가
  쌓이면 prior는 자연 감쇠.

## 1. 설계 원칙

1. **한 문항 = 한 축 (변인 분리)**: 두 축을 동시에 묻는 교차 적재 A/B 문항 금지.
   A/B 양자택일에서 교차 적재는 4분면 중 2개만 선택지로 제공하므로, 나머지 2분면
   유저(예: "고요한 자연", "왁자지껄한 도시")는 선택 마비 → 억지 응답 → 초기 UTV 노이즈.
2. **두 축의 조합 정보는 2×2 쿼드런트 문항으로만**: 사진 4장(4분면 전부) 중 1장 선택.
   선택 마비 없이 한 탭으로 두 축을 동시 계측. A/B 교차 적재의 안전한 대체물.
3. **원탭 + 탈출구**: 모든 문항에 "모르겠어요 / 둘 다 좋아요" 고스트 버튼(시각적으로
   약하게). 탈출구 응답은 **결측 처리** — 억지 신호 주입 금지 (다크 패턴 금지 원칙).
4. **축 배분은 신호 공백 기준**: 이 퀴즈의 유저는 여행 이력이 없어 **모든 축이 수동
   신호 0**입니다. 따라서 유일한 확정 매칭축(가중치 1.0)인 `natureUrban`을 두텁게,
   국가분산 FAIL로 자기보고 외 계측 수단이 없는 `energyLevel`·`socialMode`도 두텁게.
5. **선택지 카피는 태그 어휘와 같은 언어** ([spec/06](../recommendation/06-tag-vocabulary.md)):
   첫 추천 설명("당신이 고른 '고요한 평화'와 닮은 나라")이 퀴즈 직후부터 작동해야 함
   (체감 루프 1 — 태그 언어의 순환).

## 2. 문항 세트 (13문항, 약 75~85초)

### A/B 사진 문항 (12개) — 한 문항 = 한 축

| # | 축 | 질문 | A (서명) | B (서명) |
|---|---|---|---|---|
| Q1 | natureUrban | 한 달 살기를 한다면? | 인프라가 잘 갖춰진 편리한 도심 (+0.7) | 창문을 열면 숲과 바다가 있는 자연 (-0.7) |
| Q2 | natureUrban | 숙소 창밖으로 보고 싶은 풍경은? | 대자연 (-0.7) | 도시 스카이라인 (+0.7) |
| Q3 | energyLevel | 여행 중 완벽한 오후는? | 조용히 쉬어가기 (-0.7) | 꽉 채워 즐기기 (+0.7) |
| Q4 | energyLevel | 여행 다녀온 뒤 듣고 싶은 말은? | "푹 쉬다 왔구나" (-0.6) | "진짜 알차게 놀았구나" (+0.6) |
| Q5 | socialMode | 아름다운 야경 앞에서 드는 생각은? | "혼자 이 분위기를 온전히 즐겨야지" (-0.7) | "아, 누군가와 같이 봤어야 하는데!" (+0.7) |
| Q6 | socialMode | 여행지에서의 저녁은? | 혼자 조용히 현지 맛집 (-0.7) | 새로 만난 사람들과 왁자지껄 (+0.7) |
| Q7 | socialMode | "같이 다닐래요?" 우연한 동행 제안, 내 마음은? | 부담스럽다 (-0.6) | 반갑다 (+0.6) |
| Q8 | planningStyle | 출발 전날 밤, 나는? | 숙소만 잡고 나머지는 현지에서 (-0.7) | 시간 단위 일정표 완성 (+0.7) |
| Q9 | planningStyle | 맛집은 어떻게 찾나요? | 걷다가 끌리는 곳에 들어감 (-0.6) | 미리 리스트 만들고 예약까지 (+0.6) |
| Q10 | noveltyAppetite | 여행지에서 맞이한 첫 아침, 내 발걸음은? | 남들이 다 가는 유명 랜드마크부터 (-0.7) | 지도에 없는 낯선 로컬 골목으로 (+0.7) |
| Q11 | noveltyAppetite | 낯선 현지 음식 앞에서 나는? | 익숙한 메뉴를 찾는다 (-0.6) | 일단 도전해본다 (+0.6) |
| Q12 | natureUrban | 여행 사진첩에 더 많길 바라는 장면은? | 산·바다·하늘 (-0.6) | 거리·건물·사람 (+0.6) |

### 2×2 쿼드런트 문항 (1개) — 사진 4장 중 1장

| # | 축 조합 | 질문 | 4분면 선택지 (서명) |
|---|---|---|---|
| Q13 | natureUrban × energyLevel | 지금 당장 순간이동한다면? | 호숫가 오두막 (nU -0.5, eL -0.5) / 래프팅·트레킹 대자연 (nU -0.5, eL +0.5) / 골목 카페 소도시 (nU +0.5, eL -0.5) / 야시장 대도시 (nU +0.5, eL +0.5) |

> 쿼드런트 문항의 **성립 조건 2가지**: ①측정하는 두 축만 4장에서 갈리고 나머지 축은
> 통제될 것(제3축 고정), ②4분면 각각이 **독립적인 여행 원형(archetype)으로 자연스럽게
> 존재**할 것. Q13은 네 장면이 각각 원형이라 성립. 사진 검수 시 동행/군중의 존재감
> (socialMode)이 4장에서 비슷해야 함.
>
> socialMode × energyLevel 쿼드런트는 **설계했다가 폐기** — 제3축을 고정하면 네 칸이
> "혼자+활동 / 친구+활동"의 조합 나열이 되어 유저 눈에 매트릭스가 노출되고(행동 패턴
> 중복), 혼자/함께 구도는 Q5~Q7에서 이미 3회 계측. 매칭 모델에 상호작용 항이 없어
> 잃는 정보도 미미(쿼드런트 응답은 결국 축별 평균에 ±0.5로 합산될 뿐).

### 관심사 문항 (1개, 마지막)

- **"여행에서 가장 끌리는 걸 3개 골라주세요"** — spec/06 관심사 태그 9개 칩 그리드.
- Interest Tags 초기화 + `interestFit` + 추천 설명 어휘 확보 (이것이 없으면 첫 추천이
  축 언어로만 설명되어 반쪽).

축별 계측량: natureUrban 2+쿼드1, energyLevel 2+쿼드1, socialMode 3,
planningStyle 2, noveltyAppetite 2, 관심사 1.

### 문항 순서와 리듬 (고정 — 재배치 금지)

**A/B 12개 → 쿼드런트 1개 → 관심사 칩 1개** 순서는 인지 부하 설계입니다.

- A/B 구간은 좌우 원탭의 단일 리듬으로 속도감 있게 소화 (쿼드런트를 중간에 섞으면
  선택지 수가 2→4→2로 출렁이며 인지 부하가 튐).
- 쿼드런트는 A/B 리듬이 끝난 뒤 후반에 — 마지막 관심사 칩 그리드(9개)로
  넘어가기 전의 자연스러운 브릿지.
- 상호작용은 전 구간 **사진 탭(클릭) 선택** — 스와이프 제스처 없음. 탭이 학습 비용이
  0이고, 쿼드런트(4장)·관심사 칩과 입력 방식이 통일되어 구간 전환 시 조작법이 안 바뀜.
- 트랜지션 가이드: A/B 구간은 탭 즉시 다음 문항으로 빠른 슬라이드 전환(선택 카드에
  짧은 글로우 피드백), Q13부터는 부드러운 크로스페이드로 전환해 "구간이 바뀌었다"는
  신호를 시각적으로 제공.

## 3. 점수화 → 초기 UTV

```
UTV[축a] = 해당 축을 건드린 응답 서명의 평균
           (쿼드런트 서명 ±0.5는 A/B ±0.6~0.7보다 자연 가중 하향)
탈출구 응답 → 해당 문항 결측 (평균에서 제외)
축 전체 결측 → 인구 사전값(0), 신뢰도 최저
```

- **축별 신뢰도 상한 0.4** (제안값): 자기보고 prior의 "신뢰도 하향 플래그"(3.0 스펙
  2.1절 3단 폴백)의 구체화. 응답 문항 수에 비례하되 상한을 넘지 않음.
- **원장 밖 prior로 보관**: 퀴즈는 여행이 아니므로 여행 원장(불변)에 넣지 않습니다.
  UTV 재생 시 초기값으로만 주입 — 실제 평가가 쌓이면 λ 스케줄에 따라 자연 희석.

## 4. 추천 연결 (퀴즈만으로 3슬롯 도달)

- `tasteFit`: 초기 UTV ↔ 국가 Taste Core 코사인, 축별 신뢰도 가중 (기존 5절 변경 1).
- `interestFit`: 관심사 3개 ↔ 국가 Interest Tag Profile.
- `contextFit`: 유저 입력 불필요 — 공개데이터 Constraints + 상황 필터 기본값.
- 램프업: `w_pop` 비중 높게 시작 (기존 램프업 규칙의 시작점).
- `fresh_stretch` 폴백: 방문 이력이 없어 `noveltyDistance` 계산 불가 →
  한국인 방문 빈도 등 공개데이터 프록시로 대체 (이 퀴즈 경로의 유일한 신규 폴백).
- 결과 화면 카피는 **"첫인상 지문"**으로 구분 (P2-C 기존 규칙 승계).

## 5. 계측·검수

- 이벤트: `quiz_answered { questionId, choice: "A"|"B"|"Q1"~"Q4"|"escape", elapsed_ms }`
  + 기존 `onboarding_step_completed`. spec/05에 병합 필요.
- **문항별 탈출구 선택률**: 특정 문항만 유독 높으면 문항 교체 신호.
- **문항→서명 매핑은 2인 검수 게이트 대상** (spec/06과 동일 — 리스크 #2의 확장).
- **사진 세트 검수 기준**: A/B 한 쌍은 **한 축만** 갈라야 함 (예: energyLevel 문항의
  두 사진이 자연/도시로도 갈리면 natureUrban 오염). 쿼드런트 4장은 4분면이 명확하고
  **측정하지 않는 제3축이 4장에서 동일**해야 함 (2절 제3축 고정 원칙).
  3.0 스펙 11절 "사진 세트 제작" 미결 항목의 구체 요건.

## 6. 미결 항목

- 서명 값 전체 확정 (2인 검수)
- 신뢰도 상한 0.4의 실측 튜닝 (원격 설정 분리 — 리스크 #5 원칙)
- 사진 세트 제작 (5절 검수 기준 적용)
- ~~P2-A/P2-B 유저용 미니 버전 채택 여부~~ → **확정**: 축별 신뢰도 게이트로 미달 축
  문항만 동적 출제 (1절 분기 기준). 남은 미결은 `c_min`(0.4)과 간접 신호 가중
  `v_a`(spec/02 4.4)의 실측 튜닝 — 원격 설정으로 분리
