# UI-1. 취향 온보딩

## 1. 목적

유저가 앱의 가치를 먼저 이해하고, 과거 여행 등록 또는 사진 선택 퀴즈로 첫 여행 지문과
추천을 얻도록 합니다. “축을 직접 설정”하는 화면이 아니라 **행동과 여행 이력으로 축을 추정**하는
플로우입니다.

근거: [온보딩 플로우](../07-onboarding-ui-flow.md), [13문항 퀴즈](../09-taste-quiz.md)

## 2. 메인 UI 구조

### UI-1A. 훅

#### 1A-1 가치 선언

- 중앙: 여행 경로로 그려지는 지문 모션
- 헤드라인: `지금까지의 여행이, 다음 여행지를 알고 있어요`
- 보조 설명 1줄: `다녀온 여행으로 먼저 읽고, 부족한 축만 짧게 물어볼게요`
- 주 CTA: `시작하기`
- 보조 문구: `약 2분이면 끝나요`
- 금지: 로그인 버튼, 긴 앱 소개, 페이월, “설문부터 시작” 뉘앙스

#### 1A-2 기대 설정

- 예시 5축 지문
- 문구: `과거 여행을 넣으면 취향이 그려지고, 부족한 부분만 몇 문항 더 묻습니다`
- 보조 문구: `여행 기록이 없으면 사진 선택으로 첫인상을 만들어요`
- 주 CTA: `내 지문 만들기`
- 상단: 뒤로가기, 건너뛰기

### 비즈니스 로직 — 축 신뢰도 게이트 후 퀴즈

과거 여행을 등록해도 축마다 신호량이 다릅니다. 퀴즈는 **전 문항을 무조건 묻지 않고**,
등록 직후 축별 신뢰도를 계산한 뒤 **임계값보다 낮은 축만** 출제합니다.

```text
과거 여행 등록 완료
  → 축별 신뢰도 c_a 계산
  → c_a < c_min 인 축만 퀴즈 출제
  → 통과한 축은 질문하지 않음
  → 관심사 태그가 0이면 관심사 화면만 별도 노출
```

| 기호 | 의미 | 초기값 |
|---|---|---|
| `c_a` | 축 a의 신뢰도 | `n_a / (n_a + k_axis)` |
| `n_a` | 등록 여행·태그·비교에서 모인 축 a의 유효 신호량 | 여행 국가 프로필 변별력 가중 포함 |
| `k_axis` | 베이지안 완화 상수 | `4` |
| `c_min` | 퀴즈 출제 하한 | `0.4` (축당 유효 신호 ≈3개와 동치, 원격 설정) |

#### 판정 결과별 UI

| 판정 | 조건 | UI |
|---|---|---|
| 퀴즈 생략 | 전 축 `c_a ≥ c_min` | 바로 지문 합성(UI-1D) |
| 미니 퀴즈 | 일부 축만 `c_a < c_min` | 미달 축 문항만 동적 출제 (예: energy·social만 → Q3·Q5·Q7 수준) |
| 풀 퀴즈 | 전 축 미달 또는 여행 0개 | A/B 12 + Q13 + 관심사 |
| 관심사만 | 축은 통과, 관심사 태그 관측 0 | 관심사 칩 화면만 |

규칙:

1. 게이트는 **여행 개수 고정 분기가 아니라** 축별 `c_a`로만 판단한다.
2. 통과한 축의 문항은 화면에 아예 올리지 않는다.
3. 퀴즈 응답은 원장에 넣지 않고 UTV prior로만 보관한다. 이후 실평가가 쌓이면 prior는 희석된다.
4. 유저에게는 기술 용어 대신 `부족한 취향만 조금 더 확인할게요`처럼 말한다.
5. `c_min`·`k_axis`는 원격 설정으로 분리해 튜닝한다. 상세 산식은 [spec/09](../09-taste-quiz.md)·[spec/02](../../signal/02-signal-quality-and-aggregation.md).

### UI-1B. 과거 여행 찾기

#### 1B-1 등록 방식 선택

사진 권한 요청을 기본 경로로 강제하지 않고 처음부터 두 방식을 동등하게 선택하게 합니다.

- 제목: `지난 여행을 어떻게 불러올까요?`
- 선택 카드 1 — `사진첩에서 자동으로 찾기`
  - 사진 위치를 기기 안에서 분석해 국가·시기를 자동 완성
  - `빠르게 등록` 배지
- 선택 카드 2 — `직접 입력하기`
  - 국가·시기·만족도를 직접 입력
  - 사진 권한 없이 진행 가능
- 여행 이력이 없는 경우: `사진 퀴즈로 시작`

#### 1B-2 사진첩 프라이밍

`사진첩에서 자동으로 찾기`를 고른 경우에만 표시합니다.

- 세계 지도와 감지될 여행 핀 예시
- 필수 경계 문구: `사진 위치는 기기 안에서만 분석돼요. 서버로 전송되지 않아요.`
- 주 CTA: `사진 접근 허용하고 찾기`
- 보조 CTA: `직접 입력으로 바꾸기`

#### 1B-3 시스템 권한

- iOS 사진 권한 다이얼로그
- 허용 → 온디바이스 EXIF 스캔
- 거부/위치 태그 없음 → UI-6 과거 여행 수동 등록
- 재요청 압박 금지

#### 1B-4 스캔 진행

- 실제 단계와 일치하는 상태 문구: `사진 위치 확인 중` → `여행별로 묶는 중`
- 취소 가능
- 결과 없음 → `여행 기록을 찾지 못했어요` + `직접 등록` / `사진 퀴즈로 시작`

#### 1B-5 여행 확인 카드 루프

- 카드: 여행별 대표 사진, 국가(복수 가능), 도시, 대략적 시기
- 위치·날짜가 이어진 사진 군집은 여행 1건으로 묶고 국경을 넘으면 다국가 구간으로 제안
- 잘못 나뉜 군집은 `여행 합치기`, 잘못 합쳐진 군집은 `여행 나누기`로 수정
- 대표 사진은 군집 후보에서 자동 제안하고 유저가 같은 여행 사진 중 교체
- 질문: `이 여행, 얼마나 좋았나요?`
- 입력: 만족도 1~5 원탭
- 두 번째 여행부터 서열 비교 1회
- 보조 CTA: `이 여행 아니에요`, `나머지는 나중에`
- 3개 이상 등록 후 `지문 보러 가기` 활성화
- CTA 탭 시 **바로 지문을 그리지 않고**, 위에서 정의한 **축 신뢰도 게이트**를 먼저 실행
- 미달 축이 있으면 UI-1C로, 없으면 UI-1D로 이동

#### 1B-6 정확도 판정 브리지 (자동, 짧은 연출)

- 별도 질문 화면 없음
- 0.5~1초 수준: `여행으로 취향을 읽는 중`
- 결과에 따라:
  - 전 축 통과 → `여행만으로 지문을 그렸어요` 후 UI-1D
  - 일부 미달 → `아직 흐린 취향만 짧게 확인할게요` 후 UI-1C(미니)
  - 전 축 미달 → UI-1C(풀)

### UI-1C. 사진 취향 퀴즈

게이트를 통과하지 못한 축의 문항만 출제합니다. 과거 여행으로 이미 충분한 축은 묻지 않습니다.

#### 공통 레이아웃

- 상단: 뒤로가기, 진행 바, `현재 문항 / 출제 문항 수`, 건너뛰기
- 중앙: 질문 1줄
- 본문: 선택 가능한 사진 카드
- 하단: `모르겠어요 / 둘 다 좋아요`
- A/B 선택은 탭 즉시 짧은 글로우 후 다음 문항으로 이동
- 스와이프 입력은 사용하지 않음
- 미니 퀴즈일 때 상단 보조 문구: `부족한 취향만 확인하고 있어요`

#### 출제 분기 (축 신뢰도 게이트 결과)

- 모든 축 신뢰도 부족 → 아래 A/B 12개 + Q13 + 관심사 문항
- 일부 축만 부족 → **해당 축 문항만** 동적 출제 (통과 축 Q는 제외)
- 모든 축 충분 → 퀴즈 생략, UI-1D로
- 관심사 관측이 없으면 관심사 문항은 축 게이트와 별도로 노출

### Q13. 2×2 사진 선택

- 질문: `지금 당장 순간이동한다면?`
- 2열 × 2행 카드:
  1. 호숫가 오두막
  2. 래프팅·트레킹 대자연
  3. 골목 카페 소도시
  4. 야시장 대도시
- 한 장 선택, `모르겠어요` 제공
- natureUrban × energyLevel을 동시에 측정
- 전환은 A/B 구간과 다르게 크로스페이드

### 관심사 선택

13문항 뒤 별도 마무리 화면입니다. 퀴즈의 축 문항 수에는 포함하지 않습니다.

- 질문: `여행에서 가장 끌리는 걸 3개 골라주세요`
- 9개 칩: 미식, 문화/예술, 역사/유적, 자연/트레킹, 해변/휴양, 밤문화, 쇼핑,
  휴식/웰니스, 스포츠/페스티벌
- 최대 3개, 1개 이상 선택 시 CTA 활성화
- 주 CTA: `내 지문 만들기`

## 4. 결과 UI

### UI-1D-1 지문 합성

- 2~4초 고정 연출
- 단계: `여행 분석 중` → `취향 축 계산 중` → `30개국과 비교 중`
- 실제 수행하지 않는 작업을 표시하지 않음

### UI-1D-2 첫 지문

- 5축 지문 시각화
- 축: 자연↔도시, 고요↔활동, 즉흥↔계획, 혼자↔함께, 익숙함↔새로움
- 낮은 신뢰도 축: 흐리게 표시 + `아직 데이터가 적어요`
- 퀴즈만 사용한 경우 제목: `첫인상 지문`
- 주 CTA: `내게 맞는 여행지 보기`

### UI-1D-3 첫 추천

- UI-4의 3슬롯 축약본
- 추천 확인 후 UI-2 로그인으로 이동
- 로그인 전에도 지문과 추천은 반드시 보여줌

## 5. 상태와 예외

| 상태 | 처리 |
|---|---|
| 사진 권한 거부 | 즉시 수동 등록 또는 퀴즈 선택 |
| 감지 여행 0개 | 실패 문구 대신 두 대체 경로 제공 → 풀 퀴즈 가능 |
| 여행 1개 | 비교 질문 생략, 게이트는 그대로 실행 |
| 여행 등록 후 전 축 통과 | 퀴즈 생략, 바로 지문 |
| 여행 등록 후 일부 축 미달 | 미달 축 문항만 출제 |
| 문항 건너뛰기 | 결측 처리, 중립값 강제 주입 금지 |
| 앱 종료 | 마지막 완료 단계부터 복구 |
| 오프라인 | 퀴즈·로컬 스캔 진행, 로그인 후 Firestore 동기화 대기 |

## 6. 데이터와 이벤트

- 과거 여행: `users/{uid}/trips/{tripId}`, `evalSource=onboarding_backfill`
- 퀴즈 prior: 여행 원장에 넣지 않음. UTV 초기값으로 별도 보관
- 이벤트:
  - `onboarding_step_completed`
  - `quiz_answered { questionId, choice, elapsed_ms }`
  - `trip_evaluated(source=onboarding_backfill)`
