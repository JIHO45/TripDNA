# UI-2. 로그인·계정

## 1. 목적과 노출 시점

첫 지문과 첫 추천을 확인한 뒤 기록을 안전하게 저장하고 다른 기기에서도 복구하도록 합니다.
온보딩 시작 전에 로그인을 강제하지 않습니다.

근거: [온보딩 플로우 P4](../07-onboarding-ui-flow.md), [Firestore 구조](../../data/10-firestore-schema.md)

## 2. 메인 UI

### UI-2A. 계정 생성

- 상단: 방금 생성된 지문 미니 카드
- 헤드라인: `이 지문을 안전하게 보관할까요?`
- 설명: `여행 기록과 추천을 다른 기기에서도 이어볼 수 있어요`
- 주 CTA: `Apple로 계속하기`
- 하단 링크: 이용약관, 개인정보처리방침

MVP 인증 제공자는 Apple 로그인 하나로 고정합니다. 게스트 진입과 Google 로그인은 제공하지
않습니다. 인증을 취소하면 생성한 지문·추천을 현재 화면에서 다시 볼 수 있지만 홈으로
진입하거나 서버에 저장할 수 없습니다.

### UI-2B. 로그인 진행

- 시스템 Apple 인증 UI
- 앱으로 복귀하면 계정 생성/기존 계정 확인
- 성공 시 온보딩 임시 데이터와 `uid` 연결
- 처리 중 CTA 비활성화, 중복 요청 금지

### UI-2C. 성공

- 체크 모션과 `지문을 저장했어요`
- 주 CTA: `홈으로 가기`
- 1초 후 자동 이동하더라도 CTA 유지

## 3. 서브 UI

### 기존 계정 복구

- 동일 Apple 계정이면 기존 Firebase Auth `uid`로 로그인
- Firestore의 기존 원장을 불러옴
- 현재 기기의 임시 온보딩 데이터가 있으면 즉시 합치지 않고 확인:
  - `기존 기록 8개를 불러왔어요`
  - `이번에 추가한 여행 3개도 저장할까요?`
- 중복 여행 후보는 국가+기간 기준으로 표시하고 유저 확인 후 저장

### 로그아웃

- 진입: 홈 프로필 메뉴 → 계정
- 설명: `이 기기의 로그인은 해제되지만 Firebase에 저장된 기록은 유지됩니다`
- 확인 CTA: `로그아웃`

### 계정 삭제

- 진입: 계정 화면 최하단
- 영향 범위 명시: 여행 원장, 평가, 랭킹, 사진 참조, 피드백 삭제
- 재인증 후 최종 확인
- MVP 구현 전 Firebase Auth 계정과 Firestore 사용자 데이터의 실제 삭제 절차를 별도로 확정

## 4. 상태와 예외

| 상태 | UI 처리 |
|---|---|
| 인증 취소 | 오류로 취급하지 않고 로그인 화면 유지 |
| 네트워크 오류 | `연결을 확인하고 다시 시도해 주세요` + 재시도 |
| 기존 계정 | 원장 복구 상태를 먼저 보여준 뒤 홈 이동 |
| 데이터 충돌 | 자동 덮어쓰기 금지, 중복 후보 확인 |
## 5. 데이터

- 인증: Firebase Authentication
- 원장: Firestore `users/{uid}/...`
- 로그인 상태: Firebase Auth 세션
- UserDefaults에는 온보딩 완료 여부 같은 UI 상태만 저장하고 여행 원장은 저장하지 않음

## 6. 완료 조건

- 인증 성공 및 `uid` 확보
- `users/{uid}` 루트 문서 생성 또는 기존 문서 로드
- 온보딩 데이터를 유저 스코프에 저장
- UI-3 메인으로 이동
