# UI-4. 여행지 추천

## 1. 목적

유저의 지문·관심사·상황 제약을 바탕으로 성격이 다른 3개의 추천을 제시하고, 저장/스킵/싫어요
반응을 다음 추천에 활용합니다.

근거: [3슬롯 설명 체계](../../recommendation/04-slot-explainability.md), [3.0 스펙 5·6절](../../../docs/product/Travel_Fingerprint_3.0_Spec.md)

## 2. 메인 UI

### UI-4A. 추천 3슬롯

- 상단:
  - 제목 `당신의 지문으로 찾은 다음 여행지`
  - 상황 필터 버튼
  - 저장 목록 버튼
- 카드 1 — `가장 잘 맞아요` (`best_match`)
- 카드 2 — `새로운 도전` (`fresh_stretch`)
- 카드 3 — `숨은 보석` (`underrated_fit`)

각 카드 구성:

1. 목적지 대표 이미지
2. 슬롯 라벨
3. 국가명
4. 취향 매치 점수
5. 추천 이유 1~2줄
6. 현실 적합도 배지(예산·시즌·동행)
7. 저장, 스킵, 싫어요 버튼

`싫어요`는 더보기 메뉴에 숨기지 않습니다. 카드마다 항상 보이게 둡니다.

## 3. 카드별 설명

### Best match

- 제목: `가장 잘 맞아요`
- 설명 우선순위:
  1. 상위 여행에서 고른 태그 인용
  2. 유사한 랭킹 상위 여행 인용
  3. 기여 상위 축
- 예: `교토에서 골랐던 고요함·미식과 닮았어요`

### Fresh stretch

- 제목: `새로운 도전`
- 취향 적합도 하한은 통과하지만 기존 여행보다 탐험성이 큼
- 예: `익숙한 취향에서 반 발짝 바깥이에요`
- 저장·방문 이력으로 탐험 반경을 조정하되 스킵은 반경이나 재노출 확률을 낮추지 않음

### Underrated fit

- 제목: `숨은 보석`
- 인기는 낮아도 관심사·현실 적합도가 높은 나라
- 예: `많이 알려지진 않았지만 미식 취향이면 잘 맞아요`

## 4. 서브 UI

### UI-4B. 상황 필터

바텀시트 또는 전체 화면:

- 총 여행 예산 범위와 인원(선택)
- 여행 시기: 월 또는 계절
- 동행: 혼자 / 커플 / 가족 / 친구
- 출발 국가·공항(프로필 기본값, 이번 검색에서 변경 가능)
- 비행 부담 허용도(노선 데이터가 준비된 경우에만 노출)
- 안전 기준
- 적용 CTA: `추천 다시 보기`
- 초기화 CTA 제공

목적지를 이미 정한 뒤 받는 “여행 무드” 입력은 두지 않습니다.

### UI-4C. 목적지 상세

- 대표 이미지와 국가명
- 추천 슬롯과 취향 매치
- `왜 추천했나요?`
  - 태그/랭킹 근거
  - 사용된 확정축
- `현실적으로는`
  - 예산, 시즌, 비행, 안전 정보
  - 검증된 데이터가 없는 항목은 숫자나 적합 배지를 추정해서 표시하지 않음
- `알아둘 점`
  - 부정 태그 리프트가 임계 이상일 때 정직한 주의 문구
- CTA:
  - `저장`
  - `관심 없어요`
  - `이 나라로 여행 등록`

Match Score와 현실 적합도를 하나의 숫자로 합치지 않습니다.

### UI-4D. 저장 목록

- 저장한 국가 카드 리스트
- 저장 시점의 추천 이유 유지
- 최신 상황 필터로 다시 확인 가능
- CTA: `여행으로 등록`
- 저장 해제 제공

### UI-4E. 피드백 확인

- 저장: 북마크 채움 + `저장했어요`
- 스킵: 현재 카드만 다음 후보로 교체. 학습 점수·탐험 반경·향후 재노출 확률은 변경하지 않음
- 싫어요: `이유를 알려주실래요?` 선택 바텀시트
  - 너무 비쌈
  - 너무 멂
  - 안전이 걱정됨
  - 취향이 아님
  - 이유 선택은 선택 사항

`싫어요`는 강한 음성 신호입니다. 해당 국가는 180일간 일반 추천 후보에서 제외하고 이후에도
강한 페널티를 유지해 거의 노출하지 않습니다. 설정의 `추천에서 제외한 여행지`에서 유저가
직접 해제할 수 있습니다. `너무 비쌈`·`너무 멂`처럼 상황성 이유를 선택했더라도 자동으로
복원하지 않고, 필터 변경 시 `다시 추천에 포함할까요?`를 명시적으로 묻습니다.

### UI-4F. 예측 대 실제 결과

추천 저장 후 실제 방문·평가가 연결된 경우:

- `예측 매치 82% ↔ 실제 여행 랭킹 2위`
- 어긋난 경우 지문 변화 델타
- CTA: `달라진 추천 보기`

## 5. 상태와 예외

| 상태 | 처리 |
|---|---|
| 지문 데이터 부족 | 인기 가중치를 높이고 `첫 추천` 표시 |
| 30개국 밖 국가 | 회색 처리 또는 추천 후보 제외 |
| 필터 결과 0개 | 어떤 필터가 후보를 제거했는지 안내, 완화 CTA |
| 카드 스킵 | 같은 슬롯의 다음 후보로 교체 |
| 3장 모두 반응 완료 | 새 세트 생성 CTA, 무한 자동 로딩 금지 |
| 오프라인 | 마지막 추천 캐시 표시, 피드백 동기화 대기 |

## 6. 데이터와 이벤트

- 읽기: `countries`, `tagVocabulary`, 사용자 UTV/원장
- 쓰기: `users/{uid}/cardFeedback/{feedbackId}`
- 이벤트:
  - `slot_impression`, `slot_click`, `slot_save`, `slot_reopen`
  - `recommendation_feedback { slot, action, countryCode }`
  - `exploration_slot_feedback`
- 설명 유형: 태그 인용 / 랭킹 앵커 / 축 폴백

### 현실 적합도 데이터 범위

- 현재 국가 데이터에는 Numbeo 기반 국가별 상대 물가 지수 `constraints.cost`만 있습니다.
- 유저의 총예산·인원·여행일수와 항공·숙박 실가격 데이터가 없으므로 현재 값만으로
  `예산에 맞음`을 단정하지 않습니다. MVP에서는 `물가 낮음/중간/높음` 참고 배지만 표시합니다.
- 정확한 비행시간은 출발지와 도착 공항, 노선·경유 데이터가 필요합니다. 국가 간 값을
  하드코딩하지 않습니다.
- 공항 데이터 도입 시 `airports`에 좌표·도심 이동시간을 두고, 노선 제공자/API로
  직항·경유·예상 비행시간을 계산합니다. 수하물 수취 시간은 공항·도착편에 따라 변동이 커
  검증된 출처가 있을 때만 범위로 표시합니다.
- 노선 데이터 도입 전에는 비행시간 필터와 숫자 표시를 숨깁니다.

## 7. 완료 조건

- 성격이 다른 3슬롯이 동시에 구분되어 보임
- 각 카드에서 저장·스킵·싫어요가 바로 가능
- 추천 근거와 현실 제약이 분리되어 설명됨
