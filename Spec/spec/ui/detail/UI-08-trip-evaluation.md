# UI-8. 여행 종료 평가

## 1. 목적

여행 종료 후 **판정 + 서열 + 귀속**을 단일 구간 기준 30초 안에 수집하고, 평가 직후 지문과
추천이 어떻게 변했는지 보여줍니다.

근거: [3.0 스펙 2.2절](../../../docs/product/Travel_Fingerprint_3.0_Spec.md),
[태그 어휘](../../recommendation/06-tag-vocabulary.md), [신호 계산](../../signal/02-signal-quality-and-aggregation.md)

## 2. 시작 UI

### UI-8A. 평가 시작

- 하루 한 장 사진을 날짜순 배경/스트립으로 표시
- 제목: `{여행명}, 어땠나요?`
- 문구: `약 30초면 다음 추천이 더 정확해져요`
- 주 CTA: `평가 시작`
- 보조 CTA: `나중에`, `평가 건너뛰기`

`나중에`는 상태 유지, `평가 건너뛰기`는 방문 사실만 남기고 `skipped=true`로 완료합니다.

## 3. 판정

### UI-8B-1 만족도

- 질문: `이 여행, 전체적으로 얼마나 좋았나요?`
- 1~5 대형 원탭
- 선택 즉시 다음
- 배경에 해당 여행 사진 1~3장

### UI-8B-2 재방문 의향

- 질문: `다시 가고 싶은 여행인가요?`
- `또 가고 싶어요` / `한 번이면 충분해요`
- `잘 모르겠어요`는 null

### UI-8B-3 가장 좋았던 국가

다국가 여행에만 표시:

- 질문: `가장 좋았던 나라는 어디였나요?`
- 여행 구간 국가 칩
- 한 개 선택
- 단일 국가 여행은 화면 자체를 생략

판정·서열은 **여행 전체에 한 번만** 묻습니다. 국가마다 만족도·재방문·서열을 반복하면
다국가 여행의 입력 시간이 크게 늘고 여행 단위 랭킹과도 충돌합니다. 국가 차이는
`bestLegCountryCode`와 아래 태그별 국가 귀속으로 수집합니다.

## 4. 서열

### UI-8C. 과거 여행 비교

- 질문: `{앵커 여행}과 비교하면 어땠나요?`
- 두 여행 사진 카드
- `이번 여행이 더 좋았어요`
- `{앵커}가 더 좋았어요`
- `비슷해요 / 기억 안 나요` → skipped

앵커 선택은 같은 만족도 점수대의 최근 비의무 여행 → 인접 점수대 → 직전 여가 여행 순입니다.
첫 여행은 화면 생략.

## 5. 귀속

### UI-8D-1 좋았던 것

- 질문: `특히 좋았던 것은?`
- 최대 5개
- 태그 그룹을 시각적으로 분리:
  - 성향: 고요한 평화, 에너지 넘치는 자극 등
  - 관심사: 미식, 문화/예술, 자연/트레킹 등
- 방문국 프로필 우선 태그 + 와일드카드 1~2개
- 양극 태그는 반드시 쌍으로 노출
- 선택 0개도 다음 가능
- CTA: `다음`

### UI-8D-2 다국가 태그 귀속

다국가 여행에서 taste 라우팅 태그를 선택한 경우에만:

- 질문: ``{태그}`는 어느 나라에서 느꼈나요?`
- 여행 구간 국가 칩
- `전체 여행에서` 또는 건너뛰기
- 태그별 반복하되 한 화면에서 빠르게 처리

### UI-8D-3 아쉬웠던 것

- 질문: `아쉬웠던 점도 있었나요?`
- 최대 3개
- 부정 전용 태그:
  - 너무 북적였어요
  - 너무 심심했어요
  - 일정이 너무 빡셌어요
  - 계획대로 안 돼서 힘들었어요
  - 날씨가 아쉬웠어요
  - 예상보다 비쌌어요
  - 이동이 힘들었어요
  - 바가지/불친절
  - 위생이 아쉬웠어요
  - 인프라가 부족해 불편했어요
- 선택 사항
- 주 CTA: `평가 완료`

## 6. 결과

### UI-8E-1 처리

- `여행 기록을 지문에 반영하는 중`
- 원장 저장과 UTV 재생
- 실패 시 평가 입력을 잃지 않고 재시도

### UI-8E-2 지문 변화

- 전후 지문 오버레이
- 변한 축과 태그 근거
- 변화가 거의 없으면 그대로 표시
- 조건부축 변화에는 `지문에는 쌓이지만 추천 매칭에는 아직 사용하지 않아요`

### UI-8E-3 추천 갱신

- 즉시 갱신된 추천 1슬롯
- 문구: `이번 평가로 다음 추천이 바뀌었어요`
- CTA: `추천 보기`
- 보조 CTA: `홈으로`

### UI-8E-4 여행 대표 사진·공유

평가 저장 후 선택적으로 표시하며 30초 평가 시간에는 포함하지 않습니다.

- 하루 한 장에서 직접 고른 사진을 여행 대표 사진으로 우선 제안
- 직접 고른 사진이 없으면 동의된 자동 후보를 제안
- `다른 사진 고르기`로 하루 한 장 목록 또는 사진첩에서 교체
- `이 사진으로 대표 카드 만들기` / `나중에`
- 완성된 여행 카드는 연중 이미지 저장·공유 가능
- 다국가 여행은 여행 전체 대표 사진 1장을 사용

## 7. 진행 구조

단일 국가 기준:

```text
시작 → 만족도 → 재방문 → 비교 → 좋았던 태그 → 아쉬웠던 태그 → 지문 변화
```

다국가 기준:

```text
시작 → 만족도 → 재방문 → 베스트 국가 → 비교 → 좋았던 태그
→ 태그별 국가 귀속 → 아쉬웠던 태그 → 지문 변화 → 대표 사진(선택)
```

상단에는 전체 단계 수보다 `1/3 판정`, `2/3 비교`, `3/3 취향`처럼 세 파트 진행을 표시합니다.

## 8. 상태와 예외

| 상태 | 처리 |
|---|---|
| 첫 여행 | 비교 자동 생략 |
| 평가 전체 스킵 | 방문 사실 기록, 중앙값 대체, 반영 상한 하향 |
| 태그 0개 | 허용, 국가 프로필 base로만 계산 |
| 부정 태그 0개 | 허용 |
| 다국가 귀속 건너뛰기 | 베스트 구간 가중 배분 |
| 의무 여행 | 평가 가능, 최종 취향 게인 ×0.2 |
| 사진 없음 | 국가·기간 중심의 단색 배경 |
| 오프라인 | 원장 업데이트를 로컬 캐시에 보존, 결과 계산 가능 범위 표시 |

## 9. 데이터와 이벤트

- 업데이트: `users/{uid}/trips/{tripId}`
- 평가 필드: `satisfaction`, `wouldRepeat`, `bestLegCountryCode`, `comparison`,
  `positiveTags`, `negativeTags`, `tagLegAttribution`, `evalSource`, `skipped`
- 대표 사진: 여행 문서의 `coverPhotoStoragePath`에 Storage 경로 저장
- 이벤트:
  - `trip_evaluated`
  - `utv_recomputed(trigger=evaluated)`
- 제출 전에는 뒤로가기로 모든 응답을 수정할 수 있습니다. 최종 제출 후에는 MVP에서 평가
  수정 기능을 제공하지 않습니다. 잘못된 서열은 랭킹 보드에서 교정합니다. 평가 수정을
  추후 제공하려면 기존 값을 덮어쓰지 않고 revision 이력을 추가해야 합니다.

## 10. 완료 조건

- 원장 평가 필드 저장
- 랭킹 삽입 또는 비교 스킵 상태 저장
- UTV 재생 및 지문 델타 표시
- 추천 1슬롯 갱신
