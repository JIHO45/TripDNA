# 칩 선택 대 LLM 비교 — 계획 (2026-10-08 고정, 호출 전)

질문: 추천 탭에서 LLM을 쓰는 것이 이득인가, 경험 칩 선택과 코드 계산으로 충분한가.

## 방식

| 방식 | 입력 | 순위를 정하는 것 |
|---|---|---|
| A | 칩 | 충족률 ([coverage-check](../coverage-check/result.md)의 산식과 등급표 그대로) |
| B | 칩 | Gemini 3.8 Flash + Google 검색 |
| C | 칩 + 자유문장 | 같은 모델·설정 |

- B·C의 모델·지침·출력 형식은 실행 6의 FS 방식 그대로다(`guidelines/r6-agents.md`의 `search2`, 추론 `low`, 후보 최대 2개). 사용자 칸의 문장만 다르다.
- B의 사용자 칸: “좋아하는 경험: … / 꼭 원하는 경험: … / 피하고 싶은 것: …”. 고르지 않은 항목은 적지 않는다. 칩이 없는 사례(R10, R12)는 “선택한 항목 없음”을 보낸다(건너뛰기에 해당).
- C의 사용자 칸: B의 문장 뒤에 “이번 여행에 바라는 점: (자유문장)”.
- 사례 13개 × 2방식 = 26호출, 반복 없음. 스크립트의 최악 추정으로 US$2.5를 넘으면 멈춘다.

## 사례

[cases.json](cases.json). 취향 사례 T1~T6(자유문장과 확인 대상은 이번에 작성)과 기존 사례 7개(S5, N5, R3, R9~R12, 문장 원문 그대로).

## 보는 것 (호출 전 고정)

1. 조건 위반: `violators`가 있는 사례에서 각 방식의 후보에 위반 도시가 있는가. A는 상위 3곳(동점 포함).
2. A와 B의 겹침: B의 후보가 A의 상위 두 그룹 안에 있는 비율.
3. B에서 C로 바뀐 후보 수, C가 `target`(자유문장에만 있는 요구)을 근거나 유의점에서 다루는가.
4. 호출당 비용·지연·검색어 수.

## 읽는 규칙

- B의 후보 3분의 2 이상이 A의 상위 두 그룹 안이고 위반 수도 비슷하면: 칩만 받을 때는 LLM을 부를 이유가 약하다.
- C가 A·B의 위반이나 놓친 요구를 사례 절반 이상에서 바로잡으면: LLM의 값은 자유문장에 있다.
- 둘 다 아니면 결론을 내지 않는다.

## 한계

- 판정자는 Claude Opus 5.5 한 명이고 방식을 가리지 않는다. 사람 검수가 아니다.

- R3의 위반 도시 목록은 작성자 판단이며 미검증이다.
