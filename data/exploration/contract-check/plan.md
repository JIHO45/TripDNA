# 계약 확인 — 실행 1 계획

2026-10-15 작성. 같은 날 63회를 실행했다([결과](result.md)). 계약은 [LLM 적용 방식 5절](../../../docs/llm/README.md#5-입력응답-계약-초안)이다.

이 실험은 추천 품질 전체를 입증하지 않는다. 새 입력·응답 계약과 검사기가 실제 응답에서 작동하는지, 그리고 그 결과 기존 실패가 줄면서도 쓸 만한 후보와 설명이 남는지를 본다. "전부 확인 필요"로 처리해 오류만 줄어드는 것은 성공으로 세지 않는다.

## 묻는 것

1. 검사기가 실제 응답의 계약 위반을 놓치지 않는가
2. 실행 2의 실패(F12 조용한 승인, F11 근거 없는 제외, F07 상위 후보 누락)가 줄었는가
3. 자유문장 조건이 없는 사례에서 실행 2보다 나빠지지 않았는가
4. 자유문장 조건 사례에서 쓸 만한 후보와 구체적인 유의점이 남는가
5. 제외 예외, 지난 여행 메모, 예산·기간, 사용자 데이터 속 지시를 계약대로 다루는가

## 고정한 것

첫 호출 뒤에는 이 폴더의 파일을 고치지 않는다. 고치면 새 실행이다.

- [`schema.json`](schema.json): 응답 형식.
- [`prompt.md`](prompt.md): 지침. 첫 실행은 API의 형식 강제를 쓰지 않고 `schema.json`을 지침 끝에 붙여 보낸다. 형식 강제는 따로 비교한다.
- [`cases.json`](cases.json): 새 계약 사례 C01~C08.
- 회귀 사례: [실행 2의 13개](../fixed-data-check/run2/cases.json)를 그대로 읽는다.
- 도시 자료: [실행 2의 20곳](../fixed-data-check/run2/draft.json). 이전 숫자 등급으로 매긴 미검수 초안이며, 입력에서는 등급 이름으로 바꿔 보낸다.
- 입력 조립과 검사: `scripts/check_contract.py`의 `user_message`와 `check`.

## 방식과 호출 수

두 모델에 같은 지침·schema·입력을 보낸다. 검색과 API 형식 강제는 둘 다 쓰지 않는다. 2026-10-15 사용자 결정으로 Haiku 5.5를 더했다.

| 방식 | 모델 | 설정 | 반복 | 호출 | 용도 |
|---|---|---|---|---|---|
| `flash` | Gemini Flash(`gemini-3.8-flash`) | 생각 수준 low. 실행 2와 같다 | 1회 | 21 | 실행 2 기준선과 비교. 모델이 같아서 바뀐 것이 계약뿐이다 |
| `haiku` | Claude Haiku 5.5(`claude-haiku-5-5`) | 추론 켜짐(끌 수 없음), effort medium(기본값) | 2회 | 42 | 모델 후보로서의 품질과 응답의 흔들림 |

- 두 모델의 추론 설정은 맞출 수 없다. Flash의 low와 Haiku의 medium은 같은 정도가 아니다.
- `haiku`의 기준은 두 번 모두 만족해야 충족이다. `flash`는 한 번이라 우연일 수 있다.
- 출력 상한은 두 모델 모두 8,192토큰이다(추론 포함). 확인용 사례는 정해지면 따로 센다.

## 비용

- 지출 규칙: 첫 외부 파일럿 총 US$10 상한을 모든 실험이 함께 쓴다([평가 계획](../../../docs/evaluation/README.md)).
- 지금까지의 지출: 이 기기의 응답 기록을 합치면 US$6.93이다. 다른 기기에서만 돌린 실행이 있으면 빠져 있다. 남은 한도는 약 US$3.07이다.
- 단가(100만 토큰당 입력/출력): Flash US$0.75/3.75(스크립트의 기존 값, 2026-10-07 확인), Haiku 5.5 US$0.10/0.50(Anthropic 단가표 2026-10-06 기준, 프롬프트 10만 토큰 이하).
- 예상: 실행 2 검색 없음은 호출당 약 US$0.012였다. 이번에는 지침·schema·출력이 길어지므로 `flash`를 호출당 US$0.03으로 잡으면 21회에 US$0.63이다. `haiku`는 같은 토큰 수로 약 1/7.5이라 42회에 US$0.2 안팎이다.
- 호출 직전마다 "이번 실행의 기록된 지출 + 다음 호출의 최대치(입력 문자당 2토큰, 출력 상한 전부)"가 US$1.50을 넘으면 멈춘다. API 오류도 기록하고 멈춘다.
- 결제 잔액(사용자 확인, 2026-10-15): Google 약 4,600원, Anthropic US$5 충전. 위 총 US$10 상한과는 별개다.

## 합격 기준

| | 기준 | 미충족이면 |
|---|---|---|
| A. 검사기 | AI 판독으로 찾은 계약 위반 가운데 검사기 범위 안의 것을 검사기가 모두 잡는다 | 검사기를 고치고 같은 응답으로 다시 센다(호출 없음) |
| B. 기존 실패 | F11·F12·F13: 자유문장 조건이 `required: true`로 추출되고, 모든 후보가 그 조건을 보고하고, "확인됨" 카드가 0이다. F07·F11: "말없이 빠짐"이 0이다. 검증되지 않은 탈락은 실패로 센다 | 계약이나 지침을 고쳐 새 실행 |
| C. 비회귀 | F01~F09·C06: 빠진 필수 후보가 실행 2보다 늘지 않는다(F07은 줄어야 한다). 시즌 미확인 세부에 기대는 후보(F05·F06의 이스탄불)만 "확인 필요"이고 나머지 카드는 "확인됨"이다. 카드 수가 min(3, 기준 후보 수) | 실패. 원인을 계약·지침·검사기 중에서 찾는다 |
| D. 유용성 | F10~F13·C07·C08: 카드가 1장 이상 남는다. 유의점이 그 조건을 구체적으로 다룬다(판독) | 실패 유형으로 기록하고 다음 변경의 대상으로 삼는다 |
| E. 새 계약 | C01 예외 적용, C02·C03 예외 없음과 `forbid` 없음, C04 `memories_used`에 t1과 관련 있는 반영, C05 이유 추측 없음, C06 예산·기간 때문의 탈락·"확인 필요" 0, C07 "확인됨"과 유의점, C08 지시 미이행 | D와 같다 |

A·B를 모두 만족하고 C에 회귀가 없을 때 "계약과 검사기가 작동한다"고 적는다. D·E의 미충족은 다음 변경(지침 수정, 기준 순서, few-shot) 가운데 무엇을 먼저 비교할지 정하는 근거로 쓴다.

## 코드가 세는 것과 읽을 것

코드가 응답마다 센다: 형식 실패(JSON 파싱과 `schema.json` 사후 검사. API 형식 강제는 쓰지 않지만 사후 검사는 한다), 목록 밖 ID, 중복, 제외 위반, 예외 근거 위반, 시기 조건 누락, 조건 보고 누락, LLM의 `met` 표시, 검증되지 않은 탈락, 말없이 빠짐, 사례의 필수 후보 없음, 입력에 없는 여행, 문장의 등급 표현, 카드와 표시 상태, 비용, 지연.

AI 1명(판정자)이 읽는다: 이해 요약이 맞는가, 추출한 조건의 필수·선호 구분, 이유가 핵심 경험에 기대는가, 유의점이 구체적인가, 확인하지 않은 사실을 단정하는가, `passed_over`의 이유가 타당한가, 메모 반영이 맞는가.

## 하지 않는 것

검색, API 형식 강제, 100곳 입력, 티어 가중치, 예상 비용 범위, 사람의 품질 평가.

## 호출 전에 남은 것

1. **확인용 사례.** 지금까지 사례와 기대를 모두 AI가 만들었다. 확인용 사례는 사용자가 요청 문장으로 3~5개를 쓰고, 지침을 고치는 동안 열지 않는 것을 권한다. AI가 쓰면 그 한계를 결과에 적는다.
2. **호출 경로.** `check_contract.py`의 `--run`, `--report`. 2026-10-15 작성, 호출 전.
3. **지출 승인.** 위 비용으로 호출해도 되는지 사용자가 정한다.

## 한계

- 사례·기대·판정자가 모두 AI다. 도시 자료 20곳은 사람 검수 전이다.
- `flash`는 사례당 1회, `haiku`는 2회다. 응답이 흔들리는지 보는 최소한이며 차이가 우연일 수 있다.
- 두 모델은 추론 설정이 달라 같은 조건의 비교가 아니다.
- 지출 합계는 이 기기의 기록만 센 것이다.
