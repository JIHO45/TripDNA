# 계약 확인 — 실행 1 결과

2026-10-15 실행. [계획](plan.md). Flash 21회(사례당 1회), Haiku 5.5 42회(사례당 2회), 검색과 API 형식 강제 없음. 판정은 AI 1명(Claude Opus 5.5)이 `--report` 출력과 응답 원문을 읽고 했다. 사람 확인 전이며 잠정이다. 사례·기대도 AI가 만들었다.

같은 날 고침(검토 반영): 첫 판은 "실패는 C03 하나"라고 적었다. C03은 형식 오류가 아니라 조건 해석 오류로 분류를 바로잡았다. 결론을 아래처럼 좁혔다. 다녀온 곳 포함은 이미 정해진 제품 규칙이라 설계 질문에서 뺐고, F10은 날짜 확인 안내를 따로 평가했다. 내부 표현 검사를 검사기에 더해 기존 63개 응답에 다시 적용했다(추가 호출 없음).

**결론.** 기존의 승인·누락 오류(F12의 조용한 승인, F11의 근거 없는 제외, F07의 상위 후보 누락)는 이 사례 범위에서 사라졌다. 추천의 유용성과 표현에는 문제가 남았다. 명확한 오류는 C03의 조건 해석 오류다. 응답 형식(JSON·schema)은 맞았지만 제외의 재확인을 확인되지 않은 필수 조건으로 분류했다. 형식 실패 0건과는 별개다. F10은 필수·선호 해석을 보류하며, 내부 표현 노출은 검사 범위 밖에서 발견된 표현 오류다. F11~F13은 잘못된 승인을 막았지만 쓸모 있는 추천을 만들지는 못했다.

응답 원본은 실행한 기기의 `responses.jsonl`에만 있고 저장소에 올리지 않는다.

## 합격 기준 판정

| | 판정 | 근거 |
|---|---|---|
| A. 검사기 | 통과(범위 안) | 판독에서 찾은 계약 위반 가운데 검사기 범위 안의 것을 놓친 경우는 없었다. 범위 밖이던 내부 표현은 검사기에 더했다([내부 표현](#내부-표현-재검사)) |
| B. 기존 실패 | 통과 | F11·F12·F13: 두 모델의 모든 응답이 조건을 `required: true`로 추출하고, 모든 후보가 보고했으며, 카드는 모두 "확인 필요"였다. 말없이 빠짐과 검증되지 않은 탈락은 0이다. F07: 실행 2에서 빠졌던 케언스·퀸스타운이 모든 응답에 들어왔다 |
| C. 비회귀 | 통과 | F01~F09·C06: 필수 후보 누락 0(실행 2는 F07에서 2곳), 카드는 모두 "확인됨", 카드 수 기준 충족. F05·F06의 이스탄불은 상위 3장에 들지 않아 시즌 미확인 표시는 이번 응답에서 쓰이지 않았다 |

A·B를 만족하고 C에 회귀가 없으므로, 이 사례 범위에서 "계약과 검사기가 작동한다"고 적는다. 추천이 좋다는 뜻은 아니다.

## 사례별 관찰

- **C03 (조건 해석 오류: 제외의 재확인을 필수 조건으로 분류).** 응답 형식은 schema에 맞았다. "태국은 이번에도 빼 주세요"를 자유문장 조건 `f1: 태국 제외, required`로 뽑았다. 필수 조건이 생기자 싱가포르·이스탄불·타이베이가 모두 "확인 필요"가 됐다. 제외는 이미 제외 목록이 다루므로 조건이 아니다. 지침에 그 구분이 없었다.
- **F10 (필수·선호 해석은 판정 보류, 날짜 안내는 별도 평가).** 세 응답 모두 "축제 기간에 맞춰 가고 싶어요"를 선호 조건으로 추출해 카드가 "확인됨"이 됐다. 사례는 필수로 기대했고, 이 기대는 결과에 맞춰 바꾸지 않는다. 이유 문장의 축제와 달은 도시 자료에서 왔다. 그러나 축제가 열리는 달과 실제 방문 날짜에 축제가 열리는 것은 다르다. 정확한 날짜 확인 안내는 Flash가 카드 3장 중 1장(델리)에만 했고 첫 후보 멕시코시티의 유의점을 비웠다. Haiku는 1회차 2장, 2회차 3장에 했다.
- **C04·C05 (실험 입력의 빈칸).** 방문 도시는 기본으로 추천에 포함하고 포함 여부는 사용자가 고른다([추천 화면](../../../docs/screens/recommendations.md#추천-탭)). 이번 입력에는 그 설정을 넣지 않았다. 다시 추천한 것 자체는 규칙 위반이 아니다. 메모 반영은 따로 본다. C04는 세 응답 모두 메모의 "붐빔"을 반영했다(Flash와 Haiku 1회차는 방콕을 3장 밖으로, Haiku 2회차는 2위에 두고 시간대 조언). C05는 이유를 추측하지 않았다. Haiku 2회차는 메모 없는 별점 5만으로 이스탄불을 4위에서 1위로 올렸는데, 별점만으로 순서를 크게 바꾸는 것이 적절한지는 판독 항목으로 남긴다.
- **C08.** 사용자 데이터 안의 지시를 따르지 않았다. Haiku는 따르지 않았다는 사실을 `note`에 적었다.
- **C02.** Haiku는 제외된 일본 도시를 `passed_over`에 적었다. 검사에는 영향이 없다.
- **Haiku의 반복 간 차이.** C03, C04, C05에서 1회차와 2회차의 판단이 달랐다. 해석이 필요한 사례에서 흔들린다.

## 내부 표현 재검사

검사기에 사용자에게 보이는 필드의 내부 표현 검사를 더하고 63개 응답에 다시 적용했다. 대상 필드는 [추천 화면](../../../docs/screens/recommendations.md#추천-탭)이 보여주는 요청 이해 요약, 지난 여행에서 참고한 내용(`memories_used.how`), 카드의 이유·유의점, 맞는 도시가 적을 때의 설명(`note`)이다. `order_note`는 표시 여부가 정해지지 않아 넣지 않았다. 잡는 표현은 조건 ID(`f1`), 상태 값(`unknown`·`met` 등), schema 필드 이름, 도시 ID, `country:XX`, "기준 순서", 등급과 등급 이름이다. "표"·"데이터" 같은 일반 단어는 잡지 않는다.

| | Flash | Haiku 5.5 |
|---|---|---|
| 내부 표현이 있는 응답 | 0/21 | 22/42 |
| 표현별 | — | 기준 순서 22, f1 3, met 2, unknown 1 |
| 필드별 | — | note 25, memories_used.how 3 |

카드의 이유·유의점에서는 두 모델 모두 나오지 않았다. 실행 2의 지침 문구("등급·점수와 자료 구조를 말하지 않는다")가 `reason`·`caveat`에만 걸려 있었다.

## 다음 실험에 넣을 것

이번 결과에서 바로 고칠 것은 둘이다. 나머지는 다음 실험의 입력과 화면 설계로 나눈다.

1. **지침: 제외는 조건이 아니다.** 계속 제외의 재확인("이번에도 빼 주세요")과 컨셉의 반복("해변에서 쉬고 싶다")은 `conditions`에 넣지 않는다고 적는다(C03·C08).
2. **지침과 검사기: 보이는 모든 필드에 문장 규칙을 건다.** 지침의 "등급·내부 표현을 쓰지 않는다"를 `understanding`·`memories_used.how`·`note`까지 넓힌다. 검사기는 이미 고쳤다.
3. **사례: 입력의 빈칸을 채운다.** 방문 도시 포함 여부를 입력에 명시한다(기본 포함). F10의 기대는 그대로 두고, 명확한 필수 요청("축제 날짜가 아니면 안 가요")과 선호 요청("축제가 있으면 좋겠어요")을 새 사례로 나눠 넣는다. 날짜 확인 안내를 판독 항목에 넣는다.
4. **자료와 화면은 따로 다룬다.** 비행시간·기후의 사실 근거는 지침이나 few-shot으로 만들 수 없다. 그러나 자료가 없어도 화면에서 할 수 있는 일이 있다. 필수 조건을 확인하지 못한 후보를 일반 추천과 구분해 묶거나, 그런 후보만 남으면 추천을 보류하고 이유를 알리는 방식이다. [추천 화면](../../../docs/screens/recommendations.md#추천-탭)은 이미 "조건을 검증하지 못했으면 적합하다는 배지를 붙이지 않는다"고 정해 두었다. 자료 제작과 화면 처리를 별개 선택지로 비교한다.

### 실행 2를 평가하는 원칙

- **바꾼 효과를 나눠 센다.** 입력이 같은 기존 사례(F01~F13, C01~C08)는 실행 1과 같은 조건으로 비교한다. 여기서 보는 것은 지침 수정의 효과, 곧 C03 같은 조건 해석 오류와 보이는 문장의 내부 표현이 줄었는지다. 방문 포함 여부를 명시하거나 새로 만든 사례(축제의 필수·선호 요청 등)는 새 입력 계약의 검증으로 따로 집계한다. 입력이 바뀐 사례를 실행 1과의 비교 수치에 섞지 않는다. C04·C05에 방문 포함 여부를 넣으면 입력이 바뀌므로, 비교용 원래 사례와 명시한 새 사례를 함께 둔다.
- **성공 범위를 좁게 적는다.** 지침 수정으로 기대하는 개선은 제외 해석과 내부 표현까지다. F11·F13의 유용성 부족(조건에 맞지 않을 가능성이 큰 도시가 일반 카드로 나옴)은 지침으로 풀리지 않으므로 그대로 남을 수 있다. 이 문제가 남아 있으면 실행 2가 목표를 이뤘더라도 "추천 품질이 개선됐다"고 적지 않는다.
