# 계약 확인 — 실행 4 계획: 지침 v3와 신호 (d)

2026-10-17 작성. 같은 날 152회를 실행했다([결과](result.md)). 근거는 [실행 3 결과](../run3/result.md#다음에-검토할-것)와 [실행 2 결과](../run2/result.md)다.

## 묻는 것

1. 지침 v3로 날짜 요구의 조건 추출이 늘었는가(F10·E2의 미추출, E1 Haiku의 `period` 합침)
2. v3로 좁힌 규칙이 컨셉만 반복한 문장(C08, 새 K1·K5)을 다시 조건으로 뽑게 하지 않는가
3. 실행 2에서 고친 것(C03 해석, 내부 표현, 날짜 안내)과 0이던 오류가 v3에서도 유지되는가
4. 신호 (d)가 앱 입력에 합쳐진 요구를 잡아 카드를 "확인 필요"로 두는가. 다른 경우에 잘못 걸리지 않는가

이 실험은 추천 품질을 재지 않는다. F11·F13의 유용성 부족은 그대로 남을 것으로 예상하며, 남으면 "추천 품질이 개선됐다"고 적지 않는다.

## 방식과 호출 수

Flash(`gemini-3.8-flash`, 생각 수준 low)와 Haiku 5.5(`claude-haiku-5-5`, effort medium). 검색과 API 형식 강제 없음. 출력 상한 8,192토큰.

호출: 기존 24사례 × (Flash 1 + Haiku 2) = 72회, 경계 8사례 × (5 + 5) = 80회, 합계 152회.

## 비용

- 실행 2·3의 호출당 추정 비용(Flash US$0.0047·0.0051, Haiku US$0.0016·0.0017)으로 약 US$0.44다. 기록된 토큰에 단가를 곱한 추정액이며 청구액이 아니다.
- dry-run 최대 추정(입력 문자당 2토큰, 출력 상한 전부)은 US$3.35다. 엄밀한 상한은 아니다.
- 멈춤: 호출 직전마다, 다음 호출의 추정 비용을 포함해 US$1.50 초과가 예상되면 호출하지 않는다("실행 4의 기록된 지출 + 다음 호출의 최대 추정" > US$1.50). 지출과 다음 호출의 비용이 모두 추정치라, 실제 지출이 US$1.50을 넘지 않는다고 보장하지는 않는다.
- 누적: 이 기기 기록으로 센 추정액은 약 US$7.71이다. 공용 상한 US$10 대비 남은 한도는 실제 기록과 청구액으로 확인한다.

## 판정 기준

**1. 추출(v3의 목표).**

| 사례 | 개선으로 적는 조건 |
|---|---|
| E2·F10 | 두 모델 모두 자유문장 조건을 뽑은 비율이 v2보다 높다 |
| E1 | Haiku의 `period` 합침이 v2(3/12)보다 적고, 필수 조건 추출이 두 모델 모두 v2 이상이다 |
| K2 | 선호 조건을 뽑고 합치지 않는다. 5회 가운데 4회 이상을 목표로 적되, 5회라 우연을 배제하지 못한다 |
| K3·K4 | 필수 조건을 뽑고 합치지 않는다. 같은 목표 |

**2. 컨셉 반복(v3의 부작용 확인).** C08·K1·K5에서 조건을 뽑은 응답이 0이면 유지, 하나라도 있으면 회귀로 적는다.

**3. 기존 27개의 유지(실행 2와 같은 반복분).** C03 해석 오류 0, 내부 표현 0(Haiku), 날짜 안내 없음이 실행 2보다 늘지 않음, 0이던 오류 0. 하나라도 어기면 회귀로 적는다.

**4. 신호 (d).** (d)는 실행 3의 응답을 본 뒤 만든 보정 규칙이다. 실행 1~3의 264개 응답에서 3건이 걸렸다는 것은 같은 응답으로 확인한 결과이며 독립 검증이 아니다. 실행 4가 처음으로 (d)를 미리 정한 채 새 응답에 적용하는 시험이다. 응답마다 (d) 없이와 (d) 적용의 표시를 모두 남기고(보고서와 응답 기록의 `checks`), 다음을 모델별로 센다.

| 항목 | 뜻 | 판정 |
|---|---|---|
| 걸림 | (d)에 걸린 응답 수 | 기록 |
| 고침 | (d) 없이 틀린 표시가 (d)로 맞게 된 수 | 기록 |
| 오차단 | (d) 없이 맞던 표시가 (d)로 틀리게 된 수. 예: 선호 요청을 `period`에 합친 응답이 "확인 필요"가 되는 경우 | 0이 아니면 (d)의 규칙을 다시 본다 |
| 놓침 | (d)를 적용해도 표시가 틀린 수. 예: 원문을 고쳐 쓴 `quote`, 조건을 아예 뽑지 않은 필수 요청 | 0이 아니면 원인을 판독해 적는다 |

걸린 응답, 고친 응답, 놓친 응답은 모두 원문으로 확인한다. 경계 사례(K1~K5)의 결과를 기존 사례와 따로 적는다.

**표시와 효과의 분리.** 지침 v3의 효과는 (d) 없이 센 값으로 실행 2(역시 (d) 없음)와 비교한다. 코드가 잘못된 표시를 막은 효과는 같은 응답의 (d) 없이와 (d) 적용의 차이로 적는다. 실행 4의 계약상 표시는 (d) 적용 쪽이다.

## 판정 기준의 고정

이 계획의 판정 항목은 첫 호출 전에 고정한다. 첫 호출 뒤에 더하는 판단 항목은 결과 문서에 사후 탐색 분석으로 따로 적고, 이 계획의 판정에 소급 적용하지 않는다. 판정 기준을 바꿔야 하면 새 실행으로 한다.

## 세는 것과 읽을 것

`--exp 4 --report`가 출력한다.

- 기존 27개의 실행 2 대 실행 4 비교(같은 반복분), 새 사례 집계.
- 분류표: 사례·모델마다 필수·선호·조건 없음 수와, 표시가 맞은 수(지금 계약, (a), (b), (c), (d)).
- 조건 추출 누락과 불필요한 조건 추출은 최소 검사다. 엉뚱한 조건이나 일부 누락은 잡지 못한다. 경계 사례는 조건의 `text`·`quote`가 요청을 가리키는지 원문으로 판독한다.

## 한계

- 사례·기대·판정자가 모두 AI다. 도시 자료 20곳은 사람 검수 전이다.
- v3는 실행 2·3에서 본 사례를 보고 고쳤다. K1~K5 가운데 K4는 지침 예문과 가깝다. 확인용 사례(사용자 작성)는 아직 없다.

- 지침과 계약을 함께 바꿨다. 표시의 개선은 v3와 (d) 어느 쪽 덕인지 분류표의 "지금"과 "(d)" 열로 나눠 읽는다.
