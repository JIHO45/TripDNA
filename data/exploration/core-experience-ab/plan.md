# 핵심 경험 A/B — 계획

2026-10-17 작성. 같은 날 96회를 실행하고 판독했다([결과](result.md)). 근거는 [조건 판정과 순위 결정](../../../docs/recommendation/README.md#2026-10-17-결정-조건-판정과-순위)의 "핵심 경험"이다. 거기서 카드와 LLM 입력에 도시별 고정 문장을 쓸지, LLM이 요청에 맞춰 경험을 고르고 설명하게 할지를 실험 뒤 정하기로 했다. 등급의 근거가 되는 경험·시즌 자료는 이 실험과 관계없이 내부 자료로 계속 만든다.

## 묻는 것

카드에 들어갈 설명(이유·유의점)을 쓸 때, 도시별 핵심 경험 문장을 주지 않아도(B) 주었을 때(A)만큼 정확하고 요청에 맞게 쓰는가.

이 실험은 후보 선택, 조건 해석, 순서를 재지 않는다. 그것까지 포함한 전체 흐름의 비교는 B가 유망할 때 다음 단계로 한다.

## 고정한 것

두 방식에 같은 것을 주고, 차이는 하나만 둔다.

| 항목 | 고정 방법 |
|---|---|
| 요청 | 계약 확인 실험의 사례 원문(컨셉, 앱 조건, 자유문장, 지난 여행, 제외) |
| 도시와 순서 | 코드의 기준 순서에서 제외를 반영한 상위 3곳(`run_core_ab.py`의 `cards`). 모델은 고르거나 순서를 바꾸지 않는다 |
| 등급과 시즌 | 등급 이름(여행 달 적용), 세부의 시즌 달, 시즌 미확인 세부 |
| 해석된 조건 | [`cases.json`](cases.json)에 사례마다 고정(필수·보조, 확인 필요) |
| 지침 | [`prompt.md`](prompt.md) 하나. A와 B에 같다 |
| 응답 형식 | [`schema.json`](schema.json). 카드마다 `id`, `reason`, `caveat` |
| 모델·설정 | Flash(생각 수준 low), Haiku 5.5(effort medium). 검색과 API 형식 강제 없음. 출력 상한 4,096토큰 |
| **다른 것** | **A만 카드마다 "핵심 경험" 줄이 있다.** 스크립트가 두 메시지를 비교해, 핵심 경험 줄을 빼면 같음을 확인한다 |

## 사례

계약 확인 실험의 사례 12개다.

| 사례 | 고른 이유 |
|---|---|
| F01 길거리 음식+쇼핑, F07 자연+도시, F08 스파+미식, C05 문화 | 시기 조건 없는 일반 사례 |
| F03 7월 겨울 액티비티, F09 12월 동물 관찰 | 시즌에 따라 달라지는 경험 |
| F05 3월 경기 관람, F10 10월 축제(보조 선호), E1 10월 축제(필수) | 날짜에 기대는 경험. 고정 문장이 축제 이름과 달을 담고 있다 |
| F13 7월 해변, 우기 피하기(필수, 확인 필요) | 기후 주장이 섞이기 쉬운 사례 |
| C04 지난 여행 메모(방콕, 붐빔) | 메모의 반영 |
| X1 "조용한 카페"(보조, 확인 필요) | 근거 없는 판단이 섞이기 쉬운 사례 |

## 방식과 호출 수

12사례 × 2방식(A·B) × 2모델 × 2회 = 96회.

## 비용

- dry-run 최대 추정(입력 문자당 2토큰, 출력 상한 전부)은 US$1.00이다. 엄밀한 상한은 아니다.
- 입력이 계약 확인 실험보다 짧고(지침 포함 약 1,800~2,500자) 출력도 카드 3장의 설명뿐이다. 앞선 실험의 호출당 토큰으로 보면 실제 추정은 약 US$0.2다.
- 멈춤: 호출 직전마다, 다음 호출의 추정 비용을 포함해 이 실험의 지출이 US$0.80을 넘을 것으로 보이면 호출하지 않는다. 추정이라 실제로 넘지 않는다고 보장하지는 않는다.
- 누적: 이 기기 기록으로 센 추정액은 약 US$8.17이다. 공용 상한 US$10 대비 남은 한도는 호출 전에 실제 청구액과 다른 기기의 기록으로 확인한다.

## 코드가 세는 것

`--report`가 모델·방식별로 센다. 문제가 있던 응답 수다.

- 형식 실패(JSON·schema)
- 카드 불일치(주어진 도시·순서와 다름)
- 보이는 문장의 내부 표현(등급 이름, 도시 ID, 조건 ID 등)
- 날짜 확인 안내 없음(축제·경기 사례, 유의점의 "날짜·일정·일자·기간" 단어 기준)
- 입력·출력 토큰, 추정 비용, 지연

## 판독

`--export`가 같은 사례·모델·반복의 A와 B를 짝지어 무작위로 "가"·"나"를 붙인 판독표(`judging.md`)를 만든다. 판독자는 어느 쪽이 A인지 모른 채 판독한다. 정답 키(`judging_key.json`)는 판독이 끝난 뒤 연다. 쌍은 48개다.

쌍마다 두 응답을 각각 판독한다.

| 항목 | 뜻 |
|---|---|
| 확인 결과 틀린 사실 | 도시 자료나 확인 가능한 출처와 어긋나는 주장(예: 없는 축제, 다른 도시의 명소) |
| 확인할 수 없는 사실 | 맞는지 확인하지 못한 구체적 주장(예: 특정 가게, 정확한 운영 기간). 틀린 것과 따로 센다 |
| 여행 시기와 맞지 않는 계절·행사·운영 주장 | 여행 달에 할 수 없거나 열리지 않는 경험을 그 달의 경험처럼 쓴 것(예: 10월 교토의 벚꽃). 필수 조건만이 아니라 카드 설명 전체에서 센다 |
| 요청에 맞는 구체적인 이유 | 1~3. 요청의 컨셉·조건·메모와 연결되고, 그 도시에서 할 일이 구체적인가 |
| 더 나은 쪽 | 가·나·같음 |

판독자는 AI 1명이다. 사람이 판독표 가운데 일부(사례마다 1쌍 이상)를 같은 기준으로 다시 판독해 어긋나는 항목을 적는다. "확인 결과 틀린 사실"로 적으려면 근거(도시 자료의 문장이나 출처)를 함께 적는다. 근거를 대지 못하면 "확인할 수 없는 사실"로 적는다.

## 판정 기준

모델마다 따로 판정한다.

| 결과 | 조건 |
|---|---|
| B가 유망하다 | 틀린 사실 수와 시기 불일치 주장 수가 모두 A 이하이고, "더 나은 쪽"에서 B가 A보다 많이 뽑혔다 |
| A를 유지한다 | 틀린 사실이나 시기 불일치 주장이 B에서 A보다 많다 |
| 판정 보류 | 그 밖의 경우(예: 오류는 같고 선호가 갈림) |

- 확인할 수 없는 사실은 B에서 늘 것으로 예상한다. 판정 조건에 넣지 않고 수를 함께 적는다. 늘어난 주장이 필수 조건과 관련되면 따로 적는다.
- 코드 검사(형식, 카드 불일치, 내부 표현)는 두 방식 모두 0이어야 한다. 아니면 그 원인을 먼저 적는다.
- "B가 유망하다"는 고정 문장을 없앤다는 결정이 아니다. 다음 단계에서 후보 선택과 조건 해석까지 포함해 비교한다.

## 판정 기준의 고정

이 계획의 판정 항목은 첫 호출 전에 고정한다. 첫 호출 뒤에 더하는 판단 항목은 결과 문서에 사후 탐색 분석으로 따로 적고, 이 계획의 판정에 소급 적용하지 않는다.

## 실행

```
.venv/bin/python scripts/run_core_ab.py --dry-run
.venv/bin/python scripts/run_core_ab.py --run
.venv/bin/python scripts/run_core_ab.py --report
.venv/bin/python scripts/run_core_ab.py --export
```

응답 기록(`responses.jsonl`), 판독표, 정답 키는 저장소에 올리지 않는다.

## 한계

- 사례 12개, 사례·고정 해석·판독자가 AI다. 도시 자료 20곳은 사람 검수 전이며 이전 숫자 등급으로 매긴 초안이다. A의 핵심 경험 문장도 미검수다.
- 판독자가 A의 핵심 경험 문장을 정답처럼 보면 B를 불리하게 판독할 수 있다. "틀린 사실"에는 근거를 요구해 이를 줄인다.
- 2회 반복이라 흔들림은 대략만 보인다.
- 카드 3장과 순서를 고정했으므로, 실제 흐름에서 B가 후보를 다르게 골랐을 때의 영향은 재지 않는다.
- 문장의 사실을 전부 검증하지는 못한다. 확인하지 못한 주장은 "확인할 수 없는 사실"로 남는다.
