# 고정 자료 추천 확인 — 실행 2 계획

2026-10-12 작성. 같은 날 26건을 실행했다([결과](result.md)). [실행 1 결과](../result.md)와 Codex 검수에 따른 것이다. 사용자가 검색을 쓰는 쪽을 물었고, 같은 지침으로 검색 없음과 있음을 비교하기로 했다.

## 묻는 것

1. 지침을 고치면 실행 1의 오류(부 컨셉으로 후보를 뺌, 미확인 조건을 추천으로 냄, 확인하지 않은 내용을 단정함, 문장에 등급을 말함)가 사라지는가
2. 검색을 켜면 자료에 없는 조건(비행시간, 기후, 고도, 축제 날짜)에서 확인된 후보가 생기는가. 출처가 그 주장을 실제로 뒷받침하는가
3. 검색으로 비용과 지연이 얼마나 느는가

## 고정한 것

이 폴더의 파일을 첫 호출 뒤에는 고치지 않는다. 고치면 새 실행이다.

- [`draft.json`](draft.json): 20곳 자료의 사본. 실행 1과 같은 내용이다.
- [`cases.json`](cases.json): 13개. 입력은 실행 1과 같고 채점 기준만 바꿨다.
- [`prompt.md`](prompt.md): 공통 지침과 검색 방식에만 붙는 부분.

## 실행 1에서 바꾼 것

| 항목 | 실행 1 | 실행 2 |
|---|---|---|
| 방식 | 검색 없음 | 검색 없음(off), 검색 있음(on) |
| 부 컨셉 | 지침에 없음 | 순서에만 쓰고 후보를 빼지 않는다 |
| 말한 조건 | 자료 밖 지식을 표시해 유의점에 쓴다 | 자료나 검색 결과로 확인된 것만 말한다. 후보마다 `confirmed` 또는 `needs_check` |
| 조건에 어긋나는 도시 | 구분 없음 | 출처가 있으면 `excluded`로 빼고 이유를 적는다 |
| 시즌 미확인 | 유의점에 적는다 | 빼지 않고 `needs_check` |
| 문장 | 규칙 없음 | 등급·점수와 자료 구조를 말하지 않는다 |
| 채점 | 기대 도시가 하나라도 있으면 통과 | 있어야 하는 도시가 모두 있는가, 조건 승인 문제가 있는가 |
| 기록 | 사례 ID가 키 | 사례 ID와 방식이 키. 실행 폴더에 입력을 함께 고정 |

검색은 사용자가 말한 조건 가운데 자료로 답할 수 없는 것을 확인하는 데만 쓰게 했다. 어떤 도시가 컨셉에 맞는지는 검색으로 다시 정하지 않는다.

## 코드가 세는 것과 사람이 읽을 것

코드가 세는 것:

- 허용 ID, 주 컨셉 2등급 이상(시즌 적용)
- 있어야 하는 도시가 모두 있는가
- 조건 승인 문제: 말한 조건이 있는 사례에서 검색 없이 `confirmed`, 출처 없이 `confirmed`, `confirmed`로 나오면 안 되는 도시가 `confirmed`
- 문장에 등급·점수를 말한 후보 수

사람이 읽을 것:

- 출처가 그 주장을 실제로 뒷받침하는가
- 유의점이 요청과 관련 있는가, 확인하지 않은 내용을 단정하는가
- 검색 방식이 뺀 도시와 그 이유가 맞는가
- 순서가 적절한가

## 한계

- `not_confirmed`의 근거(호놀룰루 약 8시간 이상 등)는 작성자의 지식이며 출처와 대조하지 않았다.
- 13건을 방식마다 한 번씩 돌린다. 반복하지 않으므로 차이가 우연일 수 있다.
- 자료 20곳과 사례는 사람 검수 전이고 판정자는 AI다.
- 검색 방식의 응답 원본은 [Gemini 그라운딩 조항](../../README.md#저장소에-올리지-않는-기록-2026-10-12) 때문에 저장소에 올리지 않는다. 표시한 결과의 텍스트 보관은 최대 30일이다.
- 입력이 20곳이다. 100곳의 입력 크기는 다루지 않는다.
