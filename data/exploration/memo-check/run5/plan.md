# 실제 여행 메모 — 실행 5 계획: 미확인을 불충족으로 바꾸지 않는다

2026-10-13 작성. 같은 날 6건을 실행했다([결과](result.md)). 실행: `scripts/run_real_memo.py`(기본이 실행 5).

## 왜 하는가

[실행 4](../run4/result.md)에서 사용자는 조건 처리 규칙을 넣은 쪽을 골랐다. 읽힌 요구는 "내 조건을 임의로 좁히지 말고, 내가 허용한 범위 안에서 가능한 선택지를 설명해 달라"였다. 그 방식에도 문제가 남아 있었다.

- `excluded`에 고르지 않은 도시가 전부 들어갔다(14~15곳).
- 비용 자료가 없는데 "현실적으로 불가능"이라며 뺐고, 안전을 근거로 도시를 위험하다고 단정했다.
- 한 도시에는 일정 조정을 검토하고 다른 도시에는 검토하지 않았다.
- 사용자가 허용한 범위(1~2주) 밖의 조정을 제안했고, 확인하지 않은 조정을 "가능하다"고 썼다.

## 바꾸는 것

조건 처리 문단 하나만 바꾼다. 입력, 후보 목록, 개인화 규칙, 문장 규칙, 확인 질문 지침은 실행 4와 같다.

| 방식 | 내용 |
|---|---|
| PC | 실행 4의 PC와 같은 문장. 같은 시트에서 비교하려고 다시 돌린다 |
| PD | 조건 처리 문단을 아래처럼 바꾼다 |
| PDQ | PD에 실행 4에서 받은 확인 질문과 사용자의 답을 더한다 |

PD의 조건 처리:

1. `excluded`에는 사용자가 실제로 말한 조건을 어긴다는 근거가 있는 도시만 넣는다. 고르지 않은 도시를 설명하지 않고, 말하지 않은 조건을 만들지 않는다.
2. 비용과 안전은 근거가 부족한 것이 보통이다. 그럴 때는 빼지도 충족이라 하지도 않고 확인 필요로 둔다.
3. 같은 기준을 모든 도시에 적용한다. 한 도시에 일정 조정을 검토하면 다른 도시에도 검토한다.
4. 조정은 사용자가 허용한 범위 안에서만 제안하고, "조정하면 가능하다"가 아니라 "그 조합으로 가능한지 확인해야 한다"고 쓴다.
5. 도시가 싸다, 비싸다, 안전하다, 위험하다를 사실로 쓰지 않는다. 인상이나 추정이면 그렇다고 밝힌다. 사용자가 안전을 중요하게 여긴 것은 그대로 존중해, 자기 상황에서 무엇을 확인해야 하는지를 말한다.

목표는 "안전을 근거로 빼지 않는다"가 아니다. "근거 없이 안전하다거나 위험하다고 단정하지 않는다"다. 조건을 실제로 어기는 도시는 뺀다.

PDQ는 실행 4에서 결함이 있었던 답의 전달(여러 번호를 고른 답)을 고친 뒤 다시 보는 것이다. PC와 PD의 비교와는 별개이며, 답이 추천에 주는 영향은 실행 4에서 판정하지 못했다.

## 보는 것

1. `excluded`가 짧아졌는가. 남은 것은 사용자가 말한 조건을 어긴 도시인가
2. 비용과 안전에 대한 단정이 사라졌는가. 그러면서 사용자의 걱정은 다뤘는가
3. 도시마다 같은 기준을 썼는가
4. 조정 제안이 1~2주 안에 있는가
5. 규칙이 엄격해져서 설명이 쓸모없이 조심스러워지지는 않았는가. "확인 필요"만 늘고 고를 근거가 없어지면 그것도 실패다

## 평가

`--sheet`가 방식을 가린 시트를 만든다. 1부는 2부를 읽기 전에 적고, 이유에는 목록에서 보이는 것만 적는다. 목록에 대한 선호와 조건을 충족하는지는 다른 기록이다. 가격과 안전에 관한 문장은 이 실험에서 검증하지 않는다.

## 한계
