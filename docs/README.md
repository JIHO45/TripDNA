## 적용 범위

이번에 바뀐 설계는 **추천·출처·평가**다. 그 세 주제만 v2 원문을 적용하고, 화면·사용자 기억·저장·계측은 위에 연결한 기존 원문을 유지한다. 후보·제휴·출시도 기존 원문에서 지정한 범위만 참조한다. v2의 나머지 압축본은 채택 철회된 초안이며 요구사항의 추가·삭제 근거로 사용하지 않는다.

기존 원문에는 과거 추천 설계의 전제가 함께 적혀 있다. 다음 교차 참조는 해당 주제의 현재 원문으로 해석한다.

- 검수 DB를 필수로 전제한 추천/상세 생성, 기본 DB 정보의 즉시 표시, 자동 검색 금지, 생성·캐시 처리: [추천 구조](#recommendation). 기존 화면의 진입·행동·배치를 폐기하지 않으며 검색 앱 도입은 여전히 미정이다.
- 근거 ID·검수·만료·답변 분류 등 추천 사실의 허용 기준: [출처](#sources). 과거 도시 스키마의 필드는 보존 자료를 읽는 계약으로 유지하되 새 검색 응답에 그대로 강제하지 않는다.
- D3 자료 확대·과거 비교 순서·평가 기준: [평가](#evaluation). 과거 완료 기록은 당시 기록으로만 읽는다.
- 사용자 증거·제외·철회·이관, 저장·전송·삭제 보호, 실제 노출·반응 의미는 기존 원문을 유지한다. 검색 실험에도 기존 외부 전송·최소 수집 원칙을 적용한다.

기존 설계 문서 전체를 다시 활성화하는 것은 아니다. 기억 항목처럼 위에서 명시한 절만 유지한다. 다른 주제의 압축본을 채택하려면 원문과 항목별로 대조해 누락·변경을 확인한 뒤 별도로 결정한다.

## 한 주제에 하나의 원문

- 현재 적용되는 각 정책·필드·평가 규칙·화면 동작은 담당 문서 한 곳에만 쓴다. 다른 문서에는 설명을 복제하지 않고 상대 경로 링크를 둔다.
- 상위 문서는 찾아가는 입구다. 하위 정책을 요약해서 또 관리하지 않는다. 링크의 역할 설명은 허용하되 수치·예외·규칙을 다시 쓰지 않는다.
- TODO에는 작업 상태·산출물·실제 검증 기록만 둔다. 정책·실험 결과 본문은 담당 원문으로 연결한다.
- 코드/JSON이 원문인 목록·ID·필드는 문서에 전수 복사하지 않는다. 문서는 의미와 사용 범위만 설명한다.
- 과거 문서는 당시 기록이다. 위에서 명시적으로 재사용한 주제·절만 현재 적용한다. 현재 문서와의 역사적 중복은 허용하지만 서로 다른 버전을 동시에 적용하지 않는다.
- `graphify-out/`은 생성된 탐색 자료이며 정책 원문이 아니다. 에이전트 작업 규칙은 루트 `AGENTS.md`와 `CLAUDE.md`를 따른다.

## 설계가 바뀔 때

1. 바뀐 주제만 새 버전 파일에 작성한다. 예: `v3/recommendation.md`. 바뀌지 않은 문서는 복사하지 않는다.
2. 새 버전의 목차에는 새 문서와 재사용하는 이전 버전 문서의 정확한 경로를 명시한다. 기존 버전 목차는 바꾸지 않는다.
3. 이 문서의 버전 목록에 날짜·상태·목차 링크를 추가하고 현재 버전을 지정한다. 변경된 주제의 고정 진입 링크를 새 원문으로 바꾼다.
4. 새 원문에 이전 원문 링크·변경 이유·적용 범위·미정 사항을 적는다. 과거 결정·사전 평가 기준·결과를 새 결론에 맞게 고치지 않는다.
5. 오탈자·끊어진 링크 수정은 같은 파일에서 가능하다. 정책·범위·판정 기준 변경은 새 버전으로 남긴다.

한 설계 변경 때문에 모든 화면·TODO·루트 README의 규칙을 수정하지 않는다. 여러 주제를 동시에 바꾸는 결정일 때만 해당 담당 문서를 각각 새로 만든다. 제품 목표·범위 자체를 바꿀 때는 루트 README도 새 내용으로 갱신하고 이전 본문을 버전 기록으로 보존한다.

## 실험 기록

[입력·실행 파일 목차](../data/exploration/README.md)는 실험 파일의 위치를 담당한다. 호출이 시작된 입력·사전 기준·원본 응답은 수정하지 않는다. 새 실험은 새 계획·실행 디렉터리로, 집계·정정은 별도 결과 문서로 남기고 계획과 연결한다. 미완료 검수를 완료로 표시하지 않는다.
