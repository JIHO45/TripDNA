# TripDNA 세부 스펙

기준일: 2026-10-06. 제품 목표·범위의 상위 문서는 [루트 README](../README.md)다.
새 추천의 기준은 [취향·도시·LLM 추천 설계 v2](recommendation/architecture.md)다.
이 폴더는 **구현 목표**를 정의하며, 문서 수정이 앱 구현 완료를 뜻하지 않는다.

현재 우선 작업은 [도시 목록 대 프로필 탐색 실험](evaluation/profile-exploration.md)과 그에 이어지는 [추천 지침 비교 실험](evaluation/guideline-comparison.md)이다. D3 사람 검수·자료 확대는 중단했으며 기존 v3 자료는 보존한다. 다음 작업과 진행 상태는 [전환 체크리스트](TODO.md)에서 확인한다. 항목별 선행 조건·완료 기준·결정 시점을 관리한다.

## 폴더 구조

- `recommendation/`: 추천 구조·직접 증거·설명·경험 어휘.
- `evaluation/`: 비교 실험과 계측.
- `data/`: 저장·전송·개인정보 경계와 도시 자료 파일 형식. 실제 자료 파일은 루트 `data/cities/`에 둔다.
- `screens/`: 화면 동작과 질문 설계.

중복된 폴더 단계와 문서 번호를 없애고 내용 중심의 파일명을 사용한다.

## 읽는 순서

1. [핵심 설계](recommendation/architecture.md): 합의한 방향, 기억·제외 정책, LLM 책임, 미정 사항.
2. [증거와 이관](recommendation/preference-evidence.md): 무엇을 취향으로 해석하고 기존 기록을 어떻게 보존할지.
3. [비교 실험](evaluation/offline-evaluation.md): 같은 도시 자료로 선택 품질·설명·비용을 검증하는 절차.
4. [데이터 경계](data/storage-and-privacy.md): 로컬 저장, LLM 전송, 삭제와 캐시.
5. [화면별 동작](screens/README.md): 온보딩·기억 편집·추천·여행·공유.

## 적용 상태

- 현행 앱: SwiftData·로컬 사진 저장, 국가 프로필·5축 추천. 로그인 없이 이용 가능.
- 새 목표: 도시 중심, 직접 선호·이번 여행·제외를 구분하고 검수 DB를 근거로 LLM이 추천.
- 최대 3개 후보, 초기 질문 구성 등은 핵심 설계의 **기본안**이다. 문구·화면까지 모두 확정한 것은 아니다.
- 주요 도시 약 100곳을 목표로, 초기 15~20곳은 도시 중심에 자연 거점 최소 4곳을 포함한다. 자체 검수부터 시작하고 재확인 주기는 정보별 3·6·12개월이다.
- 첫 외부 LLM 파일럿 상한은 US$10이며, B1부터 수정·검증하고 출시 여부는 도시·LLM 평가 뒤 결정한다. D2 조사 후보는 확정했고 첫 공개 도시 목록·모델·출시 운영 예산은 검수와 실험 결과로 결정한다.
- 도시 자료는 현재 JSON 파일로 작성·검수·실험한다. “검수 DB”는 자료 카탈로그를 뜻한다. 운영 배포·갱신 방식과 서버 DB 필요 여부·제품은 미정이며 Firebase 제외는 유지한다.
- LLM 채택 시 호출 서버 경유가 필요하다. 사용자 전체의 행동 집계는 출시 후 별도로 판단한다.

## 정리 이력

2026-10-06에 사용자 로컬 저장·공용 도시 JSON·LLM 호출 서버의 경계를 맞췄다. DB 제품 선택이나 서버 구현 완료로 취급하지 않으며 2026-09-30의 Firebase 제외를 유지한다.

2026-09-30에 폴더의 36개 파일(문서·PDF·규칙·스크립트·CSV·JSON)을 점검했다.

- 중복된 3.0 최종본·모델 본문·클래스 다이어그램은 삭제하고 핵심 설계로 통합했다.
- 구독 수익·LLM 표현 전용을 전제로 한 옛 출시 판단 문서와 PDF를 삭제했다.
- 미사용 Firebase 규칙·Firestore 설계는 삭제하고 데이터 경계 문서로 대체했다.
- 중복 온보딩 플로우·옛 UI 생성 프롬프트는 삭제하고 화면 스펙·질문 설계에 통합했다.
- 국가 성격을 수치화하는 커뮤니티 게시 초안 두 개는 삭제했다.
- 현재 CSV 열을 덮어쓰고 독립 검수 없이 PASS를 출력하던 진단 도구·보고서는 삭제했다.
- 국가 CSV 두 개·중복 시드 JSON 두 개·생성 도구·안내 문서를 삭제했다. 과거 비교에는 해당 Git 버전과 앱 번들 자료를 사용한다. 앱이 읽는 번들 리소스는 구현 이관 전까지 유지한다.
- 기존 EMA 실험·3슬롯·Firestore 파일명은 새 역할에 맞게 변경했다. 삭제한 자료의 이력은 Git에서 확인한다.

문서 우선순위 선언을 각 파일에서 다시 만들지 않는다. 세부 문서는 핵심 설계의 정책을 참조하고 해당 화면·검증의 차이만 기술한다.
