# 도시 등급·핵심 경험 제작 형식

2026-10-17: 추가 비교 실험을 멈추고 기존 20곳을 새 등급 정의로 재판정한 뒤 후보 전체의 자료 작성을 재개했다. 사용자는 기존 20곳을 보존하는 **103곳(원본 100 + 보충 3)**을 선택했다. 이 문서는 새 자료의 현재 계약이며 [예전 상세 프로필 형식](city-format.md)은 실험 당시 기록으로 보존한다.

원문은 [catalog.json](../../data/destinations/catalog.json)이다. 후보 목록은 [destination-candidates.json](../../data/planning/destination-candidates.json), 등급의 의미와 자연스러운 여행 범위는 [추천 구조](../recommendation/README.md#도시-등급)를 따른다. 이 파일은 제작·검수용이고 앱 연결은 하지 않았다.

## 파일 계약

- `schema_version`, `updated_on`, `status`, `release_ready`: 형식 버전·작성일·자료 상태. 현재 버전 1은 초안 전용이며 `draft`, `false`만 허용한다. 사람이 검수한 출시 자료를 만드는 계약은 해당 검수 완료 시 별도 확정한다.
- `levels`: `none`, `if_there`, `make_time`, `choose` 순서의 이름형 등급. 뜻은 추천 구조를 따른다. `none`은 작성자가 추천 근거를 찾지 못했다는 뜻이며, 경험의 부재나 충분한 조사가 끝났다는 뜻이 아니다.
- `concepts`: 세부 29개와 상위 컨셉의 연결. 현재 기준 파일의 어휘를 그대로 담으며 검사기가 일치를 확인한다. 상위 등급은 중복 저장하지 않는다.
- `cities`: 앱 후보 ID를 키로 한 도시 자료. `candidate_id`로 선정 목록에 연결한다. 푸껫은 기존 초안 ID `th-phuket-island`를 보존하고 후보 원본 `th-phuket`에 연결한다. ID의 island라는 글자가 실제 범위를 보장하지 않으므로 `scope`를 읽는다.
- 도시의 `name`, `country`, `scope`, `nearby`: 식별과 포함 범위, 별도 목적지로 제외한 근교. 새 83곳의 제외 범위는 `scope`에도 명시한다. 근교를 넣어 등급을 자동 합산하지 않는다. 목록 집계 범위와 작성 범위가 같다고 가정하지 않는다.
- `grades`: 세부 29개 모두에 이름형 등급. `core`: `make_time` 이상인 세부마다 구체적 경험 한두 문장. 검수자가 등급 근거로 읽는다. 2026-10-25 결정으로 MVP에서는 LLM 설명 입력에 쓰지 않는다(출시 후 재검토). 개인화 설명을 저장하지 않는다. 하위 두 등급에는 상위 경험 문장을 임의 생성하지 않는다.
- `season`: 행사·운영 가능한 월의 합집합. `season_basis`에 출처·적용 연도·한계를 연결한다. 특정 연도만 대조했으면 그 연도를 보존한다. `year: null`은 반복 월 안내를 읽었다는 뜻이며 특정 연도의 개최 확인이 아니다.
- `season_unverified`: 운영 월을 확인하지 못한 세부. **시기 조건 충족으로 계산할 수 없다.** 두 시즌 필드에 동시에 둘 수 없고, 미기재를 확인 완료로 읽지 않는다. 초안에서는 행사·스키·수상·등산·동물 관찰·테마파크처럼 운영 시기가 영향을 줄 수 있는 비어 있지 않은 세부를 보수적으로 여기에 둔다. 연중 운영 근거를 검수한 뒤에만 해제한다. 날씨·개화 시기는 운영 월에 넣지 않는다.
- `previous_season`: 기존 20곳의 이전 월 값. 조사 단서로만 보존하며 필터·설명 입력에 사용할 수 없다. 기존 월 값을 그대로 검수 완료로 이관하지 않았다. 이전 core 전체의 월 합집합이 확인되지 않으면 새 `season`에 넣지 않는다.
- `sources`, 도시별 `evidence`: 실제 조회한 URL·조회일·대조 범위·조회 방식. `search_excerpt`는 검색 결과 발췌 확인, `page_read`는 페이지 본문 조회다. 검색 결과 확인을 원문 전수 검수로 표시하지 않는다. 해당 세부에 참조가 없으면 모델 지식 초안이며 외부 확인이 안 된 상태다. 출처가 있어도 등급 자체의 적정성·사람 승인을 증명하지 않는다.
- `provenance`, `grade_note`, `reassessment`: 작성 이력과 등급 판정. 기존 20곳은 29칸의 재판정 범위와 변경 전후·이유를 기록한다. 신규 83곳의 사후 등급 보정은 `revisions`에 날짜·세부·전후·이유를 순서대로 남기며, 마지막 값이 현재 등급과 같아야 한다. 변경하지 않은 칸도 잠정 유지이며 사실 검수 완료가 아니다.
- `review`, `human_review`, `review_flags`: 등급·범위·경험·시즌별 검수 대기 상태와 구체적 쟁점. 현재 전부 `pending`, 사람 검수는 `null`이다. 일부 출처 대조를 도시 전체 승인으로 올리지 않는다.

## 검수 순서와 완료 경계

등급 판정 기준·기준표·재판정과 도시 추가 순서는 [등급 판정 절차](destination-grading.md)를 따른다. 아래 쟁점은 그 절차의 사람 검수 단계에서 다룬다.

**초안 작성 완료**는 후보 ID 103개, 2,987개 등급, 상위 등급의 core, 범위·시즌 상태가 채워지고 구조 검사에 통과한 상태다. 낮은 등급과 `none`의 과소평가도 후속 검수 대상이다. 근거가 없는 칸을 도시 간 상대 순위의 확정값으로 취급하지 않는다.

**출시용 검수 완료**는 별도다. 먼저 아래 쟁점을 다루고, 나머지 `make_time`/`choose` 경계와 시즌을 검수한다. 도시를 출시 승인하려면 범위·등급 근거·시즌을 사람 검수 기록과 연결하고 허용된 자료만 배포하는 앱 경로도 확인해야 한다. 이번 작업은 그 상태가 아니다.

1. 메카·메디나: 종교 시설의 접근 자격·허가·허용된 관람 범위. 일반 관광 가능으로 표시하지 않는다.
2. 무을라·파타야-촌부리·덴파사르·로도스·팔마: 도시와 광역 지역의 혼동. 무을라는 2026-11-02 사용자 결정으로 멘테셰에서 주 전체(보드룸·마르마리스·페티예 등 해안 지구 포함)로 넓히고 12칸을 재판정했다(`revisions`). 지구 간 이동·당일 접근과 새 core의 사실은 아직 대조 전이다. 후보 원본의 집계 범위까지 확인한 것은 아니다.
3. 기존 20곳의 범위 경계: 리스본의 카스카이스, 케이프타운의 스텔렌보스, 멕시코시티의 테오티우아칸은 별도 목적지로 분리했다. 각각 수상·술·유적 등급의 근거가 달라진다. 멕시코시티 유적 상위 등급의 유지도 사람 재판정 대상이다. 푸껫 당일 섬 투어와 케언스 리프의 포함은 기존 작성 범위를 잠정 보존했으므로 당일 접근을 검수해야 한다.
4. 신규 후보 진입 경계: 방콕 숙소 휴식·요리 교실, 밴쿠버 박물관, 푸껫 식당, 교토 산길, 싱가포르 골목, 두바이 옛 거리, 타이베이 건축 등. 주요 일정 길이나 시설 수 대신 일부러 시간을 낼 경험인지 판단한다.
5. `choose` 경계: 파리 역사·시드니 건축의 승급, 방콕 교류·케이프타운 와인의 하향. 여행지를 선택할 정도인지 핵심 경험과 함께 판단한다. 나머지 도시도 같은 기준을 적용한다.
6. 시즌: 싱가포르 F1, 퀸스타운 스키, 밴쿠버 고래·스키, 멕시코시티·델리 축제의 예전 월 값은 재검수 대상으로 남겼다. 교토 대표 축제와 뮌헨 옥토버페스트만 새 월 근거를 연결했으며 이 역시 사람 승인이 아니다. 다른 모든 이벤트의 월·개최일은 확인 전이다.
7. 신규 83곳의 깊이: 1차 초안이 기존 20곳보다 낮게 매겨졌다. 런던·로마 등 19곳의 make_time 경계를 보정했으나(`revisions`) 다른 도시와 none ↔ if_there 경계는 같은 기준으로 다시 비교해야 한다. 등급이 순위에 쓰이므로 이 차이는 기존 20곳을 유리하게 만든다.
8. 교류: 일반 호스텔과 투어 동승만으로 상위 등급을 준 칸을 낮췄다. 푸껫의 여행자 교류 `make_time` 유지 근거도 비교 검수해야 한다. `locals` 상위 단계는 정의가 없어 현재 자료에 두지 않는다.

핵심 경험은 검수 근거다(MVP에서는 LLM 설명 입력에 쓰지 않는다). 경험 문장이 많아서 더 높은 등급을 주거나, 검색으로 장소 존재를 확인했다는 이유만으로 `choose`를 확정하지 않는다. 기후·비행시간·비용 데이터는 이번 작업에 추가하지 않는다. 추가 비교 실험과 실제 LLM API 호출도 하지 않는다.

## 자동 검사

```sh
python3 scripts/check_destination_draft.py
python3 scripts/test_destination_draft.py
python3 scripts/check_destination_draft.py --release
```

마지막 명령은 **현재 반드시 종료 코드 1로 거부**한다. 실제 앱의 배포 파이프라인에 연결된 검사가 아니라 제작용 검사다. 상태 플래그를 바꾸는 것만으로 통과할 수 없다. 누락·중복 JSON 키·ID 연결·29개 세부·등급 이름·core 누락·월 범위와 충돌·출처 참조·변경 기록을 검사한다. 사실과 추천 품질은 검사하지 않는다. 기존 실험 자료와 검사기는 수정하지 않았다.
