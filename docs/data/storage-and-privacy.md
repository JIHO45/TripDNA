# 저장·전송·도시 자료의 경계

2026-10-08 정합성 보완: 도시별 평가 원문 전송, 로컬 추천 캐시, 목록 밖 도시 요청의 서버 보관을 반영했다.
상태: 새 구조의 논리적 데이터 계약. 서버 제품 선택은 추천 구조를 따르며 새 Swift 저장 타입과 구현은 미완료다.
기준: [사용자 기억](../recommendation/memory.md), [추천 구조](../recommendation/README.md).

## 이관할 기존 저장소 (구현 현황)

- 여행·평가·랭킹·피드백·프로필·이벤트: SwiftData.
- 사진: LocalPhotoStore의 기기 내 파일.
- 국가·태그: 앱 번들 JSON. 기존 앱 실행을 위한 자료이며 새 도시 DB로 사용하지 않는다.
- 기기 간 동기화·서버 복구는 제공하지 않는다. Apple 로그인만으로 이 기능이 생기지 않는다.
- 현행 저장소 구현은 [SwiftDataStore](../../TripDNA/Infrastructure/SwiftDataStore.swift)를 참조한다.
- 폐기한 Firestore 컬렉션과 규칙을 다시 배포하지 않는다.

## 저장 방식과 도입 단계

- 사용자 기록: 현행 SwiftData·LocalPhotoStore의 기기 내 저장을 유지한다. 새 직접 증거·조건·제외 등의 로컬 저장 구조와 이관은 I1·I2에서 구현한다.
- 공용 도시 자료: 현재 `data/cities/`의 JSON 파일로 작성·검수·버전 관리하고 PC 비교 실험에서 읽는다. “도시 DB”·“검수한 DB”는 이 카탈로그의 논리적 이름이다.
- 앱 운영용 도시 자료의 배포, 외부 DB, Firebase 사용 범위: 2026-10-07에 정했다. [추천 구조의 추가 결정](../recommendation/README.md#2026-10-07-추가-결정-구독-자료-배포-저장)을 따른다.
- LLM 호출 서버: 키 보호·요청 검증·호출/비용 제한을 위한 채택 후 요구사항이다. 서버 경유를 사용자 기록의 클라우드 저장·동기화나 행동 집계 도입으로 해석하지 않는다.

## 새 구조에서 구분할 기록

- 직접 증거: 출처 ID, 원문/선택, 범위, 시점, 활성/철회, 수정 연결.
- 이번 여행: 지속되는 ID, 선택 입력 조건, 변경 버전.
- 방문: 나라, 확인된 도시 ID 또는 미확인 원문, 날짜 정밀도, 사용자 확인 여부.
- 제외: 대상 종류/ID, 이번 여행 ID 또는 계속 적용, 이유, 생성/해제 시점.
- 북마크: 도시 ID와 저장 시점. 제외와 독립이며 저장을 제외 해제로 해석하지 않는다.
- 도시별 평가: 여행·도시 식별 정도, 별점, 좋았던 점·아쉬웠던 점의 메모 원문, 수정·삭제와 버전. 도시 미상·기존 여행 전체 평가는 임의 도시로 배분하지 않는다.
- 추천: 당시 입력/자료/프롬프트/모델 버전, 순서, 도시 ID, 개인화 설명과 근거, 반영한 기억과 원본 평가 연결, 설명이 의존하는 조건. 로컬 결과 캐시이며 공용 도시 자료나 영구 선호로 자동 승격하지 않는다.
- 제외 예외: 이번 요청에서 명시한 대상과 이번 여행 범위를 원래 제외 설정과 구분한다.
- 노출·반응: 실제 보여준 추천 ID·도시·위치와 행동을 연결한다.

캐시를 원본 사용자 진술의 유일한 저장처로 삼지 않는다. 평가 수정/삭제와 기억 철회는 관련 파생 결과를 무효화한다.

## 도시와 근거

아래는 보존한 `data/cities/` 자료를 읽는 계약이다. 검색으로 얻은 사실의 허용 기준은 [출처](../recommendation/sources.md)를 따르며 이 필드를 검색 응답에 그대로 강제하지 않는다.

파일 필드·상태·만료 판정은 [도시 자료 파일 형식](city-format.md)에 정의한다. [가상 예제](../../data/cities/example.json)는 형식 확인용이며 실제 검수 카탈로그가 아니다.

도시 레코드에는 안정적 ID, 이름/별칭, 나라, 적용 지역, 검수 상태, 자료 버전을 둔다.
경험별로 장소 ID·추천 범위 안/밖/미확인 관계, 활동, 추천을 바꾸는 예약/계절/접근 제약과 근거 ID를 연결한다. 배편·숙박 필요 여부는 근거가 있는 값과 미확인을 구분한다. 버스 요금·배차·상세 시간표는 필수 수집 대상이 아니며 이미 조사한 자료는 `detail_only`로 보존할 수 있다.
근거에는 주장, 출처 URL, 확인일, 적용 지역/시기, 검수 상태가 필요하다.
자료에는 검수 종류(자체/독립), 검수자, 자료 버전과 검수일을 남긴다. 우선 자체 검수로 시작하며 독립 검수는 인력을 확보한 뒤 적용한다.

- 비용은 통화·시점·포함 항목·1인/전체 범위를 함께 둔다.
- 위치가 가까워도 이동 조건을 확인하지 않은 근교를 같은 체험권으로 단정하지 않는다.
- 추천용 짧은 요약은 상세 근거로 추적 가능해야 한다.
- 미검수 자료와 기존 국가 축은 새 도시 사실의 근거가 아니다.
- 직접 출처 검수 없이 “안전”, “예산 충족”, “예약 가능” 배지를 만들지 않는다.
- 가격·운영·예약은 최대 3개월, 교통·접근·계절 제약은 최대 6개월, 위치·상설 경험은 최대 12개월마다 재확인한다. 더 짧은 공식 유효기간이나 확인된 변경을 우선한다. 기한 지난 주장은 근거에서 보류하고 관련 필수 조건은 미확인으로 처리한다.

## LLM 전송과 서버

LLM을 앱에 채택할 때, 앱의 영속 사용자 기록과 별개로 키 보호·요청 검증·호출 제한용 서버를 구현한다. 현재 앱에 구현된 서버 기능은 아니다.
추천 입력의 원문은 [흐름](../recommendation/README.md#흐름)과 [지난 여행의 기억](../recommendation/README.md#지난-여행의-기억)에 있다. 최근 도시별 별점과 좋았던 점·아쉬웠던 점 메모 원문도 전송 대상이다. 원문 평가와 사용자가 직접 확정한 평소 선호를 구분한다. 전송할 평가의 수·길이·선택 기준은 미정이다.
원본 사진·EXIF·전체 위치 이력·불필요한 계정 식별자는 보내지 않는다.
첫 전송 전에 메모 원문과 확인된 방문 도시가 추천을 위해 외부 모델에 전달됨을 안내하고 정해진 동의 절차를 적용한다. 동의하지 않으면 전송하지 않으며 로컬 기록과 유효한 기존 결과는 이용할 수 있다.

서버는 모델 제안이 허용된 후보·근거를 사용하는지 검증하고, 앱은 저장 직전 이번 여행 예외를 반영한 최신 제외·입력·평가 버전을 다시 확인한다.
임의 DB 경로나 도구 호출을 모델 출력으로 실행하지 않는다. API 키는 앱에 넣지 않는다.
인증·남용 방지 제품 선택은 [서버 결정](../recommendation/README.md#2026-10-07-추가-결정-구독-자료-배포-저장)을 따른다. 세부 운영은 미정이며 Apple 로그인을 필수로 만들지 않는다.

LLM 요청 처리와 전체 사용자 행동 집계는 다르다. 요청 본문을 집계 학습 데이터로 자동 보관하지 않는다.
제공자 보관 설정, 요청 로그 최소화, 보관 기간·삭제 절차·전송 안내를 출시 전에 확정한다.

## 목록 밖 도시 요청과 서버 보관

2026-10-08에 사용 횟수 외에 요청된 목록 밖 도시 이름의 서버 기록을 추가했다. 여행 원장·평가 메모·도시 카탈로그·검색 결과를 공용 DB에 저장하는 결정은 아니다. 도시 자료는 기존 번들 배포를 유지한다.

- 목적은 도시 추가 수요의 확인이다. 이름 언급, 회피 요청, 실제 방문 희망을 구분하는 판정·집계 규칙은 구현 전에 정한다.
- 기록 항목, 이름 정규화·동명 도시 처리, 중복 집계 방지, 사용자 연결 여부, 보관 기간·삭제·동의 시점은 미정이다. 도시 요청 기록을 이유로 자유문장 전체나 평가 메모를 자동 보관하지 않는다.
- 집계·검토 기준은 [추천 구조의 미정 목록](../recommendation/README.md#미정)에 있다. 요청 누적을 도시 자료의 검수 완료나 자동 공개로 해석하지 않는다.
- LLM 전송 동의와 도시 요청 집계의 목적·보관 범위를 구분해 안내한다. 필요한 동의·보관·삭제 계약을 정하기 전 실제 수집을 시작하지 않는다.

## 삭제·복구·실패

- 사용자 삭제는 원본과 관련 파생 기억·캐시·노출 스냅샷의 연결까지 검토한다.
- 서버 보관이 생기면 기기 삭제만으로 끝났다고 표시하지 않는다. 실제 적용 범위를 알린다.
- 저장 실패 시 원본 입력을 보존하고 재시도할 수 있어야 한다.
- 취향/조건이 바뀐 요청의 늦은 응답은 폐기한다.
- 앱 재시작은 새 여행이 아니다. 이번 여행 제외가 사라지지 않아야 한다.
- 이관은 [기존 데이터 이관](../recommendation/memory.md#기존-데이터-이관)을 따른다.
