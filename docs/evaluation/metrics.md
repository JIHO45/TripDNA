# 추천 품질·노출·반응 계측

2026-10-08 정합성 보완: 도시별 평가·메모 참조·등록 분기·로컬 재필터·호출 비용과 차감을 구분했다.
상태: 현행 기록과 새 구조의 추가 요구를 구분한다.
기준: [추천 구조](../recommendation/README.md), [평가](README.md).

## 현행 기록

[RecommendationExposure](../../TripDNA/Recommendation/RecommendationExposure.swift)는
도시 카드가 절반 이상 보인 때 추천 결과(id)별 도시당 한 번 로컬에 기록한다(2026-10-31부터, 이전에는 나라 카드).
계산만 한 후보는 노출이 아니다. 결과 id, 도시 id, 위치(추천 카드·추가 확인 필요와 순서), 자료·프롬프트·순위·모델 버전, 컨셉·예산·제외 조건을 남긴다. 요청 문장과 메모는 넣지 않는다.
아직 수집하지 않는 조건은 미수집으로 남긴다. 이 기록을 사용자 집계 서버로 보내는 기능은 없다.

## 도시 모델에서 필요한 기록

아래는 필드와 발생 의미의 요구사항이며, 모두 구현된 이벤트 이름 목록이 아니다.

- 추천 요청/결과: 요청 ID, 입력 버전, 주·부 컨셉, 후보 집합/순서, 모델·프롬프트·도시 자료 버전, 생성/캐시/로컬 재필터 구분. 추천 카드·등록 초안·생각 중인 곳을 구분한다.
- 실제 노출: 결과 ID, 도시 ID, 화면과 위치, 시각. 현행 노출 판정 원칙을 재사용한다.
- 반응: 결과·도시·노출 연결, 북마크/교체/제외/해제, 적용 범위.
- 기억 변경: 출처, 이번 여행/평소 구분, 확인/자동 저장/되돌리기 여부.
- 생성 처리: 성공/검증 탈락/실패, 재시도 수, 입력·출력 토큰, 실제 비용, 지연, 추천 횟수 차감 여부와 사유. 실제 API 호출과 사용자 차감 횟수를 별도로 센다.
- 여행 평가: 여행·도시의 확인 정도, 도시별 별점과 메모의 수정·삭제. 원문은 평가 저장소에 두고 이벤트에 복제하지 않는다.
- 기억 반영: 추천 결과와 참조한 평가 버전의 연결. 모델이 반영했다고 보고한 것과 실제 선택·설명에서 확인된 반영을 같은 품질 지표로 간주하지 않는다.
- 목록 밖 도시 수요: [서버 기록 계약](../data/storage-and-privacy.md#목록-밖-도시-요청과-서버-보관)에 따라 도입한다. 아직 전 사용자 수요를 집계 중인 것은 아니다.
- 공유: 생성과 실제 내보내기 성공을 구분한다. 시스템 공유 시트 취소를 공유 성공으로 세지 않는다.

시작 시각·후보 조건 등 필요한 문맥을 연결하되 원문 개인정보를 모든 이벤트에 복제하지 않는다.
상세 열람·저장·미반응을 여행 만족도의 정답으로 바꾸지 않는다.
공유용 익명 통계라고 불러도 식별 가능한 연결 키가 남으면 익명이라고 보장하지 않는다.

## 보는 지표

- 첫 추천 도달률·시간, 질문 건너뛰기와 추가 입력 부담.
- [비교 실험](offline-evaluation.md)의 설명을 숨긴 후보 적합성과 선호 순서.
- 근거 오류·제외 위반·조건 위반·기억 해석 오류 및 되돌리기.
- 비용·지연·실패율·재시도율·캐시 재사용.
- 추천 저장/상세 열람은 보조 행동 지표. 만족이나 추천 정확도의 대체 지표가 아니다.
- 공유와 다음 여행 계획 시 재사용. 제휴 확정 예약은 제휴사에서 확인하며 클릭과 구분한다.

실제 노출 도시만 반응률의 분모에 넣고 카드 위치·방문 여부·입력량 차이를 함께 본다.
미노출 후보를 싫어한 것으로 학습하지 않는다. 초기에 전국 사용자 대시보드가 있다고 가정하지 않는다.

## 실험과 보관

PC 비교 실험은 별도 로그를 쓴다. 실제 앱 노출과 합치지 않는다.
실험에서 탈락한 응답도 실패/탈락으로 세고 비용에 포함한다.
보관 기간·용량·삭제·외부 전송은 [데이터 경계](../data/storage-and-privacy.md)를 따른다.
파생 기억과 노출 스냅샷에 삭제한 정보가 남는 문제를 함께 처리한다.
