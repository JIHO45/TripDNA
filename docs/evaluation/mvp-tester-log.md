# MVP 사용 기록 양식

2026-10-25 작성(사용자 결정). MVP에서는 비교 실험 대신 Joe와 소수의 테스터가 직접 추천을 받아 보며 문제를 고친다([추천 구조](../recommendation/README.md#2026-10-17-결정-조건-판정과-순위)의 핵심 경험 절). 이 문서는 그 기록 방식이다. 앱 연결 전이라 아직 기록은 없다.

## 기록 원칙

- **도시 문제와 설명 문제를 나눠 적는다.** 추천된 도시가 이상하면 등급·순위 로직을, 도시는 맞는데 설명이 이상하면 프롬프트(지침)를 고친다. 둘을 모두 지침 조정으로 해결하려 하지 않는다.
- **같은 조건으로 다시 받아 볼 수 있게 적는다.** 요청 문장, 티어, 조건, 날짜를 그대로 남긴다.
- **한 번 나온 문제보다 반복되는 문제를 고친다.** 한 사례만 보고 등급표나 지침을 바꾸지 않는다. 같은 유형이 여러 번 나오면 고친다.
- 개인 정보와 지난 여행 메모 원문은 테스터의 동의 없이 기록에 옮기지 않는다.

## 한 건의 기록

| 항목 | 적을 내용 |
| --- | --- |
| 날짜·기록자 | 2026-11-01, Joe |
| 입력 | 요청 문장, 티어(주·부 컨셉), 시기·예산·기간 조건 |
| 받은 도시 | 3곳과 순서 |
| 도시 문제 | 없음 / 있음. 있으면 어느 도시가 왜 이상한지, 기대한 도시 |
| 설명 문제 | 없음 / 있음. 있으면 틀린 사실, 과장, 요청과 무관한 내용 등 유형과 문장 |
| 기타 | 속도, 오류, 그 밖의 메모 |

## 모아서 볼 것

- **도시 문제 묶음:** 같은 세부나 같은 도시에서 반복되는지 본다. 반복되면 [등급 판정 절차](../data/destination-grading.md)에 따라 해당 세부를 다시 판정한다.
- **설명 문제 묶음:** 유형별로 센다. 틀린 사실(날짜·가격·운영 정보)이 반복되면 지침에서 그 주장을 금지하거나 줄인다. 반복되는 도시가 있으면 그 도시의 핵심 경험 문장을 다시 넣을 후보로 적는다.
- 기록 수, 테스터 수, 언제 지침 조정을 마칠지는 정하지 않았다.
