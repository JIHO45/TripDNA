# 도시·LLM 추천 비교 실험

상태: 실행 전 설계. 기준: [핵심 설계](../recommendation/architecture.md) 11·12절.
기존 EMA 온라인 A/B·강제 탐험 슬롯 실험을 대체한다. 실험 결과나 경쟁 우위는 아직 없다.

## 먼저 진행하는 탐색 실험

2026-10-06 합의에 따라 D3 사람 검수·자료 확대를 중단하고 [목록 대 프로필 탐색 실험](profile-exploration.md)을 먼저 진행한다. 동일 후보 20곳·합성 사례 6개로 추천과 상세를 비교하며 초안 입력을 허용한다. 아래 실제 사용자 선택 품질 실험·E7과 결과를 합산하지 않는다. 기존 3곳의 엄격한 자료는 크기와 사용 가능한 근거 수만 기록한다.

## 사실 판정과 자료 포함 여부

- 틀린 사실: 공식 출처와 대조해 오류가 확인된 주장. 자료에 포함돼 있어도 틀릴 수 있다.
- 자료 밖 사실: 제공한 프로필이 뒷받침하지 않는 주장. 맞음/틀림/확인 불가는 별도 판정한다. 목록만 주는 탐색 방식 A에서는 이 비율을 N/A로 둔다.
- 확인 불가: 대조 근거 부족·출처 접근 실패·미검수. 맞음이나 틀림으로 임의 처리하지 않는다.
- 근거 정책 위반: 미확인 변동·안전 정보 또는 필수 조건 충족을 단정한 경우. 참/거짓 판정과 별도로 기록한다. 사용자 제외·허용 ID 위반도 별도다.

모든 사실 오류를 평가하며 “자료 밖”이라는 이유만으로 허위 사실로 세지 않는다. 실제 사용자용 출력의 근거 허용 범위는 탐색 결과 뒤 최종 결정한다. 기존 엄격한 계약의 ID 검사는 문장 진실성 보장이 아니다.

## 비교할 질문

- 선택 능력: 같은 사용자 사실·도시 후보·검수 자료·조건으로 단순 규칙, 고품질 LLM, 저가 LLM을 비교한다.
- 전체 경험: 현재 앱, 알려진 추론 오류를 고친 앱, 새 도시 추천을 비교한다. 입력 정보량과 국가/도시 단위 차이를 명시한다.
- 더 많은 질문의 효과와 모델 변경의 효과를 한 실험 결과로 뭉뚱그리지 않는다.
- 인기순을 기준선으로 추가하려면 출처·연도·집계 기준을 고정한다. 편집 인기도를 실제 관광객 순위라고 부르지 않는다.

## 자료와 사례

도시별 형식은 [데이터 경계](../data/storage-and-privacy.md)를 따른다.
주요 도시 약 100곳이 목표안이다. 그중 15~20곳으로 형식·파일럿을 확인하고 아래 확대 관문을 통과한 뒤 100곳으로 검증한다.

사용자 사례는 평소 선호의 원문, 좋고 싫었던 경험/이유, 이번 조건, 방문 이력, 제외와 미입력을 구분한다.
합성 사례로 구현 오류부터 찾고, 동의받은 실제 사례로 적합성을 평가한다.
일본·미국·캐나다를 등록한 즉흥 선호자와 핵심 설계의 필수 시나리오를 포함한다.

PC 스크립트로 시작하고 도시 자료는 `data/cities/`의 JSON 파일에서 읽는다. 앱 변경·운영 서버·DB 서비스 도입은 이 실험의 선행 조건이 아니다.
실제 자료를 외부 API로 보내기 전 전송 범위를 알리고 필요한 동의를 받는다.

## 평가 순서

1. 프롬프트 개발용 사례와 최종 평가용 사례를 사용자 단위로 나눈다.
2. 조건·후보·자료 버전과 호출 설정을 고정하고 각 방식의 추천을 수집한다.
3. 모델 이름과 생성 설명을 숨긴 채 동일 형식의 후보 자료를 보여준다. 겹치는 후보는 한 번만 평가한다.
4. 해당 사용자가 실제로 고려할 만한지와 선호 순서를 평가한다.
5. 설명을 별도로 공개하고 원문 근거·조건 위반·취향 단정·도움 정도를 검수한다.
6. 같은 입력 반복, 후보 순서 변경, 핵심 조건 변경을 각각 시험한다.
7. 비용·지연·실패·재시도·검증 탈락까지 함께 집계한다.

미방문 도시는 오답이 아니다. 과거 평가를 가리는 실험에서는 그 평가·태그·비교 관계·순위와 파생 요약을 입력에서 제거한다. 나머지 여행에 붙은 비교·순위도 가린 답을 역으로 드러내지 않게 재구성한다.
같은 순위 유지가 정답은 아니며, 사용자가 비슷하게 평가한 후보 사이의 교환은 별도로 해석한다.

## 기록과 도입 기준

실험별 사례/후보/자료/프롬프트/모델 버전, 후보 순서, 설정, 출력, 검증 결과, 토큰·비용·지연과 사람의 평가를 별도 JSONL에 남기는 안으로 시작한다.
앱의 실제 노출 기록과 섞지 않는다. 원문 개인정보를 로그에 무조건 복제하지 않는다.
기존 앱을 기준선으로 실행할 때는 Git 커밋과 앱 번들 자료 해시를 고정한다. 폐기한 국가 편집 데이터를 문서 폴더에 별도로 유지하지 않는다.

파일럿으로 평가 절차를 다듬은 뒤, 최종 결과를 보기 전에 품질·비용·지연 기준값을 정한다.
100곳 자료 제작 여부는 아래 확대 관문으로 판정한다.
10~20명 파일럿은 오류 발견용이며 경쟁 우위의 증거가 아니다. 사용자를 단위로 결과의 불확실성을 확인한다.
설명만 좋아졌다면 선택 모델까지 교체할 근거는 부족하다. 제외 위반·허위 사실이 있는 응답을 버리고 성공 응답만 평가하지 않는다.

첫 외부 파일럿 총지출 상한은 US$10이다. 구체적인 모델·API·상한 안의 호출 계획과 실행 도구는 아직 확정/구현하지 않았다. 이 문서 정리는 유료 API 실행을 포함하지 않는다.

## 100곳 확대 관문

E7 판정 기준은 이 절에서만 관리한다. 사용자 단위·최소 인원·대표 사례 방식은 2026-09-30 사용자 답변으로 확정했다. 파일럿 실행 전에 참여자 목록·대표 사례·비교할 LLM 모델과 프롬프트 버전을 고정한다. 여러 모델 중 결과가 좋은 모델을 사후 선택해 같은 관문을 통과했다고 보고하지 않는다.

- 판정 단위는 **사용자**다. 한 사람의 추가 사례·반복 실행은 진단용으로 남기고 투표권을 늘리지 않는다.
- **최소 8명:** 개발에 사용하지 않은 실제 사용자별로 실행 전에 고정한 대표 사례 1개를 사용한다. 유효한 평가 응답자가 8명 미만이면 재시험한다. 대표 사례나 인원 기준을 결과를 보고 바꾸지 않는다.
- 설명·모델 이름을 가린 비교에서 해당 사용자가 단순 규칙보다 LLM 후보를 선호한 경우만 승리다. 사전에 고정한 전체 참여자의 과반이 승리해야 확대 신호로 본다. 동률·실행 실패·평가 미응답도 분모에 포함하며, 결과가 나쁜 참여자를 교체하거나 추가해 과반을 맞추지 않는다. 동의 철회로 기록 삭제가 필요하면 해당 판정의 표본 변경을 기록하고 재시험한다.
- 실제 제시된 제외 위반·확인된 틀린 사실·미확인 변동/안전 정보 및 필수 조건 충족에 대한 근거 없는 단정은 0건이어야 한다. 자료 밖 사실은 별도 기록하며 그 자체를 오류로 세지 않는다. 사실 판정이 끝나지 않은 응답이 있으면 통과로 처리하지 않고 보류한다. 첫 외부 LLM 파일럿 총지출은 탐색 실험을 포함해 US$10 이하여야 한다. 검증기에서 차단한 오류는 별도 보고·수정하고, 실패·재시도 비용도 포함한다.
- 자료 위반은 가능하면 독립 검수자가 확인하며 확보 전에는 자체 검수와 그 한계를 명시한다. 기준 미달이나 평가 신뢰도 부족이면 자료·질문·모델 원인을 확인해 재시험하거나 보류한다. 재시험용 사례는 개발에 사용한 사례와 분리한다.

최소 인원은 값싼 확대 판단을 위한 운영 기준이다. 통계적 우월성이나 경쟁 우위를 보장하지 않는다. 최종 평가 표본·수치 기준은 E6에서 따로 고정한다.

## 근거 우회·장소 범위 평가 — E2·D6·E5

다음은 실행할 평가 사례의 계약이며 아직 LLM 평가를 실행한 결과가 아니다.

- 근거 없이 ‘조용한 동네라 쉬기 좋을 거예요’를 `advice`로 반환: 사실 전제를 추출해 맞음/틀림/확인 불가와 자료 포함 여부를 판정한다. 조언 분류로 사실 대조를 피할 수 없다. 기존 엄격한 계약의 근거 정책 위반 여부도 별도 기록한다.
- 실제 존재하는 명소 위치 ID로 ‘안전하다’·‘오늘 운영한다’를 뒷받침: 참조 형식은 맞아도 의미 불일치 오류로 판정.
- 미확인 버스 요금·배차를 숫자로 답하거나 예약 재고를 확정: 미확인 변동 정보 단정에 해당하는 정책 위반. 실제 사실 오류 여부는 별도 대조한다. 공식 링크가 없으면 링크 생성도 금지.
- ‘한 구역에 집중하는 편을 제안’처럼 새로운 사실이 없는 조언: 정상 사례. 모든 조언을 일괄 차단하는 오탐도 측정.
- 본섬 후보에 범위 밖 섬을 포함하거나 `unknown`을 `inside`로 해석: 범위 위반. 장소 누락·다른 도시 ID·중복 참조도 검사.
- 배편/숙박 `null`을 `false`로 해석하거나 오래된 근거를 확인된 제약으로 사용: 조건 위반.
- 범위 안이라는 이유로 하루 일정 가능을 보장: 근거 없는 일정 판단.

응답 단위로 `오류 응답 수 / 평가 가능한 전체 원본 응답 수`(생성 오류율), `차단된 오류 응답 수 / 오류 응답 수`(오류 차단율), `통과한 오류 응답 수 / 검증 통과 응답 수`(노출 후보 오류율), `잘못 차단된 정상 응답 수 / 정상 응답 수`(오탐률)을 함께 기록한다. 실제 사용자 노출 여부도 별도 기록한다. 분모 0은 미산출이며, 파싱 실패·호출 실패·재시도는 별도 개수와 비용으로 남긴다. 문장 단위 진단을 응답 단위 비율과 섞지 않는다. 자체/독립 검수를 구분한다. 최종 허용 기준은 기존 E6에서 고정하고 E7의 실제 제시 오류 0건 조건은 유지한다.

언어 비교 시 같은 사용자 원문과 의미가 같은 도시 자료로 한국어·영어 입력을 비교하고 선택 품질·근거 오류·실제 토큰·비용·지연을 기록한다. 언어만 바꾸고 정보량을 늘린 결과를 언어 효과로 해석하지 않는다.
