# 실행 5 계획 — 검색·제약 입력·상위 모델 비교

상태: **2026-10-07 고정. 호출 전이다.** 입력 해시 `467f421fb3f74493`(방식 설정, 지침 블록, 사례 문장, 후보 목록, 제약 입력). 이 문서를 고정한 커밋 뒤에는 방식·지침·사례·판정 기준을 고치지 않는다. 고치면 새 실행으로 기록한다. 상위 원칙은 [평가 원문](README.md), 근거 정책은 [출처 원문](../recommendation/sources.md)을 따른다.

## 평가 원문과 달라진 점

[평가 원문](README.md#다음-비교)의 세 방식(Haiku 목록만 / 상위 모델 목록만 / Haiku 목록 + 검색)을 아래 네 방식으로 바꾼다. 2026-10-07 사용자 결정이다.

- 출처 표시를 제품 요건으로 보기로 했다. 검색 없는 상위 모델은 채택 후보가 아니므로 상위 모델에도 검색을 붙인다.
- “검색이 있어도 도시별 자료가 필요한가”를 직접 보기 위해 제약 입력 방식을 넣는다.
- 검색 없는 Haiku는 채택 후보가 아니라 잣대로 남긴다.

검색의 앱 도입 자체는 여전히 이 실험 뒤에 정한다. 그 밖의 원칙(같은 실행에서 기준선 재측정, 사례 분리, 예산, 기록 항목)은 평가 원문 그대로다.

## 방식

| 방식 | 모델 | 입력 | 지침 | 보는 것 |
|---|---|---|---|---|
| H0 | `claude-haiku-4-5` | 목록 | `list` | 잣대. 사례가 실제로 어려운지, 검색이 지연·비용을 얼마나 늘리는지 |
| HS | `claude-haiku-4-5` | 목록 + 검색 | `search` | 싼 모델 + 검색으로 충분한지 |
| HSC | `claude-haiku-4-5` | 목록 + 검색 + 제약 입력 | `search` + `constraints-header` | 검색이 있어도 제약 입력이 도움이 되는지 |
| SS | `claude-sonnet-5-5` | 목록 + 검색 | `search` | 검색을 쓴 뒤에도 상위 모델이 필요한지 |

지침은 [에이전트 지침 파일](../../data/exploration/guidelines/r5-agents.md) 하나에 블록별로 있다.

비교의 의미:

- **HS 대 HSC:** 모델·지침·검색 설정이 같고 제약 입력만 다르다. 이번 실험의 핵심 비교다.
- **HS 대 SS:** 지침과 입력이 같고 모델 구성이 다르다. 모델 등급, 추론 설정, 검색 도구 버전이 함께 바뀌므로 “Sonnet 구성”의 묶음 효과로 기록한다.
- **H0 대 HS:** 검색 도구와 검색용 지침이 함께 바뀐다. 묶음 효과이며 채택 판정에는 쓰지 않는다.

제약 입력은 실행 2의 고정본 [`profiles-constraints.json`](../../data/exploration/profiles-constraints.json)을 그대로 쓴다. 20곳의 범위와 제약만 담은 AI 초안이고 사람 검수 전이다. 전체 프로필(실행 1)은 쓰지 않는다. 실행 1에서 답변 회피·항목 끼워 맞추기·표기 오류가 반복돼, 넣으면 제약 정보의 효과와 그 부작용을 가를 수 없기 때문이다. 결과는 “이 초안 수준의 제약 입력”에 한정한다.

## 호출 설정

| 항목 | H0 | HS · HSC | SS |
|---|---|---|---|
| 추론 | 끔 | 끔 | 적응형(`adaptive`), effort `medium` |
| 검색 도구 | 없음 | `web_search_20250305` | `web_search_20260209` |
| 검색 횟수 한도(`max_uses`) | — | 추천 5, 상세 3 | 추천 5, 상세 3 |
| `max_tokens` | 4096 | 4096 | 4096 |

- Sonnet 5.5는 `thinking: disabled`를 받지 않는다. 추론을 끄는 별도 설정(`between_tools`)이 있지만, 실제로 배포할 구성에 가까운 적응형으로 둔다. 그래서 SS는 추론까지 포함한 묶음이다.
- 검색 도구 버전은 모델별로 쓸 수 있는 것이 다르다. Haiku 4.5는 기본형, Sonnet 5.5는 결과를 걸러 읽는 신형이다.
- `max_tokens`는 검색·추론이 출력 한도를 쓰므로 실행 1~4의 1024에서 올렸다. 답변 길이는 과제 문구의 문장 수 제한으로 같게 둔다.
- 프롬프트 캐시는 쓰지 않는다. 검색 위치(`user_location`)와 도메인 제한은 설정하지 않는다.
- 자동 재시도는 하지 않는다. 모델 대체(fallback)도 쓰지 않는다. 거절·오류·잘림·`pause_turn`으로 끝나지 않은 응답은 그대로 기록하고 그 쌍은 미판정이다.
- 모든 방식의 사용자 메시지 첫 줄에 `Today: YYYY-MM-DD`(호출일)를 넣는다. 검색 방식이 “최근 1년”을 판단하려면 필요하고, 방식 사이에 입력을 같게 두기 위해 H0에도 넣는다.
- 위 도구 이름·모델 ID·단가는 실행 직전 공식 문서로 다시 확인한다. 확인한 날짜와 값을 고정본에 적는다.

## 과제 문구

H0은 실행 3·4의 과제 문구를 그대로 쓴다(`NOTE_TASK`, `TASKS["detail"]`). 검색 방식은 같은 문구 끝에 아래 두 줄을 붙이고 JSON에 `sources`를 더한다.

```
Sentences that state a searched fact end with its source number, like [1].
sources: [{"n": 1, "title": "<page title>", "url": "<url>", "published": "<YYYY-MM-DD or unknown>"}], only pages returned by your searches; [] if you searched nothing.
```

- 추천: `{"candidates": [{"id", "facts": [최대 2문장], "caveat": 1문장}], "note": 1문장, "sources": [...]}`
- 상세: `{"answer": [최대 2문장], "limits": 1문장, "sources": [...]}`

`sources`와 출처 번호는 답변 본문 길이에 넣지 않는다.

## 사례

12개를 쓴다. 형식과 작성 규칙은 [사례 초안 파일](../../data/exploration/drafts/cases-r5.md)에 있다.

- **기존 실패 사례 4개(진단용):** S3(케언스 체류), S4(9월 푸껫 수영), N3(서울 출발 직항 4시간), C6(도쿄 온천 왕복 4시간). 문장과 판정 기준은 기존 고정본을 그대로 쓴다. 지침과 방식을 정한 사람이 결과를 이미 본 사례이므로 채택 판정에는 쓰지 않는다.
- **새 사례 8개(확인용):** 도시·나라가 지정된 조건 질문 4개, 도시 언급 없는 열린 추천 4개. 채택 판정은 이 8개로만 한다.

새 사례 가운데 제약 입력에 관련 내용이 있는 것과 없는 것을 섞는다. 한쪽으로만 쓰면 HS 대 HSC가 처음부터 기운다. 사례별로 어느 쪽인지 호출 전에 적어 둔다.

결론을 좌우하는 사실(이동 시간, 평년 기온, 계절 위험)은 **호출 전에** 공식 출처로 확인해 사례 파일에 적는다. 출발점·수단·관측 지점·기간도 사례에 고정하고 응답은 그 조건을 물려받는다. 실행 3·4는 이것을 응답을 본 뒤에 정해 미판정이 쌓였다.

## 호출 수와 순서

- 기본 실행: 12사례 × 4방식 × 2과제 = 96호출. 이 중 72호출이 검색을 쓴다.
- 방식 순서는 사례마다 돌려 배치한다(H0·HS·HSC·SS, HS·HSC·SS·H0 …).
- 반복: 새 사례 가운데 HS와 HSC 또는 HS와 SS의 판정이 갈린 사례만, 갈린 두 방식을 2회씩 더 실행한다. 검색 결과는 호출마다 달라질 수 있어 1회 결과의 차이를 그대로 믿지 않기 위해서다. 3회를 독립 표본처럼 합산하지 않는다.

## 예산

첫 외부 파일럿 상한 US$10을 공유한다. 실행 1~4의 누적은 기록된 토큰 기준 US$0.62이고 남은 한도는 약 US$9.38이다. 청구서와 대조한 값이 아니므로 호출 전에 Console에서 확인한다.

검색 방식의 비용은 측정한 적이 없다. 검색 요금과 검색 결과가 입력 토큰으로 들어오는 양을 모르므로 추정하지 않는다. 대신 다음 순서로 실행한다.

1. 첫 사례 하나를 네 방식 모두로 실행한다(8호출).
2. 방식별 실제 비용으로 나머지 88호출의 비용을 계산한다.
3. 남은 한도의 70%를 넘으면 실행 전에 줄인다. 줄이는 순서는 반복 실행, 기존 실패 사례, 검색 횟수 한도 순이다. 새 사례 8개는 줄이지 않는다.

상한 때문에 끝내지 못한 부분은 미판정으로 남긴다.

## 판정 항목

응답 하나가 단위다. 항목마다 위반 유무를 0 또는 1로 적는다.

| 항목 | 내용 |
|---|---|
| ① 조건 | 사용자 조건·제외 위반, 미확인 변동·안전 정보의 단정 |
| ② 사실 | 사례 파일에 확인해 둔 사실과 어긋나는 주장 |
| ③ 유의점 | 사례 파일에 필요하다고 적은 안전·계절 유의점의 누락 |
| ④ 답변 | 질문에 직접 답하지 않음, 과도한 보류 |
| ⑤ 준수 | 요청 언어가 아닌 답, 내부 용어·ID 노출(“허용된 목록”, “프로필”, 도시 ID 등) |
| ⑥ 출처 | 검색 방식만. 검색 기록에 없는 URL, 문장을 뒷받침하지 않는 출처, 편도·왕복 등 단위를 바꿔 인용, 지어낸 게시일 |

실행 3·4에서 갈린 해석을 미리 정한다.

- 숫자는 사례 파일에 적은 확인 범위 밖이면 ②=1, 안이면 0이다. 응답이 출발점·수단을 다시 밝히지 않아도 사례의 조건을 적용한다. 사례 파일에 없는 숫자는 판정 전에 공동으로 확인하고, 확인하지 못하면 미판정이다.
- 숫자가 틀려도 조건 충족의 결론이 맞으면 ①은 0이다. 숫자가 맞아도 조건을 어긴 후보를 내면 ①은 1이다.
- “허용된 목록”, “주어진 목록” 같은 표현은 ⑤=1이다.
- 출처가 붙었다는 이유로 ②를 0으로 두지 않는다. ⑥의 URL 대조는 스크립트가 검색 기록과 비교해 표시하고, 뒷받침 여부는 검수자가 페이지를 열어 본다.
- 출력 형식 위반(코드 블록, 파싱 불가)은 건수로만 보고한다.

검수는 방식을 가린 시트로 Claude와 Codex가 각자 한다. 둘이 같으면 확정, 다르면 미판정이다. 검색 방식은 `sources` 때문에 가림이 완전하지 않다. AI 검수이며 사람 검수가 아니다.

## 선택 규칙 (2026-10-07 사용자 확정)

새 사례 8개의 응답 16개(추천·상세)로 센다. “중요 오류”는 ①+②+③의 합이다. 아래 숫자는 사용자가 제안값 그대로 확정했다.

**제약 입력(HS 대 HSC)**

- HSC의 중요 오류가 HS보다 3건 이상 적고, 그 차이가 서로 다른 2개 이상 사례에서 나오며, HSC의 ④+⑤가 HS보다 2건 이상 많지 않으면: 제약 입력을 유지 후보로 둔다.
- 중요 오류 차이가 2건 이하면: 제약 입력 없이 진행한다. 차이를 찾지 못한 것이며 효과 없음의 증명은 아니다.
- 그 밖(중요 오류는 줄었는데 ④+⑤가 늘어난 경우 등)은 혼합이며 보류한다.

**상위 모델(HS 대 SS)**

- 같은 숫자를 적용한다. SS가 3건 이상 적으면 Sonnet 구성을 후보로 두고, 2건 이하면 Haiku로 진행한다.
- ⑥도 함께 본다. SS의 ⑥이 HS보다 3건 이상 적으면 중요 오류 차이가 작아도 혼합으로 기록한다.

**공통**

- 미판정은 건수에 넣지 않고 적용한 뒤, 모두 0으로 놓았을 때와 모두 1로 놓았을 때 다시 적용한다. 결과가 달라지면 보류한다.
- 반복 실행한 사례는 3회 중 2회 이상 같은 방향일 때만 그 방향으로 센다.
- 지연과 비용에는 합격선을 두지 않는다. 방식별 평균·범위·표본 수를 추천과 상세로 나눠 기록하고, 검색을 추천 첫 화면에 붙일지 상세에만 붙일지는 결과를 본 뒤 정한다.

이 결과는 다음 구현 후보를 고르는 절차다. 출시 승인이나 실제 사용자 선호 개선의 증거가 아니다.

## 고정 시점의 확인 (2026-10-07)

- **단가:** Haiku 4.5 입력 US$1 / 출력 US$5, Sonnet 5.5 입력 US$2 / 출력 US$10(100만 토큰당). 웹 검색 1,000회당 US$10이고 검색 결과는 입력 토큰으로 과금된다. 오류가 난 검색은 과금되지 않는다. 출처: [공식 단가](https://platform.claude.com/docs/en/about-claude/pricing).
- **검색 도구:** 응답의 블록 이름(`server_tool_use`, `web_search_tool_result`), 결과 항목(`url`, `title`, `page_age`), 검색 횟수 필드(`usage.server_tool_use.web_search_requests`), `max_uses`를 [공식 문서](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)와 대조했다. Sonnet이 쓰는 `web_search_20260209`는 코드 실행 안에서 검색 결과를 걸러 읽으므로 응답에 코드 실행 블록이 함께 들어온다. 더 새 버전(`web_search_20260318`)이 있지만 계획대로 `20260209`를 쓴다.
- **확인하지 못한 것:** Haiku 4.5가 `web_search_20250305`를 지원하는지는 도구 참조 문서를 열어 보지 않았다. 지원하지 않으면 첫 호출이 400 오류로 멈춘다. Console의 실제 지출과 남은 한도도 확인하지 못했다.
- **실행 도구:** `scripts/run_profile_exploration.py --run 5`. `--dry-run`과 가짜 응답으로 네 방식을 돌리는 검사를 통과했고 실행 1~4의 입력 해시는 그대로다. 실제 API는 아직 호출하지 않았다.
- **사례:** [R1~R12](../../data/exploration/drafts/cases-r5.md). 일부 확인 사실은 비공식 출처의 검색 요약으로만 확인했고 사례 파일에 그렇게 적었다. 사용자 결정으로 그대로 둔다.
- **실행 기한:** R7이 2026-10-17 기준이므로 그 전에 실행한다.

## 한계

- 한국어 입력, 사례 12개, AI 검수다. 채택 판정에 쓰는 것은 새 사례 8개뿐이다.
- 사례 작성자는 실행 1~4의 결과와 이 계획의 방식을 알고 있다. 완전히 독립된 사례가 아니다.
- 검색 결과는 날마다 바뀐다. 같은 입력을 다시 실행해도 같은 답이 나오지 않으며, 저장한 검색 기록 범위에서만 재현할 수 있다.
- 제약 입력은 검수 전 초안 20곳이다. 사람이 고친 제약이나 다른 형식의 도시 자료에 대해서는 말하지 않는다.
