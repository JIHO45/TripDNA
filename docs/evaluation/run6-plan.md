# 실행 6 계획 — Gemini로 실행 5의 구성 반복

상태: **2026-10-07 고정. 호출 전이다.** 입력 해시 `e0faf259507ef978`. 첫 호출 뒤에는 방식·지침·사례·판정 기준을 고치지 않는다. 고치면 새 실행으로 기록한다. 응답 기록의 각 줄에 이 해시가 남는다. 상위 원칙은 [평가 원문](README.md), 근거 정책은 [출처 원문](../recommendation/sources.md), 앞선 실행은 [실행 5 계획](run5-plan.md)과 [부분 결과](../../data/exploration/runs5/result-partial.md)다.

## 배경

- 실행 5(Claude)는 96호출 중 76건에서 멈췄고 남은 호출은 하지 않기로 했다. 부분 결과가 최종 기록이다.
- LLM 기능은 구독자에게만 제공하고 무료 사용자에게는 LLM을 쓰지 않기로 했다. 그래서 검색 없는 방식은 이번에 넣지 않는다.
- 사용자 결정(2026-10-07): Claude는 더 실행하지 않고 Gemini만으로, 실행 5와 같은 세 구성을 비교한다. 지침에는 형식 규칙을 보강한다.

## 방식

| 방식 | 모델 | 입력 | 실행 5의 대응 방식 |
|---|---|---|---|
| FS | `gemini-3.8-flash` | 목록 + Google 검색 | HS (Haiku + 검색) |
| FSC | `gemini-3.8-flash` | 목록 + Google 검색 + 제약 입력 | HSC (Haiku + 검색 + 제약) |
| PS | `gemini-3.1-pro-preview` | 목록 + Google 검색 | SS (Sonnet + 검색) |

- 지침은 [에이전트 지침 파일](../../data/exploration/guidelines/r6-agents.md)의 `search2` 블록을 세 방식이 함께 쓴다. 실행 5의 `search` 블록에 형식 규칙 네 줄(번역해서 사용자 언어로, 인용 표시 금지, 내부 용어 금지, JSON 객체 하나)을 보강한 것이다.
- 제약 입력과 그 안내문은 실행 5와 같다([`profiles-constraints.json`](../../data/exploration/profiles-constraints.json), 실행 2의 고정본).
- 사용자 메시지, 후보 목록, 과제 문구, `Today` 줄, 출력 형식은 실행 5의 검색 방식과 같다.

비교의 의미:

- **FS 대 FSC:** 제약 입력만 다르다. 검색이 있어도 도시별 자료가 도움이 되는지 본다.
- **FS 대 PS:** 모델만 다르다. 상위 모델이 필요한지 본다. 실행 5와 달리 추론 단계와 검색 도구가 같아서 묶음 효과가 작다.

호출 설정:

- 추론은 두 모델 모두 `thinking_level: low`다. Gemini 3.8 Flash와 3.1 Pro는 추론을 끌 수 없고, 둘이 함께 지원하는 가장 낮은 단계가 `low`다. 기본값(Flash `medium`, Pro `high`)보다 낮춘 설정이다.
- 검색 횟수를 제한하는 설정을 확인하지 못했다. 한도 없이 실행하고 실제 검색어 수를 기록한다.
- `max_output_tokens` 4096, 자동 재시도 없음, `store: false`. SDK 없이 HTTP로 Interactions API를 호출한다.
- Pro는 미리보기(preview) 모델이다. 가격·동작이 바뀔 수 있다.

## 실행 5(Claude)와 비교할 때의 한계

같은 사례를 쓰지만 두 실행의 결과를 직접 견주면 안 되는 이유가 있다. 결과 문서에 나란히 적더라도 판정으로 세지 않는다.

- **지침이 다르다.** 실행 5는 형식 규칙을 보강하기 전의 지침이다. 영어 문장·인용 표시·`sources` 누락처럼 지침이 겨냥한 항목에서 Claude가 불리하게 보인다.
- **검색 횟수 한도가 다르다.** Claude는 추천 5회·상세 3회로 제한했고 Gemini는 제한이 없다.
- **추론 설정이 다르다.** Haiku는 추론을 껐고 Gemini는 끌 수 없다.
- **실행한 날이 다르다.** 검색 결과는 날마다 바뀐다.
- **사례 수가 다르다.** 실행 5의 새 사례는 5개만 끝났다.

두 제공자를 공정하게 고르려면 같은 날, 같은 지침으로 함께 돌려야 한다. 이번 실행은 그 비교가 아니다.

## 사례

실행 5의 [R1~R12](../../data/exploration/drafts/cases-r5.md)를 문장과 판정 기준 그대로 쓴다.

- 채택 판정: 새 사례 R5~R12의 응답 16개(방식당).
- 진단용: R1~R4.
- 지침의 형식 규칙은 R1~R10에 대한 Claude의 답을 본 뒤에 썼다. Gemini는 이 사례들에 답한 적이 없다.
- 날짜: R7은 2026-10-17, R11은 11월 첫 주, R12는 “이번 주 금요일”이 기준이다. 10월 17일 전에 실행한다.

## 호출 수와 예산

- 12사례 × 3방식 × 2과제 = 72호출. 방식 순서는 사례마다 돌려 배치한다. 반복 실행은 FS와 FSC 또는 FS와 PS의 판정이 갈린 새 사례에 한해, 갈린 두 방식을 2회씩 더 한다.
- 단가(2026-10-07 [공식 단가](https://ai.google.dev/gemini-api/docs/pricing) 확인): Flash 입력 US$0.75 / 출력 US$3.75(2026-12-31까지, 이후 US$1.50 / US$7.50로 공지), Pro 입력 US$2 / 출력 US$12(프롬프트 20만 토큰 이하). 출력 요금에 추론 토큰이 포함된다. Google 검색은 월 5,000회 무료 뒤 검색어 1,000건당 US$14다.
- 비용은 측정한 적이 없다. 스크립트는 무료 검색 한도를 무시하고 검색어마다 US$0.014로 계산해 높게 잡는다.
- 상한: 이번 실행의 Gemini 지출은 US$5로 따로 잡는다. 사용자가 2026-10-07에 선불로 US$5(약 8,000원)를 충전했다. 실행 1~5의 Claude 지출(기록 기준 약 US$5.14)과 합치면 처음 정한 US$10을 조금 넘을 수 있으며, 그 초과를 이번 실행에 한해 허용한다.
- 순서: 첫 사례를 세 방식으로 실행한 뒤(6호출) 실제 비용으로 나머지를 계산한다. US$5의 70%(US$3.5)를 넘으면 반복 실행, 진단용 R1~R4 순으로 줄인다. 새 사례 8개는 줄이지 않는다.

## 판정

판정 항목 ①~⑥과 해석 규칙은 [실행 5 계획](run5-plan.md#판정-항목)과 같다. 실행 5의 부분 결과에서 드러난 점을 더한다.

- ②는 사례 파일의 확인 사실과 어긋나는 주장만 센다. 그 밖의 숫자는 판정 전에 공동으로 확인한 것만 센다.
- ⑥은 `sources` 누락, 검색 기록에 없는 URL, 숫자·계절·안전 문장에 출처 번호가 없는 경우를 센다. 출처가 문장을 실제로 뒷받침하는지는 방식당 추천 4건과 상세 4건을 판정 전에 무작위로 골라 페이지를 열어 확인한다.
- JSON 밖의 글, 코드 블록, 인용 표시 누출, 객체 두 개는 형식 건수로 따로 보고한다.

검수는 방식을 가린 시트로 Claude와 Codex가 각자 한다. 둘이 같으면 확정, 다르면 미판정이다. 한 명만 검수하면 그렇게 적고 판정으로 세지 않는다.

## 선택 규칙

실행 5에서 사용자가 확정한 숫자를 그대로 쓴다. 새 사례 R5~R12의 응답 16개로 세고, 중요 오류는 ①+②+③이다.

**제약 입력(FS 대 FSC)**

- FSC의 중요 오류가 FS보다 3건 이상 적고, 그 차이가 서로 다른 2개 이상 사례에서 나오며, FSC의 ④+⑤가 FS보다 2건 이상 많지 않으면: 제약 입력을 유지 후보로 둔다.
- 차이가 2건 이하면: 제약 입력 없이 진행한다.
- 그 밖은 혼합이며 보류한다.

**상위 모델(FS 대 PS)**

- PS의 중요 오류가 3건 이상 적으면 Pro를 후보로 두고, 2건 이하면 Flash로 진행한다.
- PS의 ⑥이 FS보다 3건 이상 적거나 PS의 ④가 FS보다 3건 이상 많으면 혼합으로 기록한다.

**공통**

- 미판정을 모두 0으로 놓았을 때와 1로 놓았을 때 결과가 달라지면 보류한다.
- 반복 실행한 사례는 3회 중 2회 이상 같은 방향일 때만 그 방향으로 센다.
- 지연과 비용에는 합격선을 두지 않는다. 방식별 평균·범위·표본 수를 추천과 상세로 나눠 적고, 무료 검색 한도를 적용한 비용과 적용하지 않은 비용, Flash의 인상 뒤 요금으로 계산한 비용을 함께 적는다.

이 결과는 다음 구현 후보를 고르는 절차다. 출시 승인이나 실제 사용자 선호의 증거가 아니다.

## 실행 전에 남은 일

1. 선택 규칙과 Gemini 예산을 확정한다.
2. `GEMINI_API_KEY`를 준비한다. Google 검색은 무료 등급에서 쓸 수 없으므로 결제가 연결된 키여야 한다.
3. 실행 도구는 `scripts/run_profile_exploration.py --run 6`이며 외부 호출 없는 검사(`--dry-run`, 가짜 응답)를 통과했다. Gemini의 요청·응답 형태와 `thinking_level` 값은 문서 요약으로만 확인했고 호출해 본 적이 없다. 첫 6호출에서 오류 없이 검색 기록과 토큰 수가 채워지는지 본다. 응답 전체를 기록에 남긴다.
4. 고정 커밋을 남긴다.
