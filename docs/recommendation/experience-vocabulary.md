# 경험 어휘와 피드백 해석

상태: 자료 저장용 경험 ID v1, 화면 문구는 초안. 기준: [핵심 설계](architecture.md) 3·6절.
태그를 기존 5축의 ±숫자로 변환하는 서명은 새 구조에서 사용하지 않는다.

## 경험의 독립된 분류

도시 탐방, 자연 풍경, 미식, 휴식·힐링, 문화·역사, 액티비티, 쇼핑, 밤 문화, 새로운 사람 만나기를 초기 분류로 제안한다.
이 목록 밖의 자유문장도 보존한다. 분류가 다 들어맞는 사람도, 아직 모르는 사람도 표현할 수 있어야 한다.

저장용 ID와 현재 한국어 라벨의 기준 파일은 [경험 분류 목록](../../data/experience-categories.json)이다. 도시 자료의 `categories`에는 이 파일의 ID만 넣고 `category_version`에 목록 버전을 기록한다. 라벨 변경은 목록의 표시 문구만 바꾸며 도시 자료의 ID는 유지한다. ID 의미는 재사용하거나 몰래 바꾸지 않는다. 분류를 추가·분리할 때 목록 버전을 올리고 기존 자료의 이관 여부를 명시한다.

`city_exploration`는 도시 탐방, `activities`는 실내·야외 체험을 포괄한다. 활동 원문을 함께 보존하며 체험 종류·강도를 분류명만으로 단정하지 않는다. `meeting_people`은 새로운 사람과의 만남이며 기존 동행 여부가 아니다. 분류 자체로 이동 수단·강도·예약 조건을 추론하지 않는다.

- 도시와 자연은 동시에 선택할 수 있다.
- 혼자만의 시간, 기존 동행과의 시간, 새로운 사람과의 만남은 반대축이 아니다.
- 밤 문화·음악 공연·술은 같은 뜻이 아니다. 사용자가 말한 세부 경험을 보존한다.
- 자연 풍경 선호만으로 등산·고강도 활동 선호를 만들지 않는다.
- 함께 여행하는 사람에게도 혼자만의 시간이 필요할 수 있다. 동행을 이유로 관련 선택지를 숨기지 않는다.

## 문장 해석의 범위

- “이번 여행 음식이 좋았다”: 해당 여행의 경험 평가.
- “여행에서 음식이 가장 중요하다”: 평소 선호와 우선순위.
- “이번 일정이 너무 빡빡했다”: 해당 여행 페이스에 대한 불만. 활동 전반을 싫어한다고 단정하지 않는다.
- “계획대로 안 됐다”: 실패 사실/불만. 계획형 성격의 증거로 바꾸지 않는다.
- “너무 북적였다”: 해당 경험의 혼잡 불만. 새 사람을 만나는 것에 대한 거절이 아니다.
- “날씨가 아쉬웠다”, “예상보다 비쌌다”: 당시 조건. 영구적인 기후·예산 한도를 자동으로 만들지 않는다.
- “불친절했다”, “위생이 아쉬웠다”: 해당 경험 보고. 국가 전체의 사실 점수로 자동 반영하지 않는다.

일반적인 선호인지 여행별 보고인지 불분명하면 원래 범위로 남긴다.
중요한 범위 변경에는 한 가지 확인 질문을 사용한다. 명시적 평소 선호의 자동 기억·되돌리기는 핵심 설계대로 적용한다.

## 선택 UI

선택하지 않은 항목은 미상이며 음성 신호가 아니다. “모르겠어요”와 “둘 다 좋아요”를 분리한다.
긍정·아쉬움 선택을 강요하지 않는다. 다른 경험을 직접 입력할 수 있게 한다.
도시의 대표 경험만 제시해 다른 경험을 답할 수 없게 만들지 않는다.
같은 항목을 다른 문구로 반복 선택해도 증거량을 부풀리지 않는다.

기존 태그는 [이관 원칙](preference-evidence.md)에 따라 실제 답변 의미를 확인할 때만 참고한다. 축 서명을 새 선호 계산에 재사용하지 않는다.
최종 화면 문구는 사례 검증과 화면 구현에서 다듬되 저장 ID는 위 목록을 따른다.
