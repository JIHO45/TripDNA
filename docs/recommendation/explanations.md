# 도시 추천과 설명의 근거

상태: 새 구조의 설명 계약. 기준: [핵심 설계](architecture.md) 5·7절.
고정된 best/fresh/underrated 슬롯·탐험 반경 공식·매칭 백분율은 새 추천에 사용하지 않는다.

## 카드

기본안은 최대 3개 도시다. 도시 이름을 중심으로 나라, 사용자에게 맞는 경험, 유의점을 보여준다.
적합한 후보가 적으면 카드 수를 줄인다. “새로운 도전” 자리를 채우려고 부적합한 곳을 끼우지 않는다.

추천 이유는 **사용자 근거 + 도시 근거**를 연결한다.
예: 사용자가 “미술관을 좋아한다”고 직접 답했고, 검수 DB에 특정 미술관 경험과 방문 조건이 있을 때 그 둘을 설명한다.
방문·북마크만으로 “미술관을 좋아하시니까”라고 말하지 않는다.

## 설명에서 구분할 것

- DB 사실: 무엇이 어디에 있고 어떤 조건에서 가능한지.
- 사용자 사실: 사용자가 직접 알려준 선호와 이번 조건.
- 적합성 판단: 그 두 사실을 연결한 추천의 이유. 미래 만족을 보장하지 않는다.
- 미확인: 자료가 없거나 최신 확인이 필요한 정보.

근거 ID의 존재만으로 모든 문장이 검증된 것은 아니다. 문장이 출처의 범위를 넘지 않는지 평가한다.
모델 내부 추론 과정을 노출할 필요는 없지만, 사용자가 판단할 추천 이유와 출처는 제공한다.

## 금지할 설명

- 집계가 없는데 “당신 같은 사람들이 좋아했어요”.
- 검수된 인기 자료가 없는데 “숨은 보석”, “세계 인기 100위”.
- “매칭 97%”, “AI 확신 90%”처럼 보정되지 않은 숫자.
- 현재 가격 없이 “항공·숙박 포함 총예산 충족”.
- 타인의 성격·국민성을 도시의 사실로 단정하기.
- 제외·비용·거리 이유를 무관한 경험 취향으로 해석하기.

## 상세 질문

DB 근거로만 답한다. 미확인 질문에는 확인되지 않았다고 말하고 준비된 공식 링크가 있으면 안내한다.
외부 검색·예약·일정 생성은 이번 범위에 추가하지 않는다.
열람과 질문 자체로 평소 취향을 갱신하지 않는다. 반복 상세 열람은 유효한 설명 캐시를 재사용한다.

제휴 링크는 추천 선택이 끝난 뒤 연결한다. 수수료·제휴 공급 여부를 추천 입력에 넣지 않는다.
설명과 유의점을 광고 뒤로 숨기지 않는다. 제휴 정책의 상위 기준은 루트 README다.
