## 사용자 정보: 하나의 점수 벡터로 압축하지 않는다

### 평소 선호

명시적으로 말한 좋아하는 경험, 피하고 싶은 경험, 여행 스타일을 보관한다.

예: “현지 음식을 먹는 게 가장 중요하다”, “자연도 도시도 좋다”, “혼자 조용히 쉬는 시간을 좋아한다”, “예약으로 하루를 꽉 채우는 건 싫다”.

선호를 받는 형태는 [컨셉과 티어](#컨셉과-티어)를 따른다. 목록 밖의 선호도 원문으로 보존한다.

각 선호에 필요한 것은 내용, 적용 범위, 출처 답변, 기록 시점, 활성/철회 상태다. LLM이 근거 없는 강도·확률·성격 점수를 만들지 않는다. 사용자가 “가장 중요”라고 말한 우선순위는 그대로 보관한다.

### 컨셉과 티어

2026-10-08 변경: 2026-10-07의 네 상태(좋아함·피하고 싶음·괜찮음·미확인)를 아래 구조로 바꿨다. 양 끝 축이 아니라 독립 항목이라는 원칙은 그대로다.

컨셉은 큰 컨셉과 그 아래 세부의 두 단계다([경험 어휘](#경험-어휘)). 세 가지 정보를 구분한다.

- **티어(평소 선호):** 사용자가 큰 컨셉을 1·2·3티어와 넷째 칸에 직접 놓는다. 화면 이름은 1티어 "가장 원해요", 2티어 "좋아요", 3티어 "있으면 좋아요", 넷째 칸 "아직 모르겠어요"다(2026-10-24. 이전 넷째 칸 이름은 "잘 모르겠음·피하고 싶음"이었다). 1~3티어는 모두 원한다는 뜻이고 3티어는 약한 긍정이다. 넷째 칸은 모르는 것과 피하고 싶은 것을 구분하지 않으며 추천 점수에 넣지 않는다. 방문 기록에서 추정하지 않는다. 건너뛸 수 있고, 놓지 않은 컨셉은 넷째 칸과 같게 다룬다. 추천에서는 LLM 입력으로 쓴다. 이전 코드 계산에서는 동점 해소에 썼으며 현재 코드 역할은 [미정](README.md#순위-계산)이다. 강하게 피하고 싶은 것은 자유문장으로 받는다.
- **여행별 컨셉(기록):** 여행마다 주 컨셉 1개와 부 컨셉 0~2개를 붙이고 세부는 선택으로 받는다. 여행을 등록할 때 붙이고 다녀온 뒤 고칠 수 있다. 출장·가족 방문 같은 의무 여행은 컨셉 없이 방문 기록만 남긴다. “가족”은 동행이지 컨셉이 아니다.
- **이번 여행 컨셉(추천 입력):** 추천을 받을 때 정한다. 티어보다 우선한다.

여행별 컨셉의 횟수는 [지문](../screens/home-and-fingerprint.md#취향-지문)과 Wrapped에 쓴다. 횟수를 선호 점수로 바꿔 추천 입력에 넣지 않는 것은 사용자 확인 전의 제안이다. 휴식 여행을 세 번 갔다는 사실과 휴식을 좋아한다는 진술은 다르다는 것이 이유다. 방문 여부로 거르는 것(새로운 곳만 보기)과 평가의 이유를 쓰는 것은 이 제안과 별개다.

각 답에는 원문과 출처·시점·적용 범위를 연결한다. 목록 밖의 세부 선호와 명시적 우선순위도 보존한다.

### 이번 여행

동행, 출발지, 날짜/계절, 기간, 예산과 포함 범위, 이번에 원하는 경험을 별도로 둔다.

- 미입력은 모름이다. 과거 여행의 평균이나 동행 빈도로 채우지 않는다. 동행을 경험 선호로 번역하지 않는다.
- 예산은 최대 금액으로 받는다(2026-10-08). 통화, 1인/일행 전체, 항공 포함 여부의 기준은 [미정](README.md#미정)이다.
- “이번에는 자연을 보고 싶다”는 이번 여행에 적용한다. 도시 선호를 지우지 않는다.
- 명시한 이번 요청은 과거 기억·제외보다 우선한다. 제외의 이번 여행 예외는 [공통 규칙](#공통으로-지킬-규칙)을 따르며, 그 외 유효한 제외와 필수 조건은 지킨다.
- 현재 여행은 앱 재시작 후에도 유지한다. “새 여행 시작”에서 조건과 이번 여행 제외를 새로 시작한다.

### 여행·관심 기록

방문 도시/나라, 직접 평가, 좋았던 이유·아쉬웠던 이유, 저장한 후보를 구분한다.

2026-10-08: 여행 평가는 도시마다 별점, 좋았던 점 메모, 아쉬웠던 점 메모로 받는다. 메모는 선택이다. 성향·관심사·아쉬움 태그를 고르는 방식은 없앤다. 메모는 원문으로 보존하고 [추천 호출의 입력](README.md#지난-여행의-기억)으로 쓴다. 이전에 고른 태그 기록은 지우지 않는다.

- 사진 위치는 방문 후보를 제안하고 사용자가 확인한다. 통과·거주·환승 여부를 방문 만족도로 추론하지 않는다.
- 나라만 확인되면 나라 방문으로 남긴다. 그 나라의 도시를 전부 방문 처리하지 않는다.
- 저장은 북마크다. 저장 한 번으로 취향을 그 도시 특성 쪽으로 이동시키지 않는다.
- 상세 열람이나 “서핑도 할 수 있어?”라는 질문은 취향 확정이 아니다.
- “A가 B보다 좋았다”는 두 여행의 상대 평가만 남긴다. 이유 없이 모든 특성의 확신을 올리지 않는다.
- 재방문 의향은 해당 여행지에 대한 의향이다. 일반적인 새로움 성향으로 확대하지 않는다.

## 증거 단위

내용·원문/선택지·출처·시점·적용 범위·활성/철회 상태를 함께 보존한다.
직접 답변과 모델의 해석을 구별하고, 요약에는 원본 증거 연결을 남긴다.

- 방문 사실: 위치와 기간. 만족·성격은 포함하지 않는다.
- 여행 평가: 그 여행/도시/경험에 대한 좋음·아쉬움. 이유 없는 만족은 경험 선호를 바꾸지 않으며 여행지의 대표 특성으로 분해하지 않는다.
- 평소 선호: 일반적인 선호임을 분명히 말한 내용. 자동 저장 후 내용과 되돌리기를 보여준다.
- 이번 여행: 동행·예산·기간·목적. 다른 여행으로 자동 승계하지 않는다.
- 제외: 도시/나라 대상과 이번 여행/계속 적용 범위.
- 북마크: 관심 후보 보관. 취향 방향·강도의 증거로 바꾸지 않는다.

“도쿄에서 음식이 좋았다”는 해당 경험의 긍정 증거로 추천에 참고할 수 있다.
“어디든 미식이 가장 중요하다”는 평소 우선순위다. 두 진술의 범위를 같게 만들지 않는다.
여행 비교는 여행 사이의 선호 관계만 알려준다. 그 이유나 모든 항목의 확신은 알려주지 않는다.

## 피드백·기억·제외 정책

### 해석 예시

- “이번엔 너무 비싸요” → 기억으로 저장하지 않는다. 사용자가 예산 조건을 고친다(2026-10-08. 이전에는 해당 후보를 이번 여행에서 제외하고 비용 문제를 기록했다). 금액을 모르면 예산 숫자를 지어내거나 모든 고물가 도시를 일괄 제외하지 않는다.
- “이번에는 자연을 보고 싶어요” → 이번 여행의 목적. 평소 도시 선호 유지.
- “나는 원래 붐비는 곳을 싫어해요” → 평소 혼잡 회피 선호. 사람 만나기 선호와 별개.
- “도쿄 다시 추천하지 마” → 도쿄를 계속 제외. 일본 전체·다른 대도시로 확대하지 않는다.
- “일본은 추천하지 마” → 일본에 속한 도시를 제외.
- “도쿄는 별로예요” → 도쿄의 부정 반응. 이유를 추측하지 않고 아래 기간 정책 적용.
- “친구랑 여행할 거예요” → 이번 동행. 밤 문화 선호 추가 없음.
- “음식은 좋았지만 줄 서는 건 싫었어요” → 음식에 대한 긍정과 대기 회피를 따로 저장.

범위가 모호해서 이후 추천이 크게 달라지면 “이번 여행에만 적용할까요?”처럼 한 가지만 확인한다. 모든 대화에 확인 팝업을 띄우지 않는다.

### 사용자 확정 정책

- **방문 도시도 기본 추천한다.** “새로운 곳만 보기”를 선택하면 방문이 확인된 도시를 제외한다. 도시를 모르는 국가 기록은 해당 국가 전체 제외로 바꾸지 않으며, 미확인 도시를 확실한 첫 방문이라고 설명하지 않는다.
- **이유·기간 없는 도시 부정 반응은 계속 제외한다.** “도쿄는 별로예요” 뒤에는 “도쿄를 추천에서 제외했어요 · 되돌리기”를 표시한다. 해제 전까지 유지하며, 취향 항목은 변경하지 않는다. 명시적으로 “이번에는”이라고 말하면 이번 여행에만 적용한다.
- 카드의 기본 행동은 자세히 보기, 저장, 다른 후보 보기다. “다시 추천하지 않기”(2026-10-24 이전 이름: 계속 추천하지 않기)는 메뉴에 둔다(2026-10-08. 이전에는 “추천에서 계속 제외”가 카드의 주 행동이었다. 지금 끌리지 않는다는 반응을 계속 제외로 만들기에는 너무 강하다고 보았다). 제외 저장 뒤 내용과 되돌리기를 보여준다.
- **명시적인 평소 취향은 자동 저장한다.** 예: “붐비는 곳을 피하는 취향으로 기억했어요 · 되돌리기”. 저장한 내용과 범위를 사용자에게 보여준다. 질문·가정·인용·모호한 말은 명시적인 취향 진술로 취급하지 않는다.

### 공통으로 지킬 규칙

제외는 대상 ID, 도시/나라 범위, 이번 여행/계속 적용, 이유 원문, 시점, 해제 상태를 저장한다. 앱 실행 세션과 여행 범위를 혼동하지 않는다.

- 제외 목록에서 확인·해제 가능하다. 해제는 부정 이유를 반대 취향으로 바꾸지 않는다.
- 나라 제외를 해제해도 별도로 설정한 도시 제외는 유지한다.
- 이번 요청에서 명시한 제외 예외를 후보 탈락 전에 해석하고, 예외가 적용된 제외를 출력 검증에서도 다시 확인한다. 계속 제외 설정을 지우지 않으며 구체적인 입력 필터 단계는 [추천 흐름](README.md#처리-흐름과-책임)을 따른다.
- 필수 조건이나 제외를 만족하는 후보가 없으면 이를 알리고 사용자가 조건을 바꾸게 한다. AI가 임의로 해제하지 않는다. 사용자가 이번 요청에서 제외한 곳을 명시해 원하면 이번 여행에 한해 포함하고 그 사실을 알린다. 계속 제외 설정은 그대로 둔다(2026-10-08).
- 평소 취향 수정은 사용자가 원문과 적용 내용을 확인·삭제할 수 있어야 한다.
- 명시적인 정정은 이전의 같은 범위 선호를 대체한다. 서로 다른 상황의 선호는 함께 보존한다.
- 삭제·철회한 증거는 추천 입력에서 빠지고 해당 추천 캐시가 무효화된다. 단순 요약 문장 속에 다시 살아남지 않게 한다.

## 수정·철회

- 같은 원문을 반복 요약하거나 여러 화면에 표시해도 독립된 증거가 늘어난 것은 아니다.
- 평소 선호와 이번 목적이 달라도 모순으로 제거하지 않는다.
- 명시적 정정은 같은 범위의 이전 내용을 대체하고 근거 연결을 갱신한다.
- 평가 수정·삭제를 허용한다. 삭제된 여행/평가에서 파생한 기억·추천 요약도 재구성한다.
- 사용자가 별도로 직접 확정한 평소 선호는 여행 삭제와 자동으로 함께 지우지 않는다. 삭제 범위를 표시한다.
- 철회된 정보가 추천 캐시·대화 요약·공유 문장에서 다시 복원되지 않도록 한다.
- 저장 실패 시 기억했다는 안내를 하지 않는다.

## 경험 어휘

상태: 자료 저장용 경험 ID v1, 화면 문구는 초안. 2026-10-08에 두 단계 컨셉으로 넓히기로 했고 기준 파일은 아직 v1이다.

### 두 단계 컨셉 (2026-10-08, 목록 확정 전)

- 큰 컨셉은 10개다. 기존 9개에 “이벤트”(축제, 스포츠 직관, 콘서트·공연)를 더한다. 나이트라이프와 교류는 합치지 않는다.
- 큰 컨셉마다 세부를 둔다. 세부 목록의 초안은 [등급표 초안](../../data/exploration/coverage-check/grades-v2.json)의 `concepts`에 있다. 그 파일의 ID는 계산용 임시 ID이며 기준 파일의 ID가 아니다.
- 지문·Wrapped의 집계와 티어는 큰 컨셉만 쓴다. 세부는 추천을 좁히는 데 쓴다. 세부를 나중에 더해도 지문과 티어는 바뀌지 않는다.
- 세부는 부모를 하나만 갖는다. 사람들이 왜 가는지를 기준으로 정한다(온천은 휴양).
- 날짜가 정해진 것을 보러 가면 이벤트, 상시 영업하는 곳은 나이트라이프다.
- 목록에 없는 요청(특정 작품의 성지 등)은 세부로 만들지 않고 자유문장으로 받는다.
- 화면에서는 “미식 여행”처럼 컨셉 이름으로 부른다. 표시 이름만 바꾸고 ID는 유지한다.
- 기준 파일을 v2로 올릴 때 기존 ID와의 대응, 그리고 하이킹을 `activities`에서 자연으로 옮기는 의미 변경을 명시한다.

### 경험의 독립된 분류

v2 전환 전까지 저장용 ID는 기준 파일의 기존 ID를 유지한다. 선호를 받는 형태는 [컨셉과 티어](#컨셉과-티어)를 따른다.
이 목록 밖의 자유문장도 보존한다. 분류가 다 들어맞는 사람도, 아직 모르는 사람도 표현할 수 있어야 한다.

저장용 ID와 현재 한국어 라벨의 기준 파일은 [경험 분류 목록](../../data/experience-categories.json)이다. 도시 자료의 `categories`에는 이 파일의 ID만 넣고 `category_version`에 목록 버전을 기록한다. 라벨 변경은 목록의 표시 문구만 바꾸며 도시 자료의 ID는 유지한다. ID 의미는 재사용하거나 몰래 바꾸지 않는다. 분류를 추가·분리할 때 목록 버전을 올리고 기존 자료의 이관 여부를 명시한다.

`city_exploration`는 도시 탐방, `activities`는 실내·야외 체험을 포괄한다. 활동 원문을 함께 보존하며 체험 종류·강도를 분류명만으로 단정하지 않는다. `meeting_people`은 새로운 사람과의 만남이며 기존 동행 여부가 아니다. 분류 자체로 이동 수단·강도·예약 조건을 추론하지 않는다.

- 도시와 자연은 동시에 선택할 수 있다.
- 혼자만의 시간, 기존 동행과의 시간, 새로운 사람과의 만남은 반대축이 아니다.
- 밤 문화·음악 공연·술은 같은 뜻이 아니다. 사용자가 말한 세부 경험을 보존한다.
- 자연 풍경 선호만으로 등산·고강도 활동 선호를 만들지 않는다.
- 함께 여행하는 사람에게도 혼자만의 시간이 필요할 수 있다. 동행을 이유로 관련 선택지를 숨기지 않는다.

### 문장 해석의 범위

- “이번 여행 음식이 좋았다”: 해당 여행의 경험 평가.
- “여행에서 음식이 가장 중요하다”: 평소 선호와 우선순위.
- “이번 일정이 너무 빡빡했다”: 해당 여행 페이스에 대한 불만. 활동 전반을 싫어한다고 단정하지 않는다.
- “계획대로 안 됐다”: 실패 사실/불만. 계획형 성격의 증거로 바꾸지 않는다.
- “너무 북적였다”: 해당 경험의 혼잡 불만. 새 사람을 만나는 것에 대한 거절이 아니다.
- “날씨가 아쉬웠다”, “예상보다 비쌌다”: 당시 조건. 영구적인 기후·예산 한도를 자동으로 만들지 않는다.
- “불친절했다”, “위생이 아쉬웠다”: 해당 경험 보고. 국가 전체의 사실 점수로 자동 반영하지 않는다.

일반적인 선호인지 여행별 보고인지 불분명하면 원래 범위로 남긴다.
중요한 범위 변경에는 한 가지 확인 질문을 사용한다. 명시적 평소 선호의 자동 기억·되돌리기는 [사용자 확정 정책](#사용자-확정-정책)대로 적용한다.

### 선택 UI

선택하지 않은 항목은 미상이며 음성 신호가 아니다. “모르겠어요”와 “둘 다 좋아요”를 분리한다.
긍정·아쉬움 선택을 강요하지 않는다. 다른 경험을 직접 입력할 수 있게 한다.
도시의 대표 경험만 제시해 다른 경험을 답할 수 없게 만들지 않는다.
같은 항목을 다른 문구로 반복 선택해도 증거량을 부풀리지 않는다.

기존 태그는 [이관 원칙](#기존-데이터-이관)에 따라 실제 답변 의미를 확인할 때만 참고한다. 축 서명을 새 선호 계산에 재사용하지 않는다.
최종 화면 문구는 사례 검증과 화면 구현에서 다듬되 저장 ID는 위 목록을 따른다.

## 기존 데이터 이관

1. 여행·구간·직접 평가·퀴즈 답·북마크·제외 원본을 보존한다.
2. 국가 평균이 포함된 파생 5축 값을 새 선호로 변환하지 않는다.
3. 퀴즈 답과 태그는 질문/선택지의 실제 뜻이 명확할 때만 그 범위로 옮긴다. 원문 의미를 복원할 수 없으면 미해석 기록으로 남긴다. 관심사 태그는 뜻이 대응하는 컨셉으로 옮길 수 있다. 성향 태그는 옮기지 않는다(2026-10-08).
4. “혼자↔함께” 한 값으로 동행·새 사람 만나기·혼잡 회피를 만들어내지 않는다.
5. 도시명은 명확히 식별되는 경우에만 도시 ID에 연결한다. 동명이거나 미확인인 값은 확인 전 보류한다.
6. 나라 방문만 있는 경우 그 나라의 모든 도시를 방문 처리하지 않는다.
7. 기존 나라 제외를 도시 하나로 축소하지 않는다. 기존 기한 있는 제외는 해당 기한을 보존하고, 새 무기한 제외와 구분한다.
   옛 세션 제외는 과거 기록으로 보존하고 새 추천의 활성 제외에는 적용하지 않는다. 새 ‘이번 여행 제외’로 승격하거나 기존 기한 있는 제외까지 비활성화하지 않는다. 이관 안내에 이 차이를 표시하고, 사용자가 원하면 새 범위로 직접 다시 제외할 수 있게 한다.
8. 이전 국가 추천 노출은 과거 국가 모델 기록으로 보존한다. 도시 모델 성과와 무표시로 합산하지 않는다.

이관은 한 번 더 실행해도 중복 증거·제외가 생기지 않아야 한다. 저장 버전별 이관 계획과 실패 시 원본 보존을 구현 단계에서 검증한다. 별도 이벤트 소싱 시스템을 새로 만들 필요는 없다.
