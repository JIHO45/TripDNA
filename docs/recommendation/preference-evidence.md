# 직접 증거와 기존 기록 이관

상태: 새 구조의 구현 목표. 기준: [핵심 설계](architecture.md) 3·6·13절.
기존 국가 벡터 재생 산식의 튜닝 지침은 폐기한다. 현행 구현 확인은
[UTVReplayService](../../TripDNA/Application/UTVReplayService.swift)와
[RecommendationService](../../TripDNA/Application/RecommendationService.swift)를 본다.

## 증거 단위

내용·원문/선택지·출처·시점·적용 범위·활성/철회 상태를 함께 보존한다.
직접 답변과 모델의 해석을 구별하고, 요약에는 원본 증거 연결을 남긴다.

- 방문 사실: 위치와 기간. 만족·성격은 포함하지 않는다.
- 여행 평가: 그 여행/도시/경험에 대한 좋음·아쉬움. 이유가 없으면 특성으로 분해하지 않는다.
- 평소 선호: 일반적인 선호임을 분명히 말한 내용. 자동 저장 후 내용과 되돌리기를 보여준다.
- 이번 여행: 동행·예산·기간·목적. 다른 여행으로 자동 승계하지 않는다.
- 제외: 도시/나라 대상과 이번 여행/계속 적용 범위.
- 북마크: 관심 후보 보관. 취향 방향·강도의 증거로 바꾸지 않는다.

“도쿄에서 음식이 좋았다”는 해당 경험의 긍정 증거로 추천에 참고할 수 있다.
“어디든 미식이 가장 중요하다”는 평소 우선순위다. 두 진술의 범위를 같게 만들지 않는다.
여행 비교는 여행 사이의 선호 관계만 알려준다. 그 이유나 모든 항목의 확신은 알려주지 않는다.

## 수정·철회

- 같은 원문을 반복 요약하거나 여러 화면에 표시해도 독립된 증거가 늘어난 것은 아니다.
- 평소 선호와 이번 목적이 달라도 모순으로 제거하지 않는다.
- 명시적 정정은 같은 범위의 이전 내용을 대체하고 근거 연결을 갱신한다.
- 평가 수정·삭제를 허용한다. 삭제된 여행/평가에서 파생한 기억·추천 요약도 재구성한다.
- 사용자가 별도로 직접 확정한 평소 선호는 여행 삭제와 자동으로 함께 지우지 않는다. 삭제 범위를 표시한다.
- 철회된 정보가 추천 캐시·대화 요약·공유 문장에서 다시 복원되지 않도록 한다.
- 저장 실패 시 기억했다는 안내를 하지 않는다.

## 기존 데이터 이관

1. 여행·구간·직접 평가·퀴즈 답·북마크·제외 원본을 보존한다.
2. 국가 평균이 포함된 파생 5축 값을 새 선호로 변환하지 않는다.
3. 퀴즈 답과 태그는 질문/선택지의 실제 뜻이 명확할 때만 그 범위로 옮긴다. 원문 의미를 복원할 수 없으면 미해석 기록으로 남긴다.
4. “혼자↔함께” 한 값으로 동행·새 사람 만나기·혼잡 회피를 만들어내지 않는다.
5. 도시명은 명확히 식별되는 경우에만 도시 ID에 연결한다. 동명이거나 미확인인 값은 확인 전 보류한다.
6. 나라 방문만 있는 경우 그 나라의 모든 도시를 방문 처리하지 않는다.
7. 기존 나라 제외를 도시 하나로 축소하지 않는다. 기존 기한 있는 제외는 해당 기한을 보존하고, 새 무기한 제외와 구분한다.
8. 이전 국가 추천 노출은 과거 국가 모델 기록으로 보존한다. 도시 모델 성과와 무표시로 합산하지 않는다.

이관은 한 번 더 실행해도 중복 증거·제외가 생기지 않아야 한다. 저장 버전별 이관 계획과 실패 시 원본 보존을 구현 단계에서 검증한다. 별도 이벤트 소싱 시스템을 새로 만들 필요는 없다.
