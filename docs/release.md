## 출시 차단 요건

아래는 출시할 빌드에서 확인할 요건이며, 이번 문서 정리로 통과한 검사가 아니다.

- 빌드·회귀 검사와 재시작 후 데이터 유지, 이관 실패 시 원본 보존.
- 출시할 추천 방식의 품질 기준 충족. 같은 입력·다른 취향 테스트만으로 정확도를 판정하지 않는다.
- 제외 위반·허위 근거 방지, 기억 수정·되돌리기·삭제, 늦은 응답·오류·비용 제한 처리.
- 평가 메모 원문의 LLM 전송 안내·동의, 키 보호·접근 통제·보관 및 삭제 정책. 목록 밖 도시 요청의 서버 기록은 별도 목적·보관·삭제 범위를 검증한다.
- 구독·차감 정책 확정 후 구매·복원·만료와 호출 한도·실패 처리를 검증한다. 실제 호출 비용과 추천 횟수 차감을 구분한다.
- 여행·평가·전체 데이터 삭제와 공유 공개 범위 확인.
- 개인정보 처리방침·권한 문구·앱 아이콘·프라이버시 선언·앱스토어 제출 자료. 처리방침·선언·권한 문구의 초안은 [개인정보 초안](privacy-draft.md)에 있다.
- 제휴 링크를 공개하는 경우 표시 문구·목적지·귀속 검증.

## 출시 검사와 병행 업무

- **R1 — 필수 시나리오 전체를 앱에서 검증한다.** [구현 회귀 시나리오](evaluation/README.md#구현-회귀-시나리오)를 저장·재시작·네트워크 실패까지 포함해 실행하고 결과를 남긴다. 핵심 로직은 자동 검사, 화면/권한/공유는 필요한 UI·실기기 검사로 확인한다. 모델의 설명으로 코드 검사를 대신하지 않는다.
- **R2 — 출시할 빌드의 회귀 검사를 실행한다.** `TripDNA` 빌드, 관련 `TripDNATests`·`TripDNAUITests`, 실제 기기 데이터 유지·삭제·공유를 확인한다. 실행하지 못한 검사는 이유와 남은 항목을 기록한다. 과거 테스트 통과를 새 빌드 결과로 복사하지 않는다.
- **R3 — 운영·심사 준비를 완료한다.** 선택 모델의 실제 운영 비용, 한도 도달·장애 대응, 전송 안내·보관/삭제, 개인정보 처리방침·권한 문구·프라이버시 선언·아이콘·설치 URL·제출 자료를 확인한다. 출시 시점 공식 요건을 다시 검토하고 최종 제출 범위를 사용자와 정한다.
- **R4 — 제휴 경로를 별도로 검증한다.** 승인·계약 조건을 확인하고 도시 ID와 제휴 목적지, 표시 문구, sub-id, 실기기 링크 귀속을 점검한다. 수수료/제휴 유무가 후보 선택에 영향을 주지 않아야 한다. 기존 구현의 존재와 공개 가능한 제휴 설정을 구분하며 승인 대기를 추천 실험의 선행 조건으로 두지 않는다.
- **R5 — 출시 후 관측을 시작한다.** 추천 적합성·근거/제외 오류·기억 수정·첫 추천 도달·공유·재사용·제휴 확정 예약을 확인한다. 수집 경로가 없는 전 사용자 수치를 측정 중이라고 보고하지 않는다. 상세 열람·저장을 만족도의 정답으로 쓰지 않는다.
