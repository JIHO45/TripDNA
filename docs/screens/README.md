## 공통 흐름

온보딩 → 홈 / 추천 / 여행의 세 탭을 유지한다.
로그인은 진입의 필수 관문이 아니다. 기억·제외·데이터 관리는 설정에서 접근한다.
홈·온보딩·추천 화면은 같은 유효 추천을 재사용해 화면마다 다른 결과가 뜨지 않게 한다.

## 온보딩과 공유 취향

사진 등록은 방문 기록을 채울 뿐이므로 직접 선호를 받을 기회를 반드시 제공한다. 다만 모든 사용자에게 모든 항목을 하나씩 질문하지 않는다.

직접 선호는 과거 여행의 컨셉 선택과 티어로 받는다(2026-10-08. 이전 제안은 좋아하는 경험 복수 선택과 피하고 싶은 것 입력이었다). 선택하지 않은 항목은 싫어함으로 간주하지 않는다. 직접 정보가 없는 특성은 미상으로 남긴다. 추천에 필요한 구체적인 예약·이동 조건만 보충하며 [매칭 원칙](../recommendation/README.md#매칭-원칙)을 따른다. 문항을 건너뛸 수 있게 하고, 건너뛰면 해당 선호를 추정해 채우지 않는다.

공유 지문의 표현과 수정 경로는 [취향 지문](home-and-fingerprint.md#취향-지문), 경험 응답의 의미는 [컨셉과 티어](../recommendation/memory.md#컨셉과-티어)를 따른다. 문항 문구와 공유 카드 배치는 해당 화면에서 다듬는다.

## 공통 표현과 상태

- 실제 처리에만 로딩을 표시한다. 고정된 분석 대기 시간이나 가짜 작업 단계를 만들지 않는다.
- 선택 입력의 건너뛰기·뒤로가기를 유지한다. 추천의 필수 입력은 [추천 화면](recommendations.md#추천-탭)을 따르며 온보딩 질문의 건너뛰기와 구분한다.
- 티어의 미선택과 명시적 자유문장 회피는 [응답 의미](../recommendation/memory.md#컨셉과-티어)를 따른다. 미선택만으로 도시 제외를 만들지 않는다.
- 저장한 내용·제외 범위를 보여주고 되돌릴 수 있게 한다.
- 원본 사진/위치 분석의 기기 내 처리와, 확인한 추천 관련 사실의 LLM 전송을 구분해 안내한다.
- 로컬 기록은 오프라인 이용 가능하다. LLM 신규 생성은 불가하며 유효 캐시만 보여준다.
- 오류 시 입력을 보존하고 재시도·수정 경로를 제공한다.
- 긴 글·큰 글꼴·스크롤·VoiceOver를 지원한다. 한 화면에 억지로 고정하지 않는다.

색상·타이포·카드 등은 앱의 기존 공용 컴포넌트를 재사용한다.
예전 다크 테마 생성 프롬프트를 새 디자인의 강제 기준으로 삼지 않는다.
여행·Wrapped·하루 한 장의 기존 기능을 이번 추천 재설계만으로 제거하지 않는다.
