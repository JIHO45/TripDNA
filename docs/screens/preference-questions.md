# 직접 선호 질문 설계

상태: 문항 초안. 확정 정책은 [핵심 설계](../recommendation/architecture.md) 9절,
화면 흐름은 [온보딩](onboarding.md)을 따른다.
예전 13문항·0.4 신뢰도 게이트·국가 경유 간접 신호 공식은 신규 구현 기준에서 제거한다.

## 처음 물을 내용

1. “여행에서 좋아하는 경험을 골라주세요.” 독립 항목 복수 선택, 자유 입력, 건너뛰기.
2. “피하고 싶은 것이 있나요?” 혼잡·긴 이동·촘촘한 예약 등 선택/문장. 강요하지 않는다.
3. 이후 후보를 실제로 가르는 정보가 부족할 때만 짧게 보충한다. 날짜·예산은 첫 추천의 필수 질문이 아니다.

선택 수·문구·화면 수는 검증 전 기본안이다. 무조건 세 가지를 채우게 하거나 모든 항목을 하나씩 묻지 않는다.

## 보충 질문의 예와 범위

- “쉬는 여행과 활동하는 여행은 각각 얼마나 끌리나요?” 둘 다 좋아함을 허용하고, 둘 다 모름과 분리한다.
- “여행 중 새 사람을 만나는 경험은 어떤가요?” 이번 동행이나 혼잡 회피와 별개로 해석한다.
- “맛집은 즉석에서 고르는 편인가요, 미리 예약하는 편인가요?” 음식 선택에서의 스타일만 알려준다. 모든 계획성으로 확대하지 않는다.
- “음식과 자연 중 이번에는 무엇이 더 중요한가요?” 이번 우선순위로 저장한다. 평소 취향에 덮어쓰지 않는다.
- “이 여행에서 특히 좋았던 것은 무엇인가요?” 해당 여행의 경험 평가다.

질문마다 묻는 대상·상황·저장 범위를 먼저 정한다.
A/B 장면은 선택 원인이 여러 개이면 한 축의 강도로 채점하지 않는다.
동행·비용·사진 매력도 차이가 답을 유도하지 않는지 검수한다.

## 응답과 수정

“모르겠어요”는 증거 없음, “둘 다 좋아요”는 양쪽 긍정이다.
“비슷했어요”와 “기억 안 나요”도 각각 동등 평가와 미상으로 분리한다.
미선택은 싫어함이 아니다. 답을 수정하거나 철회할 수 있고, 원문 선택과 문항 버전을 보존한다.
같은 개념의 유사 질문 여러 개를 독립된 확신으로 합산하지 않는다.

문항 검증은 추가 답변이 추천 선택을 실제로 개선하는지와 입력 부담을 함께 본다.
사진 자산과 최종 문구는 별도 검수 전이며, 새 퀴즈가 구현됐다는 뜻이 아니다.
