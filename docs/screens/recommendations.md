# 도시 추천·상세·피드백

상태: 새 구조의 목표 동작. 기준: [핵심 설계](../recommendation/architecture.md) 5~8절.

## 추천 탭

저장된 취향으로 바로 추천한다. 유효한 결과가 있으면 재사용한다.
동행·출발지·날짜·기간·예산·이번 목적은 선택 입력이다. 입력하지 않은 조건은 모름으로 둔다.
방문 도시도 추천하고 “새로운 곳만 보기”를 제공한다. 나라 방문만으로 모든 도시를 제외하지 않는다.

기본안은 최대 3개 카드다. 각 카드에는 도시·나라, 가능한 경험, 사용자에게 맞는 이유와 유의점을 표시한다.
매칭 백분율·고정 탐험 슬롯은 두지 않는다. 정보가 없으면 개인화되지 않은 탐색 제안으로 구분한다.
조건을 검증하지 못했으면 적합하다는 배지를 붙이지 않는다.

## 행동

- 저장: 북마크. 취향 변경 없음.
- 다른 후보 보기: 현재 요청에서 다른 후보를 탐색. 영구 제외 없음.
- 관심 없어요/이유 입력: 아래 기억·제외 정책 적용.
- 상세: 검수 DB의 정보와 개인화 설명, 추가 질문.
- 새 여행 시작: 이번 조건과 이번 여행 제외를 새로 시작. 평소 선호·계속 제외 유지.

“도쿄는 별로예요”는 계속 제외하고 저장 안내·되돌리기를 제공한다.
“이번엔 너무 비싸요”는 해당 후보를 이번 여행에서 제외한다. 임의의 예산 숫자나 영구 취향을 만들지 않는다.
“나는 원래 붐비는 곳을 싫어해요”는 평소 선호로 자동 저장하고 내용·되돌리기를 표시한다.
모호해서 적용 범위가 달라지는 경우에만 한 가지 확인 질문을 한다.

제외한 카드는 즉시 제거한다. 기본안은 그 자리를 대체하고 다른 유효 카드는 유지하는 것이다.
전체 목적·예산 등의 변경이면 전체 후보를 다시 평가한다.
저장 성공과 재추천 성공은 구분한다. 생성 실패로 사용자의 제외를 되돌리지 않는다.

## 상세와 질문

기본 DB 정보를 먼저 보여주고, 유효한 개인화 설명을 재사용한다.
무엇을 할 수 있는지·왜 맞는지·안 맞을 수 있는 점·출처를 제공한다.
추가 질문은 검수 자료로만 답하며 최신 확인은 공식 링크로 안내한다.
열람·질문만으로 취향을 변경하지 않는다. 상세에서도 제외 상태를 확인·해제할 수 있다.

제휴 링크는 추천 결과와 독립적으로 연결하고 제휴 관계를 표시한다.
사용자에게 필요한 이유·유의점을 광고 뒤에 숨기지 않는다.
추천 상세의 정확한 답변 규칙은 [추천 설명](../recommendation/explanations.md)을 따른다.

## 저장 목록과 제외 목록

북마크와 제외는 독립적이다. 저장 목록에 제외 상태를 표시하며, 북마크 해제가 제외 해제는 아니다.
추천 이유는 생성 시점 정보를 구분하고, 조건이 달라졌다면 최신 확인 경로를 제공한다.
도시를 여행으로 등록할 수 있지만 아직 정하지 않은 날짜·동행을 자동 확정하지 않는다.

## 실패·동시 변경

- 후보 부족: 가능한 수만 제시하고 어떤 조건이 제한했는지 설명한다.
- 오프라인/호출 한도: 조건을 여전히 만족하는 캐시만 표시한다. 없으면 재시도 경로와 DB 정보 제공.
- 입력 변경 중 도착한 이전 응답: 폐기한다.
- 모델이 제외 도시·알 수 없는 ID·잘못된 근거를 반환: 표시하지 않고 검증 실패 처리한다.
- 앱 재시작: 이번 여행 조건·제외 유지.
- 제외 해제: 다음 추천에 포함될 수 있을 뿐 자동 1위가 되지 않는다.
