# 여행 평가·수정

상태: 목표 동작. 기준: [핵심 설계](../recommendation/architecture.md) 3·6절.
평가를 마치면 반드시 축이 움직이거나 추천이 교체된다는 약속을 제거한다.

## 입력

여행 전체 만족도와 재방문 의향, 좋았던 경험·아쉬웠던 이유를 기록한다.
건너뛰기와 나중에 하기를 제공하고, 완료 시간을 검증하지 않고 보장하지 않는다.
미입력은 미상이다. 평가를 건너뛰면 방문 사실만 남긴다.

직접 비교를 제공하는 경우 첫 여행에는 생략한다.
“비슷했어요”는 동등 평가, “기억 안 나요”는 미상으로 구분한다.
비교 결과만으로 성향 항목의 확신을 올리지 않는다.

## 경험의 귀속

도시·구간을 여러 곳 방문했다면 좋았던/아쉬웠던 경험이 어디에 해당하는지 선택적으로 받는다.
전체 여행/도시 모름을 허용하고, 모르면 베스트 도시로 자동 배분하지 않는다.
여행 전체의 평가를 모든 방문 도시에 복제하지 않는다.
기존 나라만 있는 기록은 그 정밀도대로 보존한다.

태그는 [경험 어휘](../recommendation/experience-vocabulary.md)를 따른다.
자연과 도시를 동시에 선택할 수 있고, 고르지 않은 항목을 싫어한다고 보지 않는다.
방문지의 대표 경험만 답할 수 있게 제한하지 않는다.

## 저장과 기억

“이번 여행 음식이 좋았어요”는 해당 경험의 평가로 보존한다.
“평소에도 미식이 가장 중요해요”처럼 일반화한 직접 진술은 평소 선호로 자동 기억하고 안내·되돌리기를 제공한다.
불명확하면 원래 여행 범위를 유지하거나 필요한 확인 질문을 한다.
“재방문하지 않겠다”만으로 영구 추천 제외나 새로운 곳 선호를 만들지 않는다. 제외 요청은 별도 행동이다.

저장 성공 뒤 무엇을 기록했는지 보여준다. 단순 축 델타 연출로 학습을 과장하지 않는다.
추천을 바꿀 근거가 생겼다면 다음 추천에 반영한다. 생성 실패 시 평가 저장 성공과 구분한다.
대표 사진 선택과 공유는 평가 뒤 선택 단계로 유지한다.

## 수정·삭제와 실패

제출 후에도 평가 수정·삭제를 허용한다. 랭킹 조정은 잘못된 답을 수정하는 대체 수단이 아니다.
수정 전후의 관계를 추적해 삭제한 근거가 기억·캐시·공유 요약에 남지 않게 한다.
동일 수정이 중복 저장되어 증거가 늘어나지 않도록 한다.
오프라인에는 기록을 로컬에 저장할 수 있으나 LLM 신규 추천이 완료됐다고 표시하지 않는다.
