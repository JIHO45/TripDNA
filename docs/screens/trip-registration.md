# 과거·예정·현재 여행 등록

2026-10-08 정합성 보완: 추천의 등록 초안 연결과 도시별 평가를 반영했다. 여러 도시를 한 여행에 두는 기존 구조는 유지한다.
2026-10-08 변경: 등록할 때 여행의 컨셉을 붙인다. 갈 곳을 이미 정한 사용자는 추천이 아니라 여기로 들어온다.
상태: 기존 여행 기능을 유지하고 도시 식별·취향 해석을 갱신하는 목표 동작.
기준: [사용자 기억](../recommendation/memory.md), [후보](../README.md#candidates).

## 목록과 등록

현재·예정·지난 여행 목록과 등록 진입을 유지한다.
직접 입력과 사진첩 찾기를 제공하며 사진 권한은 선택한 경로에서만 요청한다.
여행 구간마다 나라, 알고 있는 도시, 기간을 기록한다. 다국가·다도시 여행을 한 여행의 구간으로 표현한다.

도시가 추천 DB 밖이거나 미확인이어도 여행 기록을 허용한다.
동명 도시는 나라·지역으로 확인하고, 불명확하면 원문만 보존한다.
출발/종료일이 추정이면 정밀도를 보존하며 알림용 날짜를 실제 방문 사실로 둔갑시키지 않는다.
종료일보다 시작일이 늦는 등 모순은 입력 위치에서 알려준다.

## 사진첩 후보

기기에서 위치·날짜로 방문 후보를 찾고 사용자 확인 뒤 저장한다.
합치기·나누기·잘못된 여행 제외·대표 사진 교체를 제공한다.
환승·거주·사진 수로 여행 만족도나 취향을 추론하지 않는다.
추천용으로 전송할 확인된 도시 정보와 원본 사진/위치 데이터의 경계를 안내한다.

## 동행·평가

동행과 여행/출장 등 목적은 해당 여행의 사실이다. 가족 여행 한 번으로 평소 취향을 바꾸지 않는다.
여가 여행에는 주 컨셉 1개와 부 컨셉 0~2개를 붙인다. 의무 여행(출장·가족 방문)은 컨셉 없이 기록한다. 의미는 [컨셉과 티어](../recommendation/memory.md#컨셉과-티어)를 따른다.
도시를 목록에서 골라 ID로 기록하게 할지는 [미정](../recommendation/README.md#여행지-값의-갱신-출시-후)이다. 지금은 자유 입력이다.
과거 여행의 평가는 [도시별 평가](trip-evaluation.md#입력)를 따른다. 온보딩 중 과거 여행 평가를 받을지는 별도 미정이다.
미평가 여행을 중간 만족도로 채우지 않는다.
등록만으로 “취향이 바뀌었다”거나 “추천 정확도가 올랐다”고 단정하지 않는다.

추천에서 등록 화면으로 이동할지 묻고 사용자가 선택하면 도시·나라·명시한 날짜·컨셉으로 초안을 채운다. 목록 밖 도시도 허용한다. 사용자가 저장하기 전에는 여행을 만들지 않는다. 예산 한도·대략 기간을 실제 지출·확정 날짜로 바꾸지 않는다.
추천용 이번 여행 조건과 실제 여행 원장을 구분하며, 조건 입력만으로 방문 기록을 만들지 않는다.

## 상태와 권한

예정 → 현재 → 종료 → 평가/평가 건너뛰기 흐름을 유지한다.
수정·삭제·대표 사진 변경·공유 경로를 제공한다.
첫 예정/현재 여행 등록 뒤 맥락을 설명하고 사용자가 선택한 경우 알림 권한을 요청한다.
루트 README의 제외 범위에 따라 위치 권한·도착 자동 감지를 추가하지 않는다. 종료일 기반 알림과 수동 등록을 사용한다.

2026-10-17 결정: 위치 권한은 현재 구현 범위에서 제외하되, 향후 도착 감지 기능을 설계할 때 재검토한다. 재검토할 때의 원칙은 다음과 같다.

- 위치로 어떤 불편을 줄일지(예: 여행지에 도착하면 "이번 여행을 등록할까요?" 제안)를 먼저 정하고, 그 기능을 쓰는 시점에 권한을 요청한다. 온보딩에서 미리 받지 않는다.
- 앱을 열었을 때 여행지에 있는지 확인하는 기능과, 앱을 닫아 둬도 도착을 감지해 알리는 기능은 구현과 권한 범위가 다르다. 전자로 충분한지 먼저 확인하고, 자동 알림의 가치가 확인되면 후자를 검토한다.
- 권한을 거절해도 수동 등록만으로 앱을 계속 쓸 수 있게 유지한다.
- 현재 위치는 추천의 출발지로 쓰지 않는다. 사용자의 실제 출발지를 보장하지 않는다([조건](../recommendation/README.md#조건)).

오프라인 등록은 로컬 저장이다. 클라우드 동기화 대기라고 표시하지 않는다.
저장 실패 시 입력을 보존한다. 여행 삭제 뒤 파생 기억 처리는 [증거와 이관](../recommendation/memory.md#기존-데이터-이관)을 따른다.
