# 후보 식별과 기존 자료의 용도

상태: v2. 이전 선정 근거: [D2 기록](../data/destination-selection.md). 운영 후보 전체가 확정되거나 검수 완료된 것은 아니다.

## 후보 원문

후보·순위 출처·파일럿 여부·원본 ID와 앱 ID 연결은 [destination-candidates.json](../../data/planning/destination-candidates.json)이 원문이다. 다음 비교는 이 파일의 파일럿 목록을 사용하고 실행 시 해시·순서를 고정한다. 도시명·나라만으로 주장의 사실성이 검증되는 것은 아니다.

이름·별칭·나라와 안정적인 ID로 대상을 식별한다. 푸껫처럼 원본 집계 단위와 앱 추천 단위가 다르면 JSON의 연결과 범위 결정 기록을 따른다. 범위가 미확인이면 미확인으로 남기며 먼 장소의 장점을 한 도시처럼 합치지 않는다. 허용 후보 밖 장소를 설명하는 것과 후보 밖 도시를 추천하는 것은 별도로 판정한다.

사용자가 특정 도시를 언급했다는 이유만으로 항상 다른 도시를 금지하지 않는다. 체류 고정·대안 허용 등 실제 요청의 의미는 [기억·조건](../README.md#memory)에 따라 해석한다. 나라 우선 선택 단계를 추가하지 않는다.

## 기존 자료

- [엄격한 도시 JSON](../../data/cities/): 기존 스키마의 초안·형식 예제. 스키마와 재확인 규칙은 [과거 형식](../data/city-format.md), 자체 검수 준비는 [검수 기록](../data/city-review-2026-10-06.md)에서 해석한다. 다음 실험의 필수 입력이나 검수 완료 사실로 승격하지 않는다.
- [탐색 입력과 실행 파일](../../data/exploration/README.md): 전체 프로필·제약 입력·지침과 실행 로그. 과거 실행 재현을 위해 보존한다.
- 앱 번들 국가·태그 JSON: 현행 실행 자료이며 새 도시 사실의 근거로 자동 전환하지 않는다.

과거 스키마 v3를 새 운영 계약으로 강제하지 않는다. 향후 필요한 저장 필드는 채택된 방식에 맞춰 새 버전으로 결정한다. 후보·자료 확대 여부는 [평가 관문](../README.md#evaluation)을 따른다.
