# 앱 계측과 지표

상태: v2. 이전: [계측](../evaluation/metrics.md). 실험 채점·검색 로그는 [평가](../README.md#evaluation), 개인정보 보관은 [저장](../README.md#storage)이 담당한다.

## 현행과 목표

현행 [RecommendationExposure](../../TripDNA/Recommendation/RecommendationExposure.swift)는 카드가 절반 이상 보일 때 추천 집합별 카드당 한 번 로컬 기록하는 구조다. 계산만 한 후보는 노출이 아니다. 국가 모델 기록을 도시 모델 성과와 합산하지 않는다. 전 사용자 집계가 구현됐다고 가정하지 않는다.

새 기록의 요구사항은 다음과 같으며 구현된 이벤트 이름 목록이 아니다.

- 요청/결과: 요청 ID, 입력 버전, 후보 집합·순서, 모델·프롬프트·자료 버전, 생성/재사용 구분.
- 실제 노출: 결과 ID, 도시, 화면·위치, 시각. 반응에는 해당 결과·노출을 연결한다.
- 행동: 북마크·교체·제외·해제와 적용 범위, 기억 수정·되돌리기, 여행 평가의 수정·삭제.
- 생성 처리: 성공·실패·검증 탈락·재시도, 토큰·검색 사용량·실제 비용·지연.
- 공유: 이미지 생성·내보내기 성공·공유 시트 취소를 구분한다.

불필요한 사용자 원문을 모든 이벤트에 복제하지 않는다. PC 실험 로그는 앱 노출과 별도다.

## 보는 지표

유입 경로·설치, 첫 추천 도달률·시간과 질문 입력 부담, 실제 사용자 후보 선호, 근거·조건·기억 해석 오류, 비용·지연·실패·재사용을 본다. 지문·Wrapped·여행 카드 공유와 다음 여행 계획 때의 재사용도 관찰한다.
제휴 지표·수집 경로는 [제휴 측정](../README.md#affiliates)에만 정의한다. 집계 경로가 없는 수치는 미수집으로 표시한다.

실제 노출 후보를 반응률의 분모로 사용하고 카드 위치·방문 여부·입력량 차이를 함께 본다. 저장·클릭·상세 열람은 보조 지표이며 여행 만족이나 정확도의 대체 정답이 아니다. 미노출·미반응을 싫어함으로 학습하지 않는다.
D1·D7·D30 리텐션, MAU 절대값, 평가 횟수·매일 방문을 제품의 주 성공 기준으로 쓰지 않는다. 다음 여행 재사용은 관측 기간이 필요하며 단기 결과로 대신하지 않는다.
