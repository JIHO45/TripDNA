# 화면 동작

상태: v2 목표 동작. 이전: [화면별 문서](../screens/README.md). 새 도시·LLM 화면의 구현 완료를 뜻하지 않는다.
이 문서는 진입·배치·사용자 행동·화면 상태를 담당한다. 기억의 의미는 [사용자 기억](../README.md#memory), 생성·재사용·실패는 [추천 구조](../README.md#recommendation), 근거 표현은 [출처](../README.md#sources), 전송·삭제 범위는 [저장](../README.md#storage)을 참조한다.

## 공통

온보딩 뒤 홈 / 추천 / 여행의 세 탭을 유지하고 설정에서 기억·제외·데이터 관리에 접근한다. 로그인은 필수 관문이 아니다. 홈·온보딩·추천은 같은 유효 추천을 표시한다.
실제 작업에만 로딩을 표시하며 가짜 분석 단계·고정 대기 연출을 넣지 않는다. 건너뛰기·뒤로가기·입력 보존·재시도를 제공한다. 큰 글꼴·긴 글·스크롤·VoiceOver를 지원하고 기존 공용 UI를 재사용한다.
오프라인에서는 로컬 기록과 유효 결과를 볼 수 있으며 미구현 동기화·새 생성을 완료처럼 표시하지 않는다.

## 온보딩

사진첩 찾기 / 직접 여행 등록 / 취향 질문으로 시작하는 경로를 제공한다. 사진 권한은 해당 경로를 선택한 뒤 요청하며 거부·결과 없음은 다른 경로로 이어진다.
사진에서 찾은 방문 후보는 도시·나라·기간·여행 여부를 확인하고 합치기·나누기·삭제를 제공한다. 최소 등록 수를 강제하지 않는다. 어떤 경로든 직접 선호 입력 기회를 제공하되 이미 답한 항목을 반복하지 않는다.
결과에는 취향 요약·첫 추천을 표시한다. 실제 외부 전송 시 안내·필요한 동의 절차를 거치며 미동의나 생성 실패도 로컬 기록·홈 진입을 막지 않는다. 저장된 입력·완료 단계는 재시작 후 복원한다.

## 직접 선호 질문

문항은 초안이며 선택 수·최종 문구·화면 수는 입력 부담과 정보 효과를 시험한 뒤 정한다.

1. “여행에서 좋아하는 경험을 골라주세요.” 복수 선택·자유 입력·건너뛰기.
2. “피하고 싶은 것이 있나요?” 혼잡·긴 이동·촘촘한 예약 등 선택 또는 문장.
3. 후보를 가르는 정보가 부족할 때만 보충 질문을 제안한다.

“쉬는 여행과 활동하는 여행은 각각 얼마나 끌리나요?”, “새 사람을 만나는 경험은 어떤가요?”, “음식과 자연 중 이번에는 무엇이 더 중요한가요?”처럼 대상·상황·저장 범위가 드러나는 문구를 쓴다. 음식 예약 스타일을 묻고 모든 계획성을 측정했다고 하지 않는다.
“모르겠어요” / “둘 다 좋아요”, “비슷했어요” / “기억 안 나요”는 별도 선택지다. 문항 버전과 원문 선택을 보존하고 수정·철회를 제공한다. 해석은 [기억 계약](../README.md#memory)을 따른다.
A/B 사진은 동행·비용·사진 매력도 등 여러 차이가 답을 유도하는지 검수한다. 기존 13문항·축 서명·신뢰도 게이트를 새 구조에 강제하지 않는다.

## 홈·지문·랭킹

취향 요약, 현재 여행·평가 대기 등 다음 행동, 추천 대표 카드와 공유 진입을 제공한다. 기록이 부족하면 직접 입력 CTA를 보여준다.
지문에서 근거 답변을 열고 “내 취향과 달라요”로 기억 수정에 연결한다. 평소 선호와 이번 조건을 구분해 표시한다. 옛 5축 그래프에 새 의미의 숫자를 몰래 끼우지 않으며 최종 지문 시각화는 미정이다.
랭킹은 여행 1건 단위다. 드래그는 임시 순서를 보여주고 저장 때 반영한다. 여행 상세에는 기록·평가·대표 사진·수정·삭제·공유를 제공한다.

## 추천 탭

도시·나라, 가능한 경험, 맞는 이유와 유의점, 상세·저장·제외 행동을 표시한다. 기본안은 최대 3개 카드이며 부적합한 카드로 수를 채우지 않는다.
동행·출발지·날짜·기간·예산·목적은 선택 입력이고 “새로운 곳만 보기”를 제공한다. 방문·필터의 적용 의미는 [기억 계약](../README.md#memory)을 따른다.

- 주 행동: “추천에서 계속 제외”.
- 메뉴: “이번 여행에서 제외”, “다른 후보 보기”, “이유 알려주기”.
- 저장: 북마크 목록으로 연결.
- “새 여행 시작”: 관련 조건을 새로 입력하는 진입.

자유문장 피드백은 도시를 대상으로 받고 상세 정보 질문과 구분한다. 행동의 의미와 범위는 [기억 계약](../README.md#memory)을 따른다. 저장 결과·되돌리기를 보여주고 재추천 진행 상태는 별도로 표시한다.

## 도시 상세·저장 목록

무엇을 할 수 있는지 / 왜 맞는지 / 맞지 않을 수 있는 점 / 출처와 추가 질문을 제공한다. 확인된 저장 정보가 있으면 먼저 보여줄 수 있지만 모든 도시에 기본 프로필이 존재한다고 가정하지 않는다.
사실·적합성 판단·미확인을 구분하고 출처를 열 수 있게 한다. 최종 배지 문구·배치·아이콘은 화면 검토 후 확정한다. 검색 중·실패·확인 불가를 구분하며 정확성 규칙은 [근거 계약](../README.md#sources)에 둔다.
제외한 도시도 사용자가 직접 상세를 열 수 있고 제외 상태·해제를 제공한다. 북마크 목록에도 제외 상태를 표시한다. 도시에서 여행 등록으로 연결하되 미확정 날짜·동행을 자동 채우지 않는다.
제휴 표시·배치는 [제휴](../README.md#affiliates)를 따른다.

## 설정·기억 관리

저장 내용·범위·원문 출처·시점을 표시하고 수정·삭제·되돌리기를 제공한다. 제외 목록은 도시/나라와 적용 범위를 구분해 해제할 수 있게 한다.
사진 접근·자동 후보 동의, LLM 전송 안내, 기억 하나/여행·평가/전체 데이터 삭제의 영향을 구분한다. 성공한 삭제 범위만 표시하고 실패는 재시도를 안내한다. 현재 별도 로그아웃 대신 데이터 삭제 경로를 제공하며 Apple 로그인을 백업으로 설명하지 않는다.

## 여행 등록·평가

현재·예정·지난 여행 목록과 직접 입력·사진첩 등록을 유지한다. 구간별 나라·알고 있는 도시·기간으로 다국가·다도시 여행을 표현한다. 후보 목록 밖 도시도 기록할 수 있고 모호한 도시는 원문을 남긴다. 추정 날짜는 정밀도를 보존하며 시작/종료 모순은 입력 위치에서 안내한다.
예정 → 현재 → 종료 → 평가/건너뛰기 흐름을 유지한다. 첫 예정/현재 여행 등록 뒤 사용자가 선택하면 알림 권한을 요청한다. 종료일 기반 알림과 수동 등록을 사용한다.

평가에는 만족도·재방문 의향·좋았던 경험·아쉬웠던 이유와 건너뛰기를 제공한다. 경험의 도시/구간 귀속은 선택 입력이고 전체 여행/도시 모름도 허용한다. 첫 여행은 직접 비교를 생략한다. 제출 뒤 수정·삭제가 가능하며 랭킹 조정으로 평가 수정을 대신하지 않는다.
저장 성공과 추천 생성 성공을 따로 표시하고 대표 사진 선택·공유는 선택 단계로 둔다. 오프라인 저장과 새 추천 완료를 혼동하지 않는다.

## 하루 한 장

현재 여행의 홈·상세·허용된 알림에서 사진 선택·확인으로 진입한다. 접근 거부·제한·사진 없음은 건너뛰기를 허용한다. 반응은 개인 회고 보조이며 취향·도시 사실의 정답이 아니다.
첫 수동 확정 뒤 자동 후보 동의를 별도로 받는다. 동의와 사진 접근이 있을 때만 놓친 날짜의 후보를 채우고 수동 사진을 덮어쓰지 않는다. 설정에서 동의를 변경한다. 수동 사진을 회고·대표 사진 후보로 우선한다. 스트릭·미선택 경고를 추가하지 않는다.

## Wrapped·공유

연간 회고는 기존 6장, 12월 15일~다음 해 1월 15일 시즌 진입과 해당 연도 여행 조건을 유지한다. 12월은 “올해 지금까지”, 1월은 회고 연도를 표시한다. 여행·지문 공유는 연중 제공한다.
여행 수·확인한 방문지·직접 평가·경험으로 구성한다. 여행 1건이면 비교 표현을 줄이고 근거 없는 변화나 과거 성격을 만들지 않는다. 개인 회고 사진과 공개 이미지를 구분한다.

공유 전 미리보기와 공개 내용을 확인한다. 국가 이름은 기본 숨김이며 공개 설정 변경 뒤 다시 확인한다. 정확한 날짜·도시·동행인·개인 사진은 현재 내보내기 범위에 추가하지 않는다. TripDNA 이름·설정된 설치 링크를 사용하고 없는 주소를 생성하지 않는다.
수정·철회 뒤 앱 미리보기를 갱신하며 외부로 내보낸 이미지는 회수할 수 있다고 하지 않는다. 저장 권한 거부·렌더링 실패·시트 취소를 성공으로 표시하지 않는다. 시즌 밖 개발 미리보기는 일반 사용자 기능과 구분한다.
