# 저장·전송·개인정보 경계

상태: v2 구현 목표. 이전: [저장 계약](../data/storage-and-privacy.md). 의미·필드는 [사용자 기억](../README.md#memory), 생성 결과 무효화는 [추천 구조](../README.md#recommendation)가 담당한다.

## 저장 위치

사용자 여행·평가·기억 등은 SwiftData, 사진은 LocalPhotoStore의 기기 내 파일을 유지한다. 현재 기기 간 동기화·서버 복구는 없으며 Apple 로그인만으로 복구되지 않는다. [저장소 구현](../../TripDNA/Infrastructure/SwiftDataStore.swift)을 참조한다.

공용 실험 자료는 저장소의 JSON·로그 파일이다. 운영 자료의 배포·갱신·서버 DB 필요 여부와 제품은 채택 후 구현 전에 정한다. 특정 DB 도입을 기정사실로 두지 않는다. 제품 제외 범위는 [루트 README](../../README.md#범위)를 따른다.

## 모델·검색 외부 전송

앱 채택 시 키 보호·요청 크기/형식 검증·인증/남용 방지·호출 및 사용자별/전체 비용 제한을 위한 서버를 둔다. 키를 앱에 포함하지 않는다. 로그인 선택 정책을 남용 방지 구현이라는 이유로 임의 변경하지 않는다.

전송은 활성 추천 관련 증거·이번 조건·필요한 방문 사실·후보로 최소화한다. 원본 사진·EXIF·전체 위치 이력·불필요한 계정 식별자는 보내지 않는다. 검색 도구에도 전체 사용자 원문을 그대로 복제하지 않고 필요한 도시·시기·사실 질문만 전달한다.
PC 실험의 외부 API도 외부 전송이다. 실제 사용자 자료는 전송 범위 안내·필요한 동의 후 사용한다. 제공자 및 검색 서비스의 보관 설정·요청 로그 최소화·보관 기간·삭제 절차를 선택 시 확인하고 출시 전에 확정한다. 아직 확정하지 않은 기간을 보장하지 않는다.

모델 출력으로 임의 DB 경로나 도구 실행을 허용하지 않는다. 호출 서버는 사용자 기록의 클라우드 동기화나 전 사용자 행동 집계 서버 도입과 별개다.

## 삭제와 복구

캐시를 사용자 진술의 유일한 원본으로 쓰지 않는다. 저장 실패 시 입력을 보존하고 재시도 경로를 제공한다. 삭제 시 원본과 파생 기억·추천·공유 미리보기·노출 스냅샷의 연결을 처리하며 실제 성공한 범위만 안내한다.
서버 보관이 생기면 기기 삭제만으로 모두 삭제됐다고 하지 않는다. 외부에 이미 내보낸 공유 이미지를 회수했다고 표시하지 않는다. 기록 이관의 의미는 [이관 계약](../README.md#memory)을 따른다.

## 향후 집계

목적·항목·동의·철회·보관·삭제·접근 통제를 별도로 정하기 전 과거 로컬 기록을 자동 업로드하지 않는다. 연결 식별자가 있는 기록을 익명이라고 단정하지 않는다.
도시 사실과 선호별 만족도를 분리해 검증하고, 저장·클릭을 여행 만족으로 간주하지 않는다. 공용 도시 설명이나 모델을 반응 한 번으로 자동 갱신하지 않는다. 버전별 평가·되돌리기를 통과한 개선만 적용하며 이용자 수만으로 학습 방식 전환을 결정하지 않는다.
